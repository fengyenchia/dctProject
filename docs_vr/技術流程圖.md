# 音虫 VR｜技術資料與事件流程圖

日期：2026-11-03｜版本：VR v0.1

五張圖依[技術架構](技術架構.md)及[開發規格](開發規格.md)繪製；屬於技術設計，不代表已實作。依 **01 → 02 → 03 → 04 → 05** 閱讀，每張從左上開始，圖 03 分成兩種聲音來源。

箭頭表示程式資料或事件；虛線表示重試／持續觀測。圖中相鄰模組可留在同一 Unity 程式內，不表示每個方塊都要一台設備或一個網路服務。

SAN 是遊戲精神值；群落是一次整群捕捉的單位；Gateway 是本機串接服務；outbox 是待上傳佇列。本圖為 VR 版本，不代表原 FigJam 投影版已同步修改。

## 1. 系統資料串接

OpenXR 將頭手姿態與操作送入 Unity，Unity 直接決定捕捉、SAN、回收與頭戴回饋。Gateway 只處理本機管理、保存與雲端成果；不承接 VR 影像。

## 2. 瞄準與自動捕捉判定

控制器姿態決定虛擬射線，命中有效群落後持續計時。進度中斷歸零；結算一次後更新 SAN、震動與捕捉噪音事件。

[SVG 向量圖](assets/技術流程圖/02.svg) · [PNG 圖片](assets/技術流程圖/02.png) · [Mermaid 原始碼](assets/技術流程圖/02.mmd)

<details>
<summary>展開 Mermaid 原始碼</summary>

```mermaid
flowchart TD
  pose["OpenXR 手部姿態<br/>虛擬捕捉器前向"]
  ray["Unity 射線檢查<br/>最近群落／環境遮擋"]
  valid{"探索中且命中有效群落？"}
  reset["進度歸零<br/>等待重新對準"]
  track["同一群落持續對準<br/>累積有效時間"]
  time{"達捕捉時間且目標仍有效？"}
  progress["虛擬 LCD 顯示進度<br/>持續取樣"]
  commit["標記已捕捉／整群消失<br/>收集一次／SAN 扣一次"]
  feedback["更新虛擬 LCD<br/>控制器震動"]
  noise["CAPTURE_NOISE<br/>接圖 03 的噪音／誕生"]
  pose --> ray
  ray --> valid
  valid -->|"否"| reset
  reset -.->|"重試"| ray
  valid -->|"是"| track
  track --> time
  time -->|"尚未達時長"| progress
  progress -.->|"繼續觀測"| ray
  time -->|"是"| commit
  commit --> feedback
  commit -->|"同一捕捉紀錄"| noise
```

</details>

## 3. 聲音擾動與新音虫誕生

觀眾聲音只擾動既有群落。成功捕捉的 CAPTURE_NOISE 才同時安排噪音播放及新群落生成，不靠重新收音觸發。

## 4. 虛擬到站、確認回收與城市修復

進入回收階段後，玩家在站旁且虛擬捕捉器進入感應範圍，Unity 記錄已到站。觀眾可移開再按確認，系統只結算一次，登錄種類與群落數量後轉化物品並修復城市。

![虛擬到站、確認回收與城市修復](assets/技術流程圖/04.png)

[SVG 向量圖](assets/技術流程圖/04.svg) · [PNG 圖片](assets/技術流程圖/04.png) · [Mermaid 原始碼](assets/技術流程圖/04.mmd)

<details>
<summary>展開 Mermaid 原始碼</summary>

```mermaid
flowchart TD
  returning["任務達成或 SAN 達限制<br/>進入 Return／停止捕捉"]
  reach["玩家在站旁＋虛擬捕捉器<br/>進入回收站感應範圍"]

  deny["不授權<br/>維持提示"]

  request["RECYCLE_REQUEST<br/>檢查到站／尚未回收／追蹤"]
  commit["先標記已回收／固定清單<br/>登錄種類與群落數量"]
  convert["噪音能量轉化為物品<br/>VR 城市修復演出"]

  returning --> reach
  reach --> check
  check -->|"否"| deny
  check -->|"是"| auth
  auth --> request
  request -->|"通過"| commit
  request -->|"不通過"| deny
  commit --> convert
  convert --> result
```

</details>

## 5. 成果保存、發布與離場交付

本機先保存成果及 outbox，再交付固定成果連結並背景上傳。保存、結尾與頭戴外成果交付完成才重置；網路中斷不刪除待同步結果。

![成果保存、發布與離場交付](assets/技術流程圖/05.png)

[SVG 向量圖](assets/技術流程圖/05.svg) · [PNG 圖片](assets/技術流程圖/05.png) · [Mermaid 原始碼](assets/技術流程圖/05.mmd)

<details>
<summary>展開 Mermaid 原始碼</summary>

```mermaid
flowchart TD
  snapshot["Unity 固定成果快照<br/>RESULT_READY"]
  save["Gateway 建立 result_id／token<br/>SQLite 成果＋outbox 同筆交易"]
  saved{"本機保存成功？"}
  retry["重試保存／暫停正常重置"]
  ack["RESULT_SAVED<br/>回覆 Unity"]
  upload["outbox 認證上傳<br/>同 result_id 重試不重複"]
  handoff["完成結尾／取下頭戴<br/>交付本場成果 QR"]
  uploaded{"上傳成功？"}
  phone["手機掃碼或離場重開<br/>Next.js 成果頁"]
  cloud["雲端保存同一成果<br/>與版本化音軌"]
  available{"該成果已發布？"}
  retryUpload["保留 outbox<br/>復線補傳"]
  web["感謝信／收集摘要<br/>個人旋律播放"]
  pending["成果尚未就緒或連結無效<br/>提示稍後重試"]
  reset["保存＋結尾＋QR 交付完成<br/>重置遊戲／保留成果及佇列"]
  snapshot --> save
  save --> saved
  saved -->|"否"| retry
  retry -.->|"重試"| save
  saved -->|"是"| ack
  ack -->|"背景同步"| upload
  ack --> handoff
  handoff --> phone
  handoff --> reset
  upload --> uploaded
  uploaded -->|"是"| cloud
  uploaded -->|"否"| retryUpload
  retryUpload -.->|"重試"| upload
  phone --> available
  cloud -->|"讀取成果"| available
  available -->|"是"| web
  available -->|"否"| pending
```

</details>
