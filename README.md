# 音虫 VR｜畢業製作開發專案

以聲音探索與音虫捕捉為核心的單人 VR 互動作品。觀眾扮演捕蟲人，在虛擬城市中循聲尋找音虫，回收噪音能量、修復城市，並帶走屬於這次收集的聲音紀念品。

> [!NOTE]
> 目前以 **VR 方案**為開發主線，repo 已有共用 Unity 專案 CaptureLab、技術文件與教學範例。網頁及 Gateway 依工作包開工。
> PM 時程：**2026/12/8 捕捉主功能 → 2027/1/7 桌面可試玩 → 1/31 Windows Alpha**；詳見[開發排程](docs/docs_vr/開發文件/02_里程碑與美術期限.md)。

## 互動方式

觀眾配戴 Quest 3；左手搖桿移動角色，右手持捕捉器並用搖桿左右轉身、上下調整視角。頭部追蹤保留，也可實體轉身。

| 階段 | 觀眾操作與系統反應 |
| --- | --- |
| 開場 | 觀看前導影片；配戴後觀看 VR 短版開場與操作教學。 |
| 循聲尋找 | 音虫起初隱藏但持續發出聲源；觀眾循聲尋找，用捕捉器照射後逐漸顯現。 |
| 對準捕捉 | 光罩隨控制器照向場景；同一群累積有效對準 3 秒後自動捕捉，過程逐漸顯現、聲音變小。 |
| 移開再繼續 | 移開保留原群的捕捉進度、顯現程度與音量，再對準即可接續。 |
| 完成收集 | SAN 從 100 開始，每次成功捕捉扣 20。收集後可以前往右端回收，達 5 次時停止捕捉。 |
| 回收與修復 | 角色到右端回收站確認，回收能量化為金色粒子，城市材質隨修復改變。粒子量依實收數量調整，觀眾仍可移動。 |
| 帶走成果 | 修復後返回左端起點，在同位置觸發結尾。畫面淡黑後，用左手控制器開信，閱讀對應收集數的感謝信。取下頭戴後到打卡區領熱感紙成果票、看製作展示。票上印有個人成果網頁的 QR Code，離場後也能掃碼回顧。 |

- 海天使 3 款、海蛞蝓 4 款、魟魚 1 款，單場不重複；每個出現點同一場只用一次。探索第 60 秒下雨，魟魚在戶外加入。第 120 秒恢復晴天，未捕捉的魟魚退場。
- 海天使／海蛞蝓全程可出現，同時最多 3 群，雨天加魟魚最多 4 群。預設灰盒開場屋內 1 群、屋外 2 群。捕捉器不發聲。
- 個人成果頁顯示實收圖鑑與感謝信，不播放聲音。

## 技術組成

| 部分 | 採用技術／用途 |
| --- | --- |
| VR 遊戲 | Unity 6.3 LTS（6000.3.19f1）、C#、URP、OpenXR、XR Interaction Toolkit。 |
| 頭戴與控制器 | Quest 3／Touch Plus，透過 USB Link 線連接 Windows 電腦；遊戲由電腦執行。 |
| 聲音互動 | 頭戴內建喇叭播放空間聲音。發聲顯現及其收音處理保留規劃，本階段先不做。 |
| 本機串接服務（Gateway） | Node.js、TypeScript、WebSocket、SQLite，使用 pnpm 管理套件，處理成果保存、背景上傳與收藏票列印。 |
| 網頁 | Next.js、React、TypeScript、pnpm；home 主視覺、results 卡片總覽／個人成果、about 團隊介紹。管理頁後續選配。 |
| 線上服務 | 原型規劃使用 Vercel／Neon；網頁顯示公開成果圖鑑與感謝信，不播放聲音。 |

遊戲判定由 Unity 處理；網際網路暫時中斷時先保存本機成果，恢復後補傳。詳細版本與限制見[開發規格](docs/docs_vr/開發規格.md)。

│  │  ├─ assets/           介面示意、配置圖與技術流程圖

│  └─ archive/             手機、紅外線投影與 MR 的歷史規劃

├─ web/                    ［規劃］Next.js 網頁，使用 pnpm

## 開發與協作

第一次取得專案，在想存放 repo 的上一層資料夾執行：

```text
git clone https://github.com/fengyenchia/dctProject.git
```

clone 後用 VS Code「File → Open Folder…」選 `dctProject`；日常開分支、Commit、Push 與 Pull 使用Source Control介面，合併前先在功能分支接入最新 main 並自測，再以本機 Merge／Push 更新 main。

新加入先讀[環境與 Git](docs/docs_vr/開發文件/環境與Git.md)的安裝與 clone，再看 [Unity 基本操作](docs/docs_vr/開發文件/Unity基本操作.md)入門，接著依工作包操作。開發設備已確認為 2 台 Windows、1 台 Mac M3；三人可認領 Unity 功能。Windows 進行正式 Quest Link 整合，Mac 使用 Apple Silicon 版 Editor 做桌面模擬、Gateway 與網頁。

協作採 `main`＋功能分支；命名為 `範圍/功能`，如 `unity/capture`、`web/souvenir`。完整名稱與工作包對應見[分支安排](docs/docs_vr/開發文件/環境與Git.md#分支安排與名稱)。每項工作一位主責，完成衝突檢查與自測後，在本機合併 main，複驗再推送；同時只由一人整合。

專案建立完成後，從對應位置啟動：

| 部分 | 開啟／執行位置 | 日常操作 |
| --- | --- | --- |
| Unity | Unity Hub 選 `unity-vr/` | 開啟團隊共用專案。 |
| 網頁 | 終端機先 `cd web` | `pnpm dev`；首次拉取依賴用 `pnpm install --frozen-lockfile`。 |
| Gateway | 另一個終端機先 `cd gateway` | `pnpm dev`；首次拉取依賴用 `pnpm install --frozen-lockfile`。 |

- 留在 repo 根目錄時，可用 `pnpm --dir web dev` 啟動網頁，或 `pnpm --dir gateway dev` 啟動本機服務。
- web 與 gateway 各自保留 `package.json`、`pnpm-lock.yaml`，分開安裝與啟動。
- 提交程式、`.meta`、設定及 lockfile；快取與本機資料依根目錄 [.gitignore](.gitignore) 排除。
- Git LFS 共用規則已設定；每位成員安裝後執行一次 `git lfs install`。同一場景／Prefab 同時由一人修改。
- 教學範例與實機驗收分開記錄；桌面模擬通過後，仍需測試 Quest Link、收音、循聲及效能。
