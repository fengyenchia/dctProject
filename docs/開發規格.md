# 音虫互動投影開發規格

日期：2026-11-01

版本：v1.16

用途：固定出現點紅外線識別、NFC 回收、無線捕捉器與必要線上紀念品的開發及驗收。

先讀[技術架構](技術架構.md)了解作品，再依本文件實作各模組；資料傳遞可對照[技術流程圖](技術流程圖.md)。本文件是開發規劃，不代表功能已實作或硬體已通過測試。工具與零件參考見[重要連結](重要連結.md)，需求討論、選型與驗證集中於[待確認與驗證清單](待確認與驗證清單.md)。

## 1. 功能與遊戲狀態

### 功能範圍

本文件的「場次」是一次單人體驗；「點位」是固定音虫出現位置；「群落」是該點目前的一隻或一群音虫，整群算一次捕捉。「SAN」是遊戲內精神值，成功捕捉時降低，達限制後引導回收。

單人城市互動投影，主要輸入為自製無線捕捉器。捕捉器使用 ESP32-S3、廣角紅外線追蹤相機、LCD、回收確認按鈕、震動馬達及聲音回饋。觀眾可自由走動、轉向 L 形兩面投影。每個固定出現點附近裝一顆紅外線燈，各點發射不同紅外線亮暗編碼，捕捉器解碼取得 point_id，並由設定取得 wall_id。捕捉需持續對準同一群音虫一段時間，不需按鈕；辨識有效且達設定時間後自動完成，移開或切換目標則進度歸零。操作位置不固定，介面呈現捕捉進度。

Unity 管理音虫生成、固定小範圍內快速不規則運動、消失、聲音反應、成功捕捉、SAN、回收與城市修復。一個點可對應單隻或一群音虫，但相機只辨識該點，不辨識群內個體。一次成功捕捉整群收走，SAN 扣一次；單隻視為一隻的群組，計數方式相同。未達任務條件且 SAN 尚可捕捉時繼續探索；SAN 達限制即進入正常回收流程。回收後直接進入結尾。

### 音虫與發射燈生命週期

Unity 協調音虫群落與對應發射燈的啟用／停用；燈啟用期間依點位編碼發出亮暗訊號，投影音虫不跟隨識別編碼閃爍，只同步群落生成／消失。群落成功捕捉後立即不可再次捕捉；捕捉成功產生的捕捉器噪音促使新音虫誕生，同一固定點可再次出現不同種類的群落，使用新的身分與版本；實體燈及固定點編碼不隨種類改變，舊群落的捕捉進度與紀錄不轉移至新群落。

### 狀態流程

```text
待機 → 接待區前導／領取捕捉器 → 建立場次並綁定裝置 → 教學 → 探索／捕捉
  ├─ 未完成且可捕捉 → 繼續探索／捕捉
  ├─ 達成任務 → 前往回收站
  └─ SAN 達限制 → 停止捕捉，前往回收站
前往回收站 → NFC 有效讀取並記錄本場已感應 → 可移開捕捉器／開放確認按鈕
→ 按捕捉器確認按鈕 → 回收結算 → 轉化／城市修復 → 本機保存成果 → 必備線上成果 QR／選配列印
→ 撤銷控制權 → 裝置及場景重置 → 待機
```

場次啟動由本機管理端操作；領取捕捉器不直接跳過初始化。前導在接待區播放，遊戲教學由 Unity 與裝置呈現。

### SAN 與結算

精神啃食對應成功捕捉後的 SAN 扣值，一次成功整群捕捉只扣一次，不另外計算噪音傷害或器具耐久。SAN 計算為 `max(0, 初始值 - 成功捕捉次數 × 每次扣值)`。每個可捕捉點位的當次音虫群落為一個捕捉單位，成功一次就整群收走並扣一次；群內個體數不增加扣值次數。初始值、每次扣值及任務條件以設定檔管理。單次辨識到目標不代表捕捉成功；只有 Unity 確認持續捕捉完成後才扣值及更新 LCD。

Unity 是遊戲狀態的唯一權威。捕捉器、回收座與本機串接服務（Gateway）只提出要求或回報感應資料，不自行增加捕捉數、修改 SAN 或完成任務。

### 結束與重置

1. Unity 提供本次收集清單、修復結果及旋律資料；Gateway 在同一本機資料庫交易中保存成果、唯讀 token 與同步工作，確認寫入成功且結尾、成果 QR 交付完成後才重置。
2. 標記場次完成、撤銷裝置操作權，清除裝置上的待提交操作與本場 SAN 顯示。
3. Unity 停用本場所有點位燈並取得燈控確認，清空音虫、待執行生成事件、SAN、收集清單、捕捉進度、已感應及已回收狀態，恢復待機場景與聲音。
4. Unity 回報 `EXHIBIT_READY`，本機服務確認捕捉器、燈控板及回收座就緒後，才釋放名額並依管理設定開放下一場。
5. 中途離場、啟動失敗或逾時中止時，撤銷控制權再執行重置；未完成場次不標為成功成果。

成果、待同步佇列與列印工作按場次獨立保存，遊戲重置不刪除它們。雲端同步與列印可背景續作；本機保存或重置失敗時暫停入場。

## 2. 部署、軟體與設備

### 本地互動與必要線上成果

```text
Unity → Gateway → USB／串口 → 固定燈控板 → 驅動電路 → 各點紅外線發射燈
                                ↕ 燈控狀態與執行回報
紅外線光點 → PAJ7025R3 → SPI → 捕捉器 ESP32-S3
                                ├─ LCD／回收確認按鈕／震動／音效
捕捉器外殼：被動式 NFC 標籤（獨立貼附，不接 ESP32，不需電池）
捕捉器 ESP32-S3 ↔ 展場 Wi-Fi／WebSocket ↔ Gateway ↔ 本機 WebSocket ↔ Unity

捕捉器標籤 → 回收座 NFC 讀取器 → I²C／UART → 回收座 ESP32
                                                      ↕ Wi-Fi／WebSocket
                                                    Gateway
觀眾聲音 → 現場麥克風／音訊介面 → Unity 分析 → 既有音虫擾動
Unity 預製城市／互動／捕捉器噪音音效 → 現場喇叭
Unity 兩組虛擬 Camera／Display 輸出 → L 形兩面主投影（探索、回收、轉化與城市修復）
Gateway → SQLite／事件紀錄／成果 outbox／Windows 列印
Gateway → HTTPS → 雲端 Next.js 成果 API → PostgreSQL／版本化音軌
觀眾手機 → HTTPS → Next.js 線上紀念品網頁（必做）
```

主要即時通訊使用展場 Wi-Fi WebSocket，主機走 Ethernet；固定燈控板以 USB／串口連 Gateway。Gateway 分別管理捕捉器、燈控板及回收座。外網不參與捕捉結算，雲端成果服務負責離場後的觀看。

## 3. 場次建立與設備使用

準備 2～3 支捕捉器供充電、維修與備用，每場只啟用一支。每支捕捉器保留簡單的 device_id 與 NFC tag_uid 對照；燈控板與回收座使用固定連線角色。

1. 啟動 Gateway、Unity、音訊與管理頁，確認捕捉器、燈控及 NFC 回收座連線正常，點位碼表一致。
2. 工作人員選定本場捕捉器並按開始；Unity 初始化成功後建立 session_id，回傳 SAN 與場次狀態。未就緒或已有場次時不啟動第二場。
3. Gateway 只轉送本場啟用捕捉器的操作；其他捕捉器保持待機。裝置連線使用預先配對設定，管理頁限工作人員使用。
4. 斷線時取消未完成捕捉；重連後同步狀態、丟棄舊觀測，重新對準並從零累積進度。
5. 換備機時暫停操作，由管理端指定接手機並關閉舊機操作連線；保留 SAN 與收集紀錄，清除捕捉進度及 NFC 已感應狀態。新機需重新感應回收座。
6. 結束或中途離場後先保存必要資料、清場重置，再開放下一場。成果頁只有查看功能。

## 4. 固定點位識別與捕捉

point_id 是固定點位編號，例如 A01；設定檔對應它的牆面（wall_id）、實體燈位及燈控輸出通道。音虫在燈附近的小範圍內快速亂動，整群為捕捉單位。捕捉器相機連續讀取光點亮暗變化，韌體比對點位編碼，再檢查光點是否接近瞄準中心。這條路徑取得的是「對準哪個固定點」，不是觀眾完整位置或每隻音虫的畫面座標。

1. Unity 在點位建立本次群落紀錄（target_instance_id）與狀態版本，協調群落顯示及燈控；燈控回報啟用狀態後才開放捕捉。成功捕捉立即將原群落標為不可捕捉、整群消失，並要求停用該點燈。
2. 捕捉器從 Unity 狀態快照取得點位對應的群落身分及版本；辨識光點後持續送出點位、群落、觀測時間／序號、編碼與校正版本、中心偏移及辨識有效性。光點編碼只表示固定點，不直接包含群落身分。
3. Unity 取得有效目標後建立本次捕捉紀錄（capture_attempt_id），檢查本場啟用捕捉器、群落版本、樣本時間、瞄準與 SAN；持續對準同一群落才累積進度。移開、換目標或確認失去辨識時歸零，再次對準重新開始。只有 Unity 能判定完成。
4. 進度完成且群落仍有效才整群收走、只記錄一筆捕捉並扣一次 SAN；依 capture_attempt_id 與群落身分去重。
5. 無有效身分、資料過期或光點有歧義時拒絕捕捉，提示重新對準。
6. 捕捉成功發出捕捉器噪音事件，由 Unity 生成控制模組處理新音虫誕生，不由觀眾麥克風聲音直接觸發；同點可再出現不同種類，每次建立新的群落身分與版本，更新 Unity 狀態快照及對應外觀／聲音；已消失群落不因殘留光點再次結算。捕捉紀錄保留成功當下的群落種類，後續同點換種類不回寫既有收集紀錄或旋律配方。

## 5. 裝置、Unity 與線上紀念品串接

| 模組 | 職責 |
| --- | --- |
| 捕捉器 ESP32-S3 | 光點取樣與中心偏移、點位識別、回收確認按鈕、LCD、電量、震動、音效與操作事件 |
| 固定燈控板 | 各點閃爍編碼、啟用控制、設定版本與執行回報、失聯關閉 |
| NFC 回收座 ESP32 | 讀取標籤 UID、回報讀取／移開與健康狀態 |
| Gateway | 固定設備連線、本場捕捉器與 tag_uid 對照、事件檢查、狀態同步、outbox 及列印 |
| Unity | 群落生命週期與點位啟用、捕捉、SAN、回收、投影及聲音；事件排入主執行緒 |
| 本機管理頁 | 開始／暫停／中止、切換備機、燈控與 NFC 狀態檢查、重置及補印 |
| 雲端 Next.js | 必做的個人紀念品網頁、成果 API 與旋律播放，不轉送現場遊戲命令 |

事件路徑：捕捉器／回收座／燈控 → Gateway → Unity → Gateway → 對應裝置。相機只傳光點與識別資料，不傳完整影片。裝置與燈控失聯不得由自己推算 SAN 或完成回收。

中心偏移以校正後的相機視野座標表示，範圍與正負方向在 schema 固定，與整牆座標無關。依裝置時間與主機時間的對應、樣本序號及傳輸延遲檢查資料新鮮度，不直接比較不同裝置的原始時鐘，也不把接收時間當成取樣時間；自動捕捉回覆對應 capture_attempt_id、最新 revision、成功／原因、SAN 與收集紀錄。回饋需冪等，避免重送重播成功音效。

此處 schema 指訊息欄位與格式，revision 指狀態更新序號；「冪等」表示同一事件重送時，仍只執行一次。例如同一次成功捕捉的訊息重傳，不能再扣 SAN、再播放噪音或再觸發誕生。

NFC 讀取事件回報 tag_uid、事件序號與時間，由 Gateway 對照本場啟用的捕捉器。重連時丟棄舊場次暫存事件。

## 6. 聲音與 NFC 回收站

### 聲音來源分工

| 來源 | 資料 | 對應功能 |
| --- | --- | --- |
| 預製城市與音虫聲音 | 音檔、聲源位置與種類 ID | 引導尋找、辨認區域、提供捕獲音色 |
| 現場麥克風 | 觀眾聲音的各通道音量及持續時間 | 觸發既有群落在固定小範圍內的擾動 |
| 捕捉器噪音 | Unity 成功捕捉事件、capture_attempt_id、預製噪音音軌 | 音響播放故事中的捕捉器噪音，並觸發新音虫生成控制 |
| 捕捉器瞄準 | 持續對準同一群音虫的有效觀測 | 自動累積捕捉進度，移開歸零；達條件後由 Unity 完成 |
| 結尾旋律 | 預製音軌 ID、編排與音量 | 依收集種類組成個人化成果 |

### 聲音互動資料流

```text
觀眾聲音 → 現場麥克風／音訊介面 → Unity 分析 → 既有群落擾動

成功捕捉 → 整群收走／該點停燈／SAN 扣一次 → LCD 更新／震動
        → 捕捉器噪音事件 ┬→ 現場音響播放
                 └→ 生成控制模組 → 新群落 → 投影顯示／該點紅外線發射燈啟用
```

Unity 收到麥克風的音量與持續時間後，只改變既有群落的活動。捕捉成功時另發出一次捕捉器噪音事件，同時安排音響播放與新群落生成；生成時間配合演出規則，不需等待麥克風重新收到音效。每個來源事件只處理一次，產生幾群由生成規則決定。精神啃食就是該次扣 SAN，器具損害以震動呈現，不另扣傷害或改變操作能力。所有聲音分析與遊戲判定都在展場主機完成。

### 即時處理規則

- 遊戲開始前依各區背景音量校正收音門檻。
- 使用平滑、持續時間、觸發／解除不同門檻及冷卻，避免一聲噪音重複觸發。
- 麥克風分析出的觀眾聲音事件只更新既有群落的擾動；成功捕捉產生的系統噪音事件才進入新音虫生成控制。
- 新音虫生成事件綁定 session_id 與來源 capture_attempt_id，來源事件去重，重置後拒絕舊場次的待執行事件。
- 同一固定點同時只對應一個可捕捉群落；群內可有多隻外觀個體，仍以一次整群捕捉結算。
- 城市音效、提示音及捕捉器噪音由輸出／收音處理降低回授與誤判；捕捉器噪音即使被麥克風收到，也不能再次觸發誕生或被當成新的觀眾發聲。
- 收音只在本機即時分析，第一版不保存人聲、不上傳人聲，也不做語意辨識。
- SAN 依捕捉數量降低；現場聲音影響音虫活動。
- 聲音處理不依賴雲端；捕捉器連線暫停時，現場聲音與畫面仍由本機運作，但不得讓未確認的捕捉繼續結算。

### NFC 設備配置

每支捕捉器底部貼被動式 NFC 標籤，tag_uid 對照其 device_id，用來區分 2～3 支捕捉器。標籤無需接捕捉器電路、不加電池，不儲存 SAN、收集清單或成果。

NFC 讀取器裝在回收座，由固定供電 ESP32 以 I²C／UART 讀取，再經 Wi-Fi／WebSocket → Gateway → Unity。

### 回收操作資料流

```text
NFC 標籤 → 讀取器 → 回收座 ESP32 → Gateway → Unity 記錄本場「已感應」
捕捉器確認按鈕 → ESP32 → Wi-Fi／Gateway → 回收確認事件
→ Unity 檢查本場捕捉器、可回收階段、已感應且尚未回收
→ 回收結算 → 修復演出 → Gateway 保存成果 → 線上紀念品
```

回收分成「NFC 確認到站」與「按鈕確認執行」兩步。Unity 記住本場已感應後，觀眾可移開再按捕捉器確認按鈕；按下時檢查本場狀態，才結算一次並進入結尾。已感應狀態保留到回收或本場結束，換備機時清除；捕捉仍由持續瞄準自動完成。

### 到站與回收

1. SAN 達限制或任務達成後進入「前往回收站」，LCD 與投影引導。
2. 回收座讀取標籤，經 ESP32、Gateway 回報；Unity 確認標籤屬於本場啟用捕捉器，且目前可回收。
3. Unity 將本場 `nfc_confirmed` 設為 true，LCD 顯示可按確認。觀眾可移開捕捉器，狀態保留至回收或本場結束。
4. 觀眾按捕捉器確認按鈕，送出 RECYCLE_REQUEST；Unity 檢查本場捕捉器、可回收階段、已感應且尚未回收。
5. Unity 立即將本場標記為已回收、關閉再次結算並固定收集清單，再播放雙牆轉化／城市修復、保存線上成果與處理選配列印，直接進入結尾。
6. 重複感應不重複執行回收，重複按鈕不重複結算；新場次、重置或換備機時清除已感應狀態。讀取器掉線時不能新增感應確認，但已取得的狀態不因移開或掉線取消。

回收資格以本場的已感應狀態表示。

NFC 只作識別與近距離到站，不供應捕捉器充電。

### 回收演出

回收座靠近出口，提供 NFC 感應；硬體包含天線、讀取器、控制板及維修空間。回收、能量轉化與城市修復演出統一由兩面主投影呈現，與探索場景共用 Unity 場次狀態。

## 8. 必要線上紀念品與選配列印

### 必要網頁範圍

Next.js 線上紀念品網頁為正式交付，實體印表機未採用或故障仍必須提供成果。使用者經成果 QR Code／連結進入 /results/:token，不需安裝程式或登入；離場後仍可開啟。

| 畫面／功能 | 必要內容 |
| --- | --- |
| 個人成果 | 感謝信、成功捕捉次數、收集種類／群落摘要、修復結果及版本化美術 |
| 個人旋律 | 明確播放／暫停與載入狀態；觀眾點擊啟用聲音，依共同時間軸播放 |
| 分享與保存 | 可複製成果連結、加入書籤或用瀏覽器分享 |
| 狀態處理 | 音檔載入失敗、服務離線、成果未同步／尚未就緒、連結無效／過期 |
| 手機相容 | 手機版排版、iOS Safari／Android Chrome 的播放與重開；非捕捉用相機頁 |
| 保存資訊 | 以長期保留為目標，依正式服務政策顯示保存說明或到期資訊 |

成功捕捉次數代表收走的群落次數，不能直接標為音虫個體總數。若美術／規則另有群內數量資料才另列個體數，避免成果虛構統計。

### 個人旋律

不同種類音虫各對應一個預製聲部，例如旋律或節奏層，依本場收集種類組合。音軌統一速度（BPM）、拍號、循環長度與起點，在同一時間軸播放。保存旋律配方版本（recipe_version）、音軌版本及編排資料，讓同一成果離場重開時保持相同旋律。

預製音軌與播放為線上紀念品的必要功能。

### 保存、發布與 QR 交付

outbox 是保存在本機資料庫的「待上傳佇列」；token 是成果網址中的隨機代碼，用來開啟唯讀成果頁。兩者都由程式處理，觀眾只需掃描成果 QR Code。

1. Unity 完成回收結算後交付完整成果快照；Gateway 以唯一 result_id，在同一本機 SQLite 交易中保存成果、不可猜測的唯讀 token、旋律配方與 outbox，並回覆保存完成。保存失敗不得進入正常重置。
2. Gateway 以認證 HTTPS 上傳，雲端依 result_id 冪等寫入；音軌置於版本化靜態資源／物件儲存。服務回覆後標示發布成功。
3. 結尾交付本場成果 QR Code，選配紙本也使用同一連結。即使不列印，觀眾仍可用手機掃碼保存。
4. 外網中斷時現場仍保存並交付固定 token 的連結，outbox 復線後補傳。雲端尚無該 token 時，頁面可提示「成果尚未就緒或連結無效，請稍後重試」，不假裝已知本機未上傳的成果。
5. 遊戲重置不刪除成果或 outbox；觀眾掃碼不取得遊戲控制權。成果服務獨立於展場電腦運作，以長期保留為目標；成果資料、旋律配方與對應音軌版本一併保存，維持舊連結及播放內容可用。

### 實體列印介面

列印功能啟用時，印表機連展場主機，以 Windows 驅動及列印佇列處理。票面可含音虫圖案、捕捉摘要、感謝文字及成果 QR。

每份成果預設列印一次，補印由管理端操作；缺紙、卡紙或斷線不重算成果、不重播遊戲，不阻塞線上成果與下一場。

## 9. 通訊介面與資料模型

### 必要識別資料

| 資料 | 用途 |
| --- | --- |
| device_id／tag_uid | 區分 2～3 支捕捉器；只接受本場啟用機及其 NFC 標籤 |
| session_id | 區分每場紀錄，拒絕上一場的延遲事件 |
| point_id | 辨識固定光點；設定檔對應牆面、燈通道與閃爍編碼 |
| target_instance_id／capture_attempt_id | 分別記錄本次生成的群落、本次瞄準捕捉；同點新群落重新計算進度，同次成功只扣一次 SAN 並觸發一次噪音事件 |
| result_id／唯讀 token | 同一成果上傳與重開使用同一份紀錄及連結 |

不同編號代表不同用途，不要求每台設備都使用全部欄位。燈控只需點位與啟用狀態，NFC 座端只需回報讀到的標籤；群落種類、SAN、回收與成果統一在主機管理。

例如捕捉器 01 的標籤只用於選機與回收驗證；A01 的紅外線編碼表示音虫出現點。A01 換一群音虫後，點位編碼不變，但 Unity 會建立新的群落紀錄，避免沿用前一群的捕捉進度。

### 主要事件

| 方向 | 事件 | 最少必要內容／作用 |
| --- | --- | --- |
| 管理端 → Gateway／Unity | SESSION_START／PAUSE／RESET | 選用捕捉器、開始／暫停／重置 |
| Unity → 燈控（經 Gateway） | POINT_STATE_SET／ACK | point_id、啟用／停用與執行確認 |
| 捕捉器 → Unity（經 Gateway） | POINT_OBSERVATION／POINT_LOST | 本場、點位、目標版本、樣本序號／時間、中心偏移與辨識有效性 |
| Unity → 捕捉器 | CAPTURE_PROGRESS／CAPTURE_RESULT／STATE_SNAPSHOT | 進度、結果、SAN、收集摘要與目前階段 |
| Unity 內部 | CAPTURE_NOISE | 以同一捕捉紀錄協調音響播放及新群落生成，各執行一次 |
| 回收座 → Unity（經 Gateway） | NFC_TAG_SEEN | tag_uid、事件序號／時間；確認本場已感應 |
| Unity → 捕捉器 | RECYCLE_AUTHORIZED | 已感應、可按確認的狀態提示 |
| 捕捉器 → Unity（經 Gateway） | RECYCLE_REQUEST | 本場確認按鈕事件；Unity 檢查已感應及尚未回收 |
| Unity → Gateway | RESULT_READY | 固定的本場成果快照 |
| Gateway → Unity | RESULT_SAVED | 本機保存成功；結尾與 QR 交付完成後才重置 |
| Gateway → 雲端 | RESULT_UPLOAD／ACK | 同一 result_id 重試上傳，不新增另一份成果 |

持續觀測最新優先，過期樣本不累積進度；同點換新群落時清除舊進度，等待裝置同步新目標版本後再捕捉。成功捕捉、SAN、噪音、新群落生成、回收與列印都不能因訊息重送而重複執行。按鈕事件先去彈跳；結算由 Unity 確認後才回饋裝置。

### 資料分工

設定檔保存捕捉器與 NFC 標籤對照、點位／牆面／燈通道／閃爍編碼、相機校正與素材設定。Unity 保存本場選用捕捉器、SAN、群落、捕捉進度、收集紀錄、`nfc_confirmed` 與是否已回收；Gateway 保存成果、待上傳佇列與選配列印狀態。

重置清除本場暫存狀態，不刪除設備設定、已存成果或待上傳工作。一般觀眾人聲、影片與移動軌跡不預設保存。

## 10. 異常與備援

| 情況 | 處理 |
| --- | --- |
| 無光點／被擋／超出發光或相機視角 | 依辨識有效期限確認失去目標後，進度歸零並提示重新對準，不沿用舊樣本 |
| 同時看見多個光點 | 已識別的多點屬正常情況；只有目標選擇不明、編碼無效或反射無法區分時拒絕捕捉 |
| 編碼中的正常暗段 | 不直接視為音虫消失；由解碼有效性與樣本期限判定是否仍可維持目標，缺資料不累積進度 |
| 點位識別無效／燈控失聯 | 撤銷鎖定；燈控 watchdog 關燈，未知狀態不接受捕捉 |
| 群落消失／已捕捉／同點新群落生成 | 驗證 target_instance_id 及版本，拒絕舊要求，不重複扣 SAN |
| 光點還亮但 Unity 已令群落不可捕捉 | 拒絕捕捉並重試停燈／檢查 ack，不把實體燈當遊戲真相 |
| 捕捉器掉線／重啟 | 保留場次、取消未完成操作，重綁、快照、新鮮鎖定後恢復 |
| 備機接手 | 管理端停用舊機操作連線、啟用新機，清除進度與已感應狀態 |
| 重複開始／多機同時操作 | 只開放一場及一支捕捉器；重複開始不另建場次 |
| NFC 錯誤標籤／未知 UID／多標籤干擾 | 不開放回收，提示移開其他物品並重新感應 |
| NFC 移開 | 更新標籤目前是否在座旁；本場「已感應」紀錄保持有效 |
| NFC 事件過期／重播／座端斷線 | 拒絕舊事件；座端斷線時不能新增已感應狀態，已確認的本場狀態仍保留 |
| 場次結束／重置／備機接手 | 清除已感應狀態；已開始的回收只結算一次 |
| 同一標籤持續感應 | 保持本場已感應狀態；回收仍等待按鈕，已回收則不再次結算 |
| SAN 達限制 | 正常停止捕捉、進入 NFC 回收引導 |
| 低電／電源瞬降 | 提醒工作人員，備機轉移或中止，保留已確認紀錄 |
| 系統音效誤觸收音 | 調整擺位、輸入抑制、平滑與擾動門檻，降低音虫誤反應 |
| 外網斷線／雲端同步失敗 | 現場照常，outbox 保留；同一 token 復線後發布，網頁提供尚未就緒提示及重試 |
| 網頁音軌／播放失敗 | 提示點擊、重試及音量；感謝信與收集摘要仍可查看 |
| Unity 當機 | 依最後確認快照安全恢復，否則中止；先關燈，不用 LCD 本地數值重建成果 |
| 重置／本機保存失敗 | 暫停下一場，確認關燈與資料後由管理端排除 |
| 列印功能啟用時印表機故障 | 線上成果仍必須交付，紙本工作可補印 |

備用捕捉器需同韌體、相機及瞄準校正，標籤 UID 預先登錄。重置不刪除已存成果、outbox 及標籤設備對照；但須清除本場選用捕捉器、已感應與已回收狀態。

## 11. 管理功能

管理頁顯示本場使用哪支捕捉器、設備連線與電量、啟用點／目前群落、燈控執行確認（ack）、瞄準點與偏移、SAN、NFC 已感應／已回收、待上傳成果及列印狀態。提供開始、暫停、中止、切換備機、單燈檢查、NFC 狀態檢查、重置及補印，僅供已登入的工作人員使用。

啟動順序包含 Gateway、固定燈控、回收座、音訊、Unity 及管理頁。編碼設定版本不一致、板卡未就緒或無法確認全燈停用，不開放新場次。日誌保留版本與錯誤，不記錄完整憑證。

- [PAJ7025R3 原廠資料表](https://www.codico.com/media/productattach/p/i/pixart_paj7025r3_-_productbrief_2461050_4.pdf)：SPI、多光點資訊及電氣規格。
- [PAJ7025R3 樣品包](https://www.codico.com/en/paj7025r3-sample-kit-cdc)：標示視角與採購參考；樣品包不等同完整 ESP32 開發套件。
- [Espressif ESP-NOW](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/network/esp_now.html)：裝置間無線通訊文件。
- [Sunton 板卡定義](https://github.com/rzeldent/platformio-espressif32-sunton)：板型設定與接腳資料參考。
- [Sunton 顯示器驅動](https://github.com/rzeldent/esp32-smartdisplay)：LVGL 顯示介面實作參考。
- [Espressif SPI LCD](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/lcd/spi_lcd.html)
- [Espressif RGB LCD](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/lcd/rgb_lcd.html)：RGB 平行介面顯示器文件。
- [MDN WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API)
- [Unity 多顯示器](https://docs.unity3d.com/6000.0/Documentation/Manual/MultiDisplay.html)
- [Unity Microphone.Start](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Microphone.Start.html)
- [Unity Audio Mixer](https://docs.unity3d.com/6000.0/Documentation/Manual/AudioMixer.html)
- [MDN 媒體播放](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)
- [Node.js 支援版本](https://nodejs.org/en/about/previous-releases)
- [Unity 6 版本資訊](https://unity.com/releases/unity-6)
- [Next.js App Router](https://nextjs.org/docs/app)

- [ESP32-S3 GPTimer](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gptimer.html)：硬體計時器文件。
- [DFRobot Gravity NFC 模組 DFR0231-H](https://www.dfrobot.com/product-1917.html)：回收座模組資料，I²C／UART 與 ESP32 相容說明。
- [Adafruit PN532 函式庫](https://learn.adafruit.com/adafruit-pn532-rfid-nfc/arduino-library)：讀取相容標籤與接線參考，核對實際模組介面。
- [NXP NTAG213／215／216](https://www.nxp.com/products/NTAG213_215_216)：被動式 NFC Type 2 標籤資料。
- [NXP PN532 產品狀態](https://www.nxp.com/products/rfid-nfc/nfc-hf/nfc-readers/nfc-integrated-solution:PN5321A3HN)：原廠產品狀態。
- [NXP PN7160](https://www.nxp.com/products/PN7160)：控制器資料。

完整連結分類見[重要連結](重要連結.md)。與既有手機輸入方案相關的規格及參考保留於[手機方案規格存檔](archive/手機方案規格_v0.8.md)，不列入目前紅外線方案驗收。
