# 音虫互動投影開發規格

日期：2026-10-30  
版本：v0.9  
用途：自製無線紅外線捕捉器、本地互動、雙牆定位、回收及成果服務的開發與驗收規格。

組員概覽見[技術架構](技術架構.md)。候選模組為 PAJ7025R3；雙牆自動識別、覆蓋、供貨、續航及效能均待原型，不以套件支援宣稱代替驗收。

## 1. 功能與遊戲狀態

### 功能範圍

單人城市互動投影，主要輸入為自製無線捕捉器。捕捉器使用 ESP32-S3、廣角紅外線追蹤相機、LCD、捕捉按鈕、震動馬達及聲音回饋。觀眾可自由走動、轉向 L 形兩面投影；雙牆自動識別是必要功能，尚待原型驗證。

Unity 管理音虫生成、微動、消失、聲音反應、成功捕捉、SAN、回收與城市修復。SAN 依成功捕捉數量扣減。未達任務條件且 SAN 尚可捕捉時繼續探索；SAN 達限制即進入正常回收流程。回收後直接進入結尾。

### 狀態流程

```text
待機 → 接待區前導／領取捕捉器 → 建立場次並綁定裝置 → 教學 → 探索／捕捉
  ├─ 未完成且可捕捉 → 繼續探索／捕捉
  ├─ 達成任務 → 前往回收站
  └─ SAN 達限制 → 停止捕捉，前往回收站
前往回收站 → 回收座確認捕捉器到站 → 開放回收操作
→ 回收結算 → 轉化／城市修復 → 本機保存成果 → 成果 QR／選配列印
→ 撤銷控制權 → 裝置及場景重置 → 待機
```

場次啟動由本機管理端操作；領取捕捉器不直接跳過初始化。前導在接待區播放，遊戲教學由 Unity 與裝置呈現。

### SAN 與結算

SAN 可採 `max(0, 初始值 - 已成功捕捉數量 × 每隻扣除值)`，初始值、扣值及任務條件以設定檔管理。按鍵要求不算成功；只有 Unity 確認後才扣值及更新 LCD。

Unity 是遊戲狀態的唯一權威。捕捉器、回收座與本機串接服務（Gateway）只提出要求或回報感應資料，不自行增加捕捉數、修改 SAN 或完成任務。

### 結束與重置

1. 本機持久化本次收集清單、修復結果、感謝信與旋律配方，建立獨立成果 token 與待同步工作。
2. 標記場次完成、撤銷裝置操作權，清除裝置上的待提交操作與本場 SAN 顯示。
3. Unity 清空本場音虫、生成計時、SAN、收集清單、冷卻、瞄準、回收座狀態及暫存提示，恢復待機場景與聲音。
4. Unity 回報 `EXHIBIT_READY`，本機服務確認裝置就緒後，才釋放名額並依管理設定開放下一場。
5. 中途離場、啟動失敗或逾時中止時，撤銷控制權再執行重置；未完成場次不標為成功成果。

成果、待同步佇列與列印工作按場次獨立保存，遊戲重置不刪除它們。雲端同步與列印可背景續作；本機保存或重置失敗時暫停入場。

## 2. 部署、軟體與設備

### 本地互動與雲端成果

```text
牆面紅外線參考點 → PAJ7025R3 候選模組 → SPI → ESP32-S3
                                                     ├─ 按鈕
                                                     ├─ LCD
                                                     ├─ 馬達驅動 → 震動馬達
                                                     └─ 聲音播放／功放 → 小喇叭
ESP32-S3 ↔ 展場 Wi-Fi／WebSocket ↔ 本機串接服務（Gateway，Node.js）
                                             ↕ 本機 WebSocket
                                       Unity Windows
                                        ├─ Camera A → 主投影 A
                                        ├─ Camera B → 主投影 B
                                        └─ 回收視圖／現場聲音
回收座接點／感應介面 → 控制板／USB → Gateway → Unity
現場麥克風 → 多輸入音訊介面 → Unity 或本機音訊分析服務
Gateway → SQLite／事件紀錄／待同步佇列／Windows 列印
Gateway → HTTPS → 雲端成果 API／PostgreSQL／音樂素材
觀眾手機 → HTTPS → Next.js 成果頁
```

原型預設採展場 Wi-Fi WebSocket，主機走 Ethernet。WebSocket 是應用程式連線，外網不參與捕捉結算。裝置只能連已配對的本機服務；區網隔離、憑證驗證與正式部署是否使用 TLS 於整合時定版。

若改採 OpenFIRE 的 ESP-NOW 無線路徑，需增加相容 ESP32-S3 USB 接收器及主機轉接程式，並驗證瞄準與遊戲狀態的雙向傳輸；不是電腦 Wi-Fi 就能直接接 ESP-NOW。兩種無線路徑擇一驗收，不串接成不必要的多層路徑。

### 電源與續航

每台約 2 小時為設計目標，並非續航保證。以 3.7 V、3000 mAh 為例，標稱能量 11.1 Wh；若假設可用約 9 Wh，平均 2／4／6 W 分別約 4.5／2.2／1.5 小時。此為估算，不直接指定正式電池。

量測開機、持續追蹤、LCD 背光、無線、聲音及震動同時啟動的平均與峰值功耗，再決定電池。不得以休眠電流估算遊戲續航。裝置回報電量與低電狀態；無法可靠取得百分比時不顯示虛構精確數字。低電不自行清除遊戲，交由管理端安全轉移備機或中止。

## 3. 場次建立與控制權

1. 啟動音訊、本機串接服務、Unity 與管理頁，確認裝置配對、校正版本及回收座狀態。
2. 工作人員以本機管理端選定捕捉器並按開始，本機服務原子保留唯一名額，建立待啟動場次；重複啟動使用同一要求 ID。
3. Unity 初始化並回覆 `SESSION_PREPARED`，才綁定裝置與有效控制世代，回傳完整 SAN／流程快照；初始化失敗時清理後才釋放名額。
4. 同場只接受一台已配對捕捉器。備用機保持待機，不接受遊戲操作；管理端轉移控制權時遞增 `control_epoch`，舊裝置命令立即失效。
5. 短暫斷線保留場次、取消未完成捕捉，裝置回報連線中；重新綁定後取得完整快照，重新定位再開放按鈕。
6. 逾時或中途離場由管理端中止，完成重置後再開放。裝置關機或離線本身不立即釋放名額。

展場主機未就緒、啟動中、遊戲中或重置中均拒絕第二場。裝置連線須驗證配對資訊、有效場次與控制世代；管理頁需登入。成果頁永遠唯讀，不取得展場操作權。

## 4. 紅外線定位、雙牆與捕捉

### 光點資料與座標

PAJ7025R3 提供紅外線光點座標、大小及亮度等資料，不會直接給出音虫 ID 或牆面 ID。韌體經 SPI 讀取，校正鏡頭畸變、判定光點組別，將裝置的固定瞄準軸映射到牆面標準化座標 `u/v`（左上 0,0；右下 1,1）。

布展分別建立牆面 A／B 的參考點實體配置、正式投影映射與校正版本。以可靠的點對應估算平面透視關係；若使用四點平面求解，必須能識別足夠且非退化的對應點，不能只靠一顆亮點猜測牆面。廣角畸變修正、偏離中心的瞄準軸及外殼裝配誤差均納入校正。

音虫微動、生成、消失、命中範圍與遮擋由 Unity 決定。Unity 將目標位置映射到相同牆面座標，與當次瞄準位置比對；光點不隨音虫移動。調整投影 warp、比例、參考點、鏡頭或模組固定角度後重新校正。

### 雙牆自動識別：必要功能、待驗證

不能把 OpenFIRE 的單畫面四點追蹤或多份校正設定，當作現成雙牆自動辨識。感測器可輸出多光點，也不代表韌體會自動將它們分成牆面。

原型需選定並驗證識別方式，例如可辨識的參考點幾何配置或帶時間編碼的發光控制；兩者都是工程候選，尚未定版。時間編碼需同步感測取樣與光源控制，幾何配置需測斜拍與透視後是否仍可區分，不先承諾有效。

牆面切換狀態：
`SEARCHING → CANDIDATE_A/B → TRACKING_A/B`；點數不足、兩組混雜或誤差過大時進入 `AMBIGUOUS/LOST` 並停止捕捉。新牆需連續穩定通過才切換，清除舊瞄準資料，不能直接沿用上一面牆座標。進入與退出門檻分開，避免轉角來回跳牆。

手動選牆只可用於工程除錯，不取代正式雙牆自動切換驗收。若單牆原型成功而雙牆失敗，仍視為定位尚未通過，須回報團隊調整，不默認縮小互動需求。

### 捕捉與延遲

1. 定位程式送出牆面、校正版本、樣本序號、樣本年齡、有效點數、品質及 `u/v`。
2. 按鈕送出 `CAPTURE_START`，引用同一次有效追蹤樣本。Unity 驗證裝置、場次、控制世代、映射版本、座標、資料新鮮度、可捕捉階段、目標、冷卻與 SAN。
3. Unity 以當前狀態判定；目標消失、已捕捉、樣本過期或失去定位時拒絕，提示重新瞄準。
4. 確認成功後更新音虫、SAN 與收集紀錄，再回傳結果。裝置本地可先顯示處理中，成功音效與成功震動只依確認結果觸發。
5. 按鍵或長按時長待遊戲規則定版；長按須設心跳／租約，失聯立即取消未完成動作。

高頻瞄準資料限流並採最新樣本優先；捕捉、回收等結算命令需確認與去重。樣本新鮮度須合併裝置端樣本年齡與傳輸時間，時間同步及容許誤差於協定定版。定位失效或資料過期時不得使用最後一次成功座標繼續捕捉。

### 覆蓋測試

以實際投影尺寸測距牆 0.5／1／1.5 公尺、側邊、不同高度、快速轉向與轉角，記錄定位誤差、失效率及切換時間；這些是測試點，不是已保證可用範圍。模組標示約 143° 視角需確認水平／垂直定義及有效邊緣精度，不能直接套成整牆覆蓋。

投影機、展場燈與鄰展設備開啟，播放亮／暗／閃動場景，驗證干擾及反射。測試參考點遭人、裝飾或回收站遮擋的情況。參考點數量與安裝位置須以覆蓋測試決定。

## 5. 裝置、Unity 與成果服務串接

| 模組 | 職責 |
| --- | --- |
| 捕捉器韌體 | 光點與瞄準資料、裝置身分、按鈕、LCD、電量、震動及短音效 |
| 本機 Gateway | 連線／配對驗證、場次與控制綁定、限流、事件去重、快照、成果 outbox 及列印 |
| Unity | 唯一遊戲狀態、命中、SAN、回收、投影及聲音；網路事件排入主執行緒 |
| 本機管理頁 | 開始／暫停／中止、裝置切換、重置、測試與補印 |
| 雲端 Next.js | 唯讀成果查詢與播放；接收已驗證的成果上傳，不轉送遊戲操作 |

本機 HTTP API 草案：`GET /api/exhibit/status`、`POST /api/sessions/start`、`POST /api/sessions/resume`、`GET /api/calibration/manifest`。開始及恢復只供已授權管理／裝置流程使用，非觀眾手機操作。

雲端 API 草案：`POST /api/results`（展場服務認證、依 result_id 冪等上傳）、`GET /api/results/:token`（唯讀）。雲端上傳使用 HTTPS。相同成果重試不得重複發布或列印。

遊戲事件路徑：`捕捉器 → 區網 → Gateway → Unity → Gateway → 捕捉器`。Unity 回傳 SAN、revision、階段與回饋，裝置不能單靠本地計數更新正式結果。LCD 只需數值與狀態資料，不傳相機預覽。

捕捉訊息範例（邏輯 JSON 草案；無線封包編碼可另訂）：

```json
{
  "protocol_version": 2,
  "type": "CAPTURE_START",
  "device_id": "catcher-01",
  "session_id": "session-example",
  "control_epoch": 1,
  "request_id": "capture-unique-id",
  "payload": {
    "wall_id": "wall-a",
    "reference_group_id": "ir-group-a",
    "content_version": "city-v1",
    "calibration_version": "cal-v1",
    "tracking_seq": 42,
    "sample_age_ms": 30,
    "u": 0.42,
    "v": 0.61,
    "visible_point_count": 4,
    "tracking_valid": true
  }
}
```

回覆攜帶同一 request_id、成功與否、原因、最新 revision、SAN 與收集狀態。Wi-Fi、ESP-NOW、USB 測試轉接層使用同一邏輯事件；不同傳輸不能各自產生獨立遊戲狀態。

## 6. 聲音與回收站

### 聲音來源分工

| 來源 | 資料 | 對應功能 |
| --- | --- | --- |
| 預製城市與音虫聲音 | 音檔、聲源位置與種類 ID | 引導尋找、辨認區域、提供捕獲音色 |
| 現場麥克風 | 各通道音量、發聲持續時間、必要時頻段特徵 | 吸引／聚集音虫，超過持續門檻時增加活動或生成風險 |
| 捕捉器按鈕操作 | 開始／取消／完成要求 | 模擬收錄指定音虫，依遊戲目標取得聲源 |
| 結尾旋律 | 預製音軌 ID、編排與音量 | 依收集種類組成個人化成果 |

麥克風由音訊介面輸入 Unity，分析音量與持續時間。多通道讀取及驅動相容性需實測，必要時透過本機音訊服務傳回分析值。（參見文末 Unity Microphone 文件）

### 即時處理規則

- 遊戲開始前依各區背景音量校正收音門檻。
- 使用平滑、持續時間、觸發／解除不同門檻及冷卻，避免一聲噪音重複觸發。
- 每支麥克風對應固定區域權重。
- 「吸引既有音虫」與「新增音虫」是不同事件，分別設門檻、冷卻與生成上限。
- 依喇叭、捕捉器音效與麥克風擺位測試回授，對系統提示音採輸入抑制，降低誤觸。
- 收音只在本機即時分析，第一版不保存人聲、不上傳人聲，也不做語意辨識。
- SAN 依捕捉數量降低；現場聲音影響音虫活動。
- 聲音處理不依賴雲端；捕捉器連線暫停時，現場聲音與畫面仍由本機運作，但不得讓未確認的捕捉繼續結算。

### 回收座到站確認與操作

回收站設於出口附近，以消光實體造型承接能量集中、轉化及物品生成演出。捕捉器靠近回收座，以接點或感應確認到站；具體型號待選。接點／感應用於近距離到站確認，不用於牆面瞄準。

1. SAN 達限制或任務達成後，Unity 進入「前往回收站」，裝置與投影顯示引導。
2. 回收介面回報 station_id、感應狀態、樣本時間與可取得的裝置識別資訊。無裝置識別的單純有人訊號，不得直接等同有效捕捉器到站。
3. 驗證到站訊號與本場有效捕捉器關聯，經去抖及持續有效確認後，Unity 開放回收操作。
4. 原型先規劃沿用捕捉按鈕，在 LCD 顯示「按下回收」；正式按鍵配置於介面測試確認。按下時再次驗證場次、階段與最新到站狀態。
5. Unity 鎖定捕捉清單、產生唯一 recycle_id，執行轉化、城市修復及成果保存。完成後離開回收座不重複結算。

到站資格不能僅用「瞄準回收站」代替。感應失效、拔離或資料過期時取消到站資格並鎖定操作；回收已確認執行後則以 transaction 狀態完成一次。接點需防彈跳、誤短路與接觸不良；感應需測有效距離與誤觸。

回收座固定供電；接點或感應方案均不預設支援充電。若增加充電須另訂電源、保護與接點規格。

## 8. 成果保存與列印

### 音樂產生

音樂素材先統一 BPM、拍號、循環長度與起點，再依捕捉種類選取音軌、編排與混音。以種類控制聲部、數量控制有限的密度或段落，避免收得多就無限制疊音。

成果儲存 `recipe_version`、音軌版本、編排參數與固定 seed，確保每次開啟播放相同的預製音軌組合。

成果頁依共同時間軸播放音軌。單一音檔下載列為擴充功能，需增加伺服器混音及檔案儲存。

### 成果保存與連結

- Unity 完成回收後建立本機不可重複的成果記錄，本機串接服務（Gateway）將成果送到雲端。
- 雲端資料庫保存收集清單、修復結果、感謝信模板與音樂配方；版本化音檔置於靜態資源／物件儲存。
- 結尾投影／成果顯示區與選配票面提供成果 QR Code；觀眾手機開啟獨立網址，可加入書籤或分享。
- 成果連結使用不可猜測的唯讀 token，不使用可遞增流水號公開所有人的紀錄。
- 成果 token 與場次操作憑證分開；場次結束後撤銷操作權，唯讀成果連結仍有效。
- 頁面載明成果保存期間，服務費用與保存期限待團隊確認。
- 外網暫斷時本機保留待同步成果；可列印預先配置 token 的成果連結，同步完成前頁面顯示處理中。

### 實體列印

印表機連接展場主機，由本機服務透過 Windows 驅動與列印佇列輸出。若使用 ESC/POS，需驗證型號與指令相容性。

票面可包含音虫圖案、收集摘要、感謝文字與成果 QR。每份成果預設列印一次，補印由管理端明確操作。缺紙或卡紙只標記列印失敗，不重算成果、不重播整段遊戲。

## 9. 通訊介面與資料模型

### 事件與可靠性

捕捉器送要求，Unity 回已確認結果。邏輯訊息含 protocol_version、device_id、session_id、control_epoch、request_id、type、payload；配對與服務憑證置於認證層，不寫一般日誌。裝置位址不能單獨作為授權依據。

| 方向 | 事件 | 功能 |
| --- | --- | --- |
| 管理端 → 本機服務 | SESSION_START／SESSION_RESUME | 排他建立、恢復場次與選定裝置 |
| 裝置 ↔ 本機服務 | DEVICE_HELLO／CONTROL_BIND／HEARTBEAT | 配對、狀態、控制世代與存活確認 |
| 裝置 → Unity | TRACKING_UPDATE／TRACKING_LOST | wall_id、reference_group_id、校正及內容版本、樣本序號／年齡、u/v、品質、有效點數 |
| 裝置 → Unity | CAPTURE_START／CAPTURE_CANCEL | 按鍵／長按的要求與取消 |
| Unity → 裝置 | AIM_FEEDBACK／CAPTURE_RESULT／STATE_SNAPSHOT | 最新追蹤提示、SAN、收集狀態、遊戲階段、回饋及 revision |
| 裝置 → Gateway | DEVICE_STATUS | 電量、韌體、錯誤、連線與校正版本 |
| 聲音分析 → Unity | AUDIO_FEATURES | 區域音量與持續時間，不含雲端原始人聲 |
| 回收介面 → Unity | STATION_PRESENCE／STATION_LOST | 站點、裝置關聯、感應狀態及時間 |
| 裝置 → Unity | RECYCLE_REQUEST | 可回收階段與到站有效時提出回收 |
| Unity → Gateway | RECYCLE_COMMITTED／RESULT_READY | 固定回收交易、成果與 outbox |
| Unity → 本機場次服務 | SESSION_PREPARED／EXHIBIT_READY | 初始化與重置完成後才開放操作 |
| 本機場次服務 ↔ Unity | SESSION_END／SESSION_ABORT | 結束／中止，撤銷控制權並重置 |
| 管理端 → Gateway | PAUSE／RESET／REPRINT／CONTROL_TRANSFER | 受保護的維運操作 |

request_id 去重；重送不得重複捕捉、扣 SAN、震動或列印。快照含遞增 revision，裝置忽略舊狀態；瞄準回饋帶 tracking_seq，以免顯示舊樣本。重連拉完整快照，不重播歷史動畫。錯誤包含 SESSION_BUSY、CONTROL_REVOKED、TRACKING_LOST、WALL_AMBIGUOUS、STALE_SAMPLE、NOT_AT_STATION；錯誤碼於協定定版。

裝置可立即顯示處理中，業務成功須等 Unity 確認。傳輸層送達不等同業務完成。高頻樣本可丟棄舊資料；結算命令須 ack、逾時與同 ID 重試，並限制訊息大小、類型與頻率。

### 最小資料模型

| 資料 | 核心欄位 |
| --- | --- |

| ExhibitSlot | 展場 ID、入場開放、主機就緒、唯一場次、保留逾時 |
| ControlBinding | session_id、device_id、配對認證、有效連線、control_epoch、心跳及恢復期限 |
| DeviceDefinition／DeviceStatus | 韌體、配對、LCD／回饋能力、電量、錯誤及連線 |
| WallDefinition／ZoneDefinition | 牆面、輸出對應、互動範圍、生成規則 |

## 10. 異常與備援

| 情況 | 處理 |
| --- | --- |
| 光點不足／反射干擾／瞄準超出範圍 | 標定位失效、停止捕捉，LCD 提示重新對準；現場調整光點與曝光 |
| 兩牆混雜／自動切換不確定 | 暫停捕捉、清除舊座標，穩定識別後才恢復，禁止猜牆 |
| 校正版本不符 | 拒絕操作、管理端重新載入並驗證 |
| 音虫消失或已捕捉 | 不扣 SAN，回傳重新對準提示 |
| 無線掉線／裝置重啟 | 保留場次、取消未完成捕捉；驗證控制權、取快照並重新定位，逾時中止 |
| 備用裝置接手 | 管理端轉移、遞增控制世代，撤銷原裝置並同步 SAN |
| 重複開始／多機同時操作 | 原子名額與 request_id 去重，只有有效綁定裝置可操作 |
| 初始化失敗／Unity 未就緒 | 清理待啟動場次，重置完成後才開放 |
| 低電／電源瞬降 | 提醒工作人員、停止不可靠提交，安全轉移備機或中止；測負載與供電 |
| SAN 達限制 | 正常停止捕捉、進入回收引導 |
| 回收座誤觸／感應過期／拔離 | 清除到站資格、鎖定回收；已開始的已確認交易只完成一次 |
| 喇叭或捕捉器音效誤觸收音 | 調擺位、平滑、門檻與播放抑制，限制音虫生成 |
| 外網中斷 | 現場繼續，本機保存待同步；成果頁未完成發布時顯示準備中 |
| Unity 當機 | 讀最後確認快照；無法安全恢復時中止，不依 LCD 數值重建成果 |
| 結束後收到舊裝置命令 | 依場次及控制世代拒絕，不影響下一場 |
| 重置或本機保存失敗 | 暫停下一場，管理端排除 |
| 印表機缺紙／故障 | 保存數位成果與列印工作，管理端補印，不重算遊戲 |

準備同韌體、同相機與經校正的備用捕捉器。裝置到 Unity 的邏輯介面固定為牆面、瞄準座標與操作事件，方便維護。正式展出前完成備機轉移、充電輪替與復原演練。

## 11. 管理、測試與驗收

管理頁顯示入場狀態、場次、有效裝置與控制世代、Unity／回收座狀態、校正版本、牆面、點數、追蹤品質、瞄準位置、SAN、麥克風、電量、待同步成果與列印。提供開始、暫停、中止、控制權轉移、重置、測試、音量校正與補印，必須認證且僅供工作人員使用。

固定腳本啟動 Gateway、音訊、Unity 與管理頁。日誌保留版本、時間、錯誤及測試結果，不記錄完整認證資訊或一般觀眾原始人聲。

| 階段 | 範圍 | 通過條件 |
| --- | --- | --- |
| P0 單牆 | PAJ7025R3、ESP32-S3、參考點、按鈕、LCD、本地連線、Unity 音虫 | 0.5／1／1.5 公尺測試並記錄可用範圍；能正確捕捉微動目標，消失與定位失效不誤結算 |
| P1 雙牆 | 正式大小的 L 形雙牆、實際站位及混合光點 | 自動識別兩牆，轉向後恢復、歸屬不明時停止；人工切牆不算正式通過 |
| P2 完整流程 | 單人綁定、SAN、聲音／震動、到站回收、旋律、感謝信及成果 QR | 連續兩場完全隔離；斷線／備機轉移不重複結算，到站前不能回收 |
| P3 展場 | 投影光路、正式聲音、無線、電源、列印與維運 | 光源、遮擋、續航、故障恢復與持續運作通過，所有限制有紀錄 |

開發目標尚非測得數據：
- 裝置按壓立即顯示處理中；捕捉要求至投影確認回饋的 p95 初期目標 ≤300 ms，另量測 LCD、聲音與震動回傳。
- 區分光點取樣、定位、無線、Gateway、Unity 與顯示延遲；依音虫實際大小設定誤差及切牆時間門檻。
- 人聲至本機音虫反應初期目標 ≤150 ms；量測音訊緩衝及裝置路由。
- 所有預期站位測距、斜拍、高低位置、快速轉身、轉角兩組參考點、反射、遮擋與不同投影明暗；記錄定位失效及誤認牆面。
- 未定位、錯牆、舊樣本、過期回收感應、舊場次或控制世代一律不能結算。
- 測斷線、封包遺失、延遲、亂序、同 ID 重送、裝置重啟與備機接手；不能重複扣 SAN、回收、成功回饋或列印。
- SAN 達限制即進入回收，站點未確認不能回收；接點去抖、感應距離、拔離及裝置身分關聯均測試。
- 關閉外網仍可完成一場、本機保存、重置並開下一場；恢復後只上傳一次，各成果可在另一台手機及展場關機後重開。
- 裝置續航以 2 小時為目標，測追蹤、亮屏、無線、頻繁震動及聲音下的整機功耗、峰值、溫升與充電週期；不足時調整電池及輪替，不用估算代替驗收。
- 主機先連續運作 4 小時，再做完整展出日測試；記錄掉幀、記憶體、掉線及恢復時間。P2 後固定投影解析度、FPS、場次時長與網路門檻。

| 設備接線及部署 | 投影輸出、音訊、控制板、網路、電力、光路與啟動腳本 |
| 美術聲音交付 | 雙牆座標、模型／動畫、LCD、聲源、音軌與紀念品 |
| 展場操作手冊 | 接待、綁定、校正、備機、充電、重置、備份、故障與補印 |

建議目錄：`firmware/`、`unity/`、`gateway/`、`web/`、`server/`、`shared/`、`docs/`。shared 放共用 schema、內容 ID、校正格式與設定；金鑰及觀眾成果不進版本庫。

分工分為 Unity／投影、硬體／韌體／定位、本機通訊／成果、Web／管理／紀念品、聲音及美術，由組員依專長分配。

### 待定規格

1. PAJ7025R3 供貨、轉接板、光點規格、有效視角與雙牆自動識別方式。
2. 0.5／1／1.5 公尺原型結果與正式最近／最遠站位、誤差及切換門檻。
3. 回收座接點或感應型號、裝置識別、去抖及 LCD 按鍵呈現。
4. 任務條件、SAN 扣值、體驗時長與捕捉按壓時間。
5. 裝置電池、聲音／LCD 型號、充電與備機數量；本地 Wi-Fi 路徑原型效能。
6. 牆高、投影機型號、光路、回收站輸出及圖上中央／後台主機配置。
7. 成果是否需混音檔下載、保存期限、印表機與成果 QR 顯示位置。
