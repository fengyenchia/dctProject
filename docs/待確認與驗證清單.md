# 音虫互動投影｜必要討論清單

日期：2026-11-07

只列需要組員決定的內容及影響可行性的關鍵測試。架構見[技術架構](技術架構.md)，裝置構想見[捕捉器示意圖](assets/手持掃描器畫面.png)。

## 1. 紅外線捕捉

- [ ] 正式有幾個出現點、最多同時出現幾群音虫？
- [ ] 自動捕捉時間：原型建議先以 **同一群累積有效對準 3 秒**為基準，視測試再比較 2／5 秒；正式秒數尚未定案。分別量測點位首次辨識延遲與有效對準計時，不能把延長等待當作辨識正確的保證；驗證移開暫停、換群分別保存、再次對準接續及新群不繼承舊進度，並確認手部疲勞與進度回饋是否影響體驗。
- [ ] **原型測試：** 長牆 2 點＋側牆 1 點，在 0.5／1／1.5 公尺、斜掃、轉角及手部晃動時，能否在捕捉時間內正確讀出不同閃爍編碼？並確認群落亂動範圍與對準容許範圍相符。量測多點編碼、反射光及亮暗間隔下的辨識率，確認光點重現後不會錯配點位；相機能看到多點不等於已能可靠辨認各點。
- [ ] **安裝測試：** 幕材是否擋紅外線、燈是否需要外露，以及投影光、現場照明與遮擋是否影響辨識？

## 2. 任務與聲音互動

- [ ] 任務達成條件、SAN 初始值／每次扣值，以及一場體驗時間？
- [ ] 觀眾發聲是否保留為可選反應，或成為必要操作？原型建議先做一次簡短引導（例如「輕聲呼喚，看看音虫會怎麼回應」），觀察觀眾是否願意嘗試，以及能否理解聲音造成的反應；不願發聲時仍可完成捕捉。此為評估建議，尚未改為正式互動規則。
- [ ] 聲音擾動原型建議：依現場背景音校正門檻；超過門檻且持續約 0.3～0.5 秒後，才依相對音量調整既有群落的局部亂動強度，持續發聲則維持反應，停止後漸復原。實際門檻、時間、恢復速度及是否影響捕捉難度需實測，不要求大喊；只擾動既有音虫，不觸發誕生。
- [ ] 捕捉器噪音促使新音虫誕生：具體生成時機、空閒點位、數量及可出現種類如何設定？所有點都被占用時，要捨棄或延後生成？回收引導期間如何呈現最後一次捕捉促成的誕生，回收演出開始時如何收束？
- [ ] **收音測試：** 麥克風怎麼擺，才能收到觀眾聲音，並減少展場音響（含故事中的捕捉器噪音）及隔壁展品誤觸發？

## 3. 捕捉器

- [ ] 雷達只是搜尋動畫，還是要顯示音虫實際方向／距離？目前紅外線方案不提供完整周圍地圖。
- [ ] 捕捉器頁面與操作細節：以觸控＋LVGL 為技術方案，原型建議主操作頁常駐 SAN、目標狀態、捕捉進度與電量，以可見頁籤／虛擬按鈕切頁，滑動作輔助。其他頁面內容、頁籤位置、可滑區域及捕捉中是否鎖定切頁需確認。
- [ ] 除 SAN 與捕捉進度，是否需要收藏總覽、音虫詳細卡片？
- [ ] **板卡實機驗證：** 依[Waveshare 2.8 V2 接腳分配](開發規格.md#候選板接腳分配)，測試 PAJ7025R3 的獨立 SPI、觸控顯示、I²C 震動與 Wi-Fi 同時運作；確認切頁／震動不影響紅外線取樣及供電。核對實際板背 V1／V2、相機樣品轉接板與電壓，再定外殼。GPIO43／44 不再輸出 UART 日誌，USB 燒錄與日誌須正常；SD 卡停用或採 1-bit 模式，確認不占用相機的 GPIO15／18。另確認電池電量的實際量測來源；未有量測資料時不得顯示推算或假電量。
- [ ] **採購核對：** Waveshare SKU 27690、V2／CST3530 的蝦皮直接商品頁、發票統編、庫存及交期；確認套裝線材，及 PAJ7025R3 的台灣供貨。比價上架索引不可直接當成交價或版本保證。
- [ ] **續航與機構測試：** 內建電池的容量、尺寸及固定方式為何？確認充電、保護及電源轉換電路符合主板、相機、螢幕及震動的電壓／峰值電流需求，檢查充電溫升與接線空間，並測試整機能否達約 2 小時目標，再決定備機與充電輪替。

## 4. 回收與紀念品

- [ ] 依收集種類／群落數量，噪音能量會轉成哪些物品、物品如何對應城市修復？具體動畫、音效與演出時長為何？
- [ ] 各音虫聲部的實際音色、素材與組合效果如何設計？同種類重複捕捉是否影響旋律編排？
- [ ] 成果 QR 顯示在哪裡、停留多久？長期保存所需的服務預算、保存政策及展後維護由誰負責？
- [ ] 是否啟用選配的實體列印？設備／紙材預算為何？

## 5. 場地與執行

- [ ] 依[展場配置圖](assets/展場配置_2026-10-29.png)確認實際尺寸、投影機型號／位置，以及人影是否擋住畫面；是否需要架高或短焦？
- [ ] 紅外線燈、支架、供電與走線如何安裝？場地方允許哪些固定方式？
- [ ] 設備哪些能借、哪些要買？各模組由誰負責，第一次三點原型何時完成？
