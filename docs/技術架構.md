## 1. 專案概述與功能範圍

本作品為單人城市互動投影。觀眾觀看前導、領取無線捕捉器，在 L 形兩面投影間自由走動，尋找投影中的噪音生物「音虫」。觀眾發聲會擾動音虫；持續用捕捉器對準同一群音虫一段時間，就會自動捕捉，不需按鈕。

「點位」是音虫的固定出現位置；「群落」是該位置的一隻或一群音虫，也是一次捕捉的單位。「SAN」是遊戲內的精神值，每次成功捕捉扣一次；達任務條件或 SAN 限制後，引導觀眾回收。

音虫在固定點附近的小範圍快速、不規則亂動；每點附近設一顆固定紅外線發射燈。群落出現時啟用該燈，消失時停用。各燈用不同的亮暗節奏表示點位，供捕捉器辨識；投影音虫不跟著這個節奏閃爍。捕捉成功後整群消失、SAN 扣一次；音響播放代表捕捉器產生的噪音，由此促成新音虫誕生。

NFC 感應成功後，系統記住本場已感應，保留到回收或本場結束；觀眾可移開捕捉器，再按其確認按鈕完成回收。系統登錄收集的種類與群落數量，由 Unity 將噪音能量轉化為物品、用於修復城市，並在兩面主投影呈現。每位完成體驗的觀眾取得線上紀念品，包含感謝信、收集摘要與個人旋律，離場後仍可開啟。

## 2. 系統連接架構

```text
Unity → 本機串接服務 → 固定燈控板 → 各點紅外線燈
紅外線相機 → ESP32-S3 捕捉器：點位辨識／LCD／震動／聲音
                            ↕ 展場 Wi-Fi
本機串接服務（Gateway） ↔ Unity：音虫／SAN／投影／聲音／回收
捕捉器 NFC 標籤 → 回收座讀取器 → 回收座 ESP32 → Wi-Fi／Gateway

現場麥克風 → 音訊介面 → Unity 分析 → 既有音虫擾動
捕捉成功 → Unity 捕捉噪音事件 → 音響播放／新音虫生成控制
捕捉器確認按鈕 → Wi-Fi／Gateway → 回收確認事件 → Unity 檢查本場已感應／可回收階段 → 登錄種類／群落數量 → 能量轉化為物品 → 修復城市（雙牆投影）
Unity 成果 → Gateway 保存／上傳 → 雲端資料與音樂素材 → Next.js 線上紀念品網頁
```

本機串接服務（Gateway）是展場電腦上的程式，負責在捕捉器、燈控板、回收座與 Unity 之間轉送資料，並保存、上傳成果。Unity 統一決定音虫狀態、捕捉、SAN 與回收結果；捕捉器回報瞄準及按鈕，依 Unity 的結果更新螢幕、震動與音效。

即時互動在展場區域網路完成，雲端負責離場成果。外網中斷時保存本機成果，復線後上傳。

## 5. 點位識別與捕捉流程

1. **點位設定：** 例如 A01 是長牆的一個出現點，B01 是側牆的一個出現點；各自對應一顆紅外線燈。
2. **呈現與燈控：** Unity 協調音虫出現／消失與該點紅外線發射燈的狀態。
3. **辨識與對準：** 相機讀取光點的閃爍編碼，認出點位；光點接近感測視野中心時，表示捕捉器正對準該群音虫。點位設定已包含所屬牆面。
4. **自動捕捉：** 持續對準同一群音虫，系統辨識有效目標後自動累積進度，LCD／投影同步顯示；達設定時間且群落仍有效才結算，不需按鈕。移開或改對其他目標時進度歸零。
5. **回饋：** 成功後整群消失、該點停燈、SAN 扣一次，LCD 更新並提供震動等回饋。Unity 協調噪音播放與新群落誕生，新群落出現時啟用該點的燈。同一點可換不同種類；點位編碼不變，新群落重新計算捕捉進度。

捕捉器辨識的是固定光點，不逐隻追蹤畫面中的音虫，也不量測觀眾在展場的完整位置。觀眾可走動及轉向兩面牆，捕捉時維持對準即可。

## 6. 聲音、NFC 回收與紀念品

| 環節 | 運作方式 |
| --- | --- |
| 聆聽與發聲 | 預製城市聲音引導探索；麥克風經音訊介面送入 Unity，分析音量與持續時間，觸發既有音虫在固定小範圍內的擾動 |
| 捕捉回饋 | 成功後整群收走、扣一次 SAN 並震動；音響播放代表捕捉器產生的噪音，該事件促使新音虫誕生 |
| NFC 到站 | 座端讀取捕捉器標籤，經 ESP32、Gateway 傳給 Unity，記錄本場已感應；移開後仍保留，到本場回收或結束時清除 |
| 回收與修復 | 感應後可移開，再按捕捉器確認按鈕；Unity 檢查已感應且尚未回收，結算後標記已回收、登錄種類與群落數量；Unity 控制噪音能量轉化為物品、修復城市，並由兩面主投影呈現 |
| 線上紀念品 | Next.js 顯示感謝信、收集摘要與個人旋律，成果連結可離場重開 |
| 實體列印（選配） | 列印紀念品及同一成果 QR Code，線上成果不依賴列印設備 |

兩種聲音分開處理：觀眾聲音經麥克風分析，只擾動既有音虫；捕捉成功則由 Unity 同一次事件協調音響播放與新音虫誕生，不需麥克風重新收到音效。故事中的「精神啃食」就是扣 SAN，「防護器具損害」以震動呈現，不另外計算傷害或降低操作能力。

每支捕捉器的設備編號對照其 NFC 標籤，用來確認到站的是本場使用的捕捉器。Unity 記錄本場「已感應、尚未回收」，觀眾按確認後才結算一次；重複感應或按鈕不重複回收。SAN 與收集資料由主機管理，標籤只提供識別。個人旋律依收集種類組合預製音軌，不同種類各對應一個聲部。

## 8. 場次與資料流程

準備 2～3 支捕捉器，每場由管理端選定並啟用一支，其他待機。換備機時停用舊機操作、保留收集紀錄並清除捕捉進度與 NFC 已感應狀態；新機須重新感應。結尾與成果 QR 交付完成、本機成果保存成功後才重置並開放下一場。Unity 是狀態來源，裝置不自行修改 SAN 或收集數量。

Gateway 將 Unity 的每場成果存入本機資料庫；尚未上傳的成果排入佇列，復線後補傳，遊戲重置不刪除。Next.js 的成果頁與 API 部署於雲端，觀眾以本場成果 QR Code 開啟，離場後仍可查看。另在展場主機提供工作人員管理頁，查看連線、電量、場次、回收與成果同步狀態。
