# 工作包與認領

## 代號怎麼看

| 代號 | 意思 | 包含的工作 |
| --- | --- | --- |
| U | Unity | 遊戲規則、場景、聲音、虛擬介面與回收。 |
| I | Integration（系統串接） | 共用資料、Gateway、保存、上傳、列印與重置串接。 |
| W | Web（網頁） | 成果頁、API、工作人員管理頁。 |
| X | XR 整合／驗證 | Quest Link、頭手追蹤、收音、震動與頭戴效能。 |

字母是本專案的工作分類，數字是分類內的編號，不是人名或全專案執行順序。例如 I1 可先約定資料格式，不必等全部 Unity 美術完成。

## 認領規則

- **先選工作包，再填人名**；不預設誰只能做網頁或美術串接。
- 每包一位主責，負責開發、自測、紀錄結果與交付。
- 同一場景檔、Prefab、Input Actions 同時只由一人修改。
- 每個主責都要交付可重現的測試步驟；Windows 限定問題由主責和 A 一起處理。
- 換包前先合併小成果，不留只有原作者能啟動的版本。
- 認領時選用[分支名稱表](環境與Git.md#分支安排與名稱)，再填入交付紀錄；每個功能從最新 main 開始。

## 三人怎麼認領與接續

建議如下，可互換；確認後把名字填入上方「主責」欄。箭頭表示接續順序。

| 成員 | 認領代號 |
| --- | --- |
| A | U0 → U1 → W1 |
| B | U2 → X1 |
| C | U3 → I1 → I2 |
