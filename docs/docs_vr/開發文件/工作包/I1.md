# I1｜本機串接與保存

[分段排程與整合期限](../02_里程碑與美術期限.md)

| --- | --- |
| **2026/12/22** | **2027/1/3** |

初版驗收：Unity 成果存 SQLite、ACK、重送／重連與管理命令可測。

分支：`gateway/save`；資料格式使用 `shared/result-schema`。開工前依[網頁／Gateway 環境](../共用/網頁開發慣例.md)準備 Node.js 24 LTS、pnpm 11.9.0。

先做第 1～2 節建立服務；第 3～4 節再接 Unity 的 Ending。先完成本機保存／ACK；第 7～8 節接自動重連、故障恢復與管理命令。

## 1. 建立 Gateway

| 步驟 | 在哪裡 | 操作／預期 |
| --- | --- | --- |
| 1 | VS Code → File → Open Folder | 選 repo 根目錄，不是 unity-vr。 |
| 2 | Explorer 建 `gateway/src/` | Windows 最後是 `C:/dctProject/gateway/src/`。 |
| 3 | 複製 [gateway-tutorial.ts](../範例程式/I1/gateway-tutorial.ts) | 放到 `gateway/src/index.ts`，**改檔名**。 |
| 4 | 同時複製 [gateway-admin.ts](../範例程式/I1/gateway-admin.ts) 到 `gateway/src/gateway-admin.ts` | 管理命令與快照；由 index 匯入。 |
| 5 | 建立 `gateway/package.json` | 貼上下方完整內容；僅首次建立者操作。 |
| 6 | VS Code → Terminal → New Terminal | 確認目前位於 repo，再執行安裝命令。 |

`gateway/package.json`：

```json
{
  "name": "audio-bugs-gateway",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "packageManager": "pnpm@11.9.0",
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "check": "tsc --noEmit"
  }
}
```

```text
cd gateway
pnpm add ws
pnpm add -D typescript tsx @types/node@24 @types/ws
```

安裝後提交 `gateway/package.json` 與 `gateway/pnpm-lock.yaml`，不提交 node_modules；本資料夾不使用 package-lock.json。

在 `gateway/tsconfig.json` 建下列完整內容：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "types": ["node"],
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*.ts"]
}
```

## 2. 啟動與核對

在 gateway 終端機：

```text
pnpm check
pnpm dev
```

| 應看到 | 代表 |
| --- | --- |
| check 沒有 TypeScript 錯誤 | 語法與型別檢查通過。 |
| `Tutorial Gateway: ws://127.0.0.1:8787` | 本機 WebSocket 等待 Unity。 |
| `http://127.0.0.1:8788/health` 開啟後顯示 ok | 本機讀取介面啟動。 |
| `gateway/data/` 有 SQLite 及 gateway-key.txt | 本機資料已建立；不提交 Git。 |

終端機保持開著；要停止按 Ctrl+C。其他人初次拉取後在 gateway 執行 `pnpm install --frozen-lockfile`，再用 `pnpm dev` 啟動；不重建 package.json。

## 3. Unity 掛上傳送元件

1. 複製 [UnityGatewayProbe.cs](../範例程式/I1/UnityGatewayProbe.cs)到 `Assets/_Project/Scripts/Tutorial/`。
2. 等編譯；選 Hierarchy 的 DesktopLab → Add Component → UnityGatewayProbe。
3. Probe 的 **Lab** 欄位拖入同一個 DesktopLab 物件。
4. Play，Console 出現 `Gateway key file: <完整路徑>/gateway-key.txt`。
5. 複製這段路徑到檔案總管／Finder 的前往資料夾；沒有檔案就自行建立 `gateway-key.txt`。
6. 把 **gateway/data/gateway-key.txt 的內容**複製進去，存成純文字；不把金鑰放進 Scene 或程式碼。
7. Inspector 勾 Automatic Connection／Automatic Result Save；等自動連線，也可手按 Connect Gateway。
8. 顯示 Connected 才繼續；這是連線成功，還沒保存本場成果。

## 4. 送真實捕捉結果

| 步驟 | 操作 | 應看到 |
| --- | --- | --- |
| 1 | 正常抓 5 群、到站確認、完成暫代修復 | Phase 為 Ending，SAN 0。 |
| 2 | Probe 面板按 Send same result / retry | 顯示 Waiting for RESULT_SAVED。 |
| 3 | 等 ACK | 顯示 RESULT_SAVED (local SQLite only)；Inspector 的 Result Saved 為 true。 |
| 4 | 再按一次相同按鈕 | 仍是同一結果，不多算、不改 token。 |
| 5 | 按 Copy result token | 剪貼簿得到本場公開只讀 token。 |
| 6 | 開 `http://127.0.0.1:8788/results/貼上token` | 回傳實際收集到的 5 個變體 JSON。 |

Probe 會先在 Unity 本機目錄寫 `pending-<result_id>.json`，再傳送；Gateway 用同一交易保存 results、outbox 與 automatic print job 後才 ACK。

**本章不自動重置。**收到 ACK 仍不代表雲端已發布、已列印或已交票。

## 5. 斷線與錯誤測試

| 操作／現象 | 預期／修正 |
| --- | --- |
| 先停 Gateway，再按 Connect | 顯示連線錯誤；Unity 規則仍能保留。 |
| 重啟 Gateway，等自動重連並重送同結果 | 相同 result／token；SQLite 不新增第二份。 |
| key 檔不存在／不一致 | 檢查 Console 路徑、純文字編碼及首尾空白；重新連線。 |
| `EADDRINUSE` | 已有另一份 Gateway；關閉重複的終端機服務。 |
| Send 按鈕沒出現 | 要先 Connected，且正式流程已到 Ending。 |
| 只看到 lab-result.json | 那是U1練習檔；本章由 Probe 組成完整契約。 |
| SQL／SQLite 模組無法載入 | 確認 `node --version` 為 24 LTS；全員依 lockfile 安裝。 |
| PowerShell 阻擋 pnpm.ps1 | 改用同一命令的 `pnpm.cmd`，例如 `pnpm.cmd dev`；不修改系統的腳本安全設定。 |

## 6. 共用成果欄位

| 欄位 | 用途 |
| --- | --- |
| session_id／event_id | 本場及這次操作；重送沿用，不替備用控制器編號。 |
| result_id／token | 同一份保存結果／公開只讀連結。 |
| variants | 5 個不同變體；每個帶名稱、來源及 stem_id。 |
| asset_version／recipe_version | 重開仍用同版圖像、音檔與配方。 |
| melody.stem_ids | 本場 5 個聲部，不由網頁重新抽。 |

在 repo 建 shared/，將 [sample-result.json](../範例程式/I1/sample-result.json) 複製為 shared/result-ready.example.json，提交為跨包對照範本。範例 token 只能用於開發假資料，不上傳雲端。

完整範例：[sample-result.json](../範例程式/I1/sample-result.json)。範例名稱、BPM 與音檔仍是佔位；正式值由素材 catalog 提供。

## 7. 自動重連與固定成果恢復

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | Probe 勾 Automatic Connection／Automatic Result Save | 1～10 秒退避重連；Ending 每 3 秒重試同結果，ACK 後停止。 |
| 2 | 停 Gateway 10 秒再開 | Unity 不中途重開遊戲；重連後恢復本場串接。 |
| 3 | 未收到 ACK 時再按 Send | 同一 pending JSON、result_id、token，不重新抽配方。 |
| 4 | Ending 且 pending 已寫入後停止 Play，再開 Play | 讀最早一份未交付 pending；恢復 Ending 與原五個收藏，重送原成果。 |
| 5 | 依 I2 完成交票及重置，再重新啟動 | 有 delivered 紀錄的舊結果不再當待交付；新場 SAN 100。 |
| 6 | 另用測試複本破壞 pending JSON，再啟動 | Recovery blocked，停止開場；先還原備份，不造成功結果。 |

- 僅恢復**已落盤的完整 Ending 成果**；捕捉到一半當機，不宣稱可接續。停止入場，記錄故障後中止該場，再重新開場。
- 有多份待交付時，依檔案時間逐份交票；不要一次刪 pending 來清畫面。
- pending／delivered 位於 Console 顯示的 Application.persistentDataPath；不是 repo/gateway/data。
- 備份時同時保留 Unity 持久化資料與 gateway/data；不要混用另一台電腦的金鑰。

## 8. 管理命令與快照

先接 [W1 第 5 節](W1.md#5-本機管理頁與前導影片)，照表測，不需另寫第二套控制服務。

| 路徑／訊息 | 實作位置 | 用途 |
| --- | --- | --- |
| GET /state | gateway-admin.ts | 顯示最新 Unity 快照、命令回執、票務。 |
| POST /commands | gateway-admin.ts | 本機金鑰驗證，核對目前場次，再轉送既有 WebSocket。 |
| COMMAND | UnityGatewayProbe.Update | 在 Unity 主執行緒驗證，開始／暫停／恢復／校正／中止／重置。 |
| COMMAND_ACK | Unity→Gateway | 回 accepted 與原因；瀏覽器看回執，不能自行改 SAN。 |
| STATE_SNAPSHOT | Unity→Gateway | 每秒傳階段、SAN、群數、追蹤／收音／保存與到站狀態。 |

| 測試 | 預期 |
| --- | --- |
| PAUSE 後等 2 秒 | 進度、音量、影片停留；恢復後接續。 |
| 尚未回收／交票就送 RESET | accepted=false，不清收藏。 |
| 舊 session 的命令／同 command_id 重送 | 舊場拒絕；同命令沿用回執，不重複執行。 |
| Unity 斷線或超過 5 秒沒有快照 | 管理顯示離線；不把舊快照當當前狀態。 |
| 命令 10 秒無回執 | unknown；先看 Unity 最新狀態，不自動反覆送中止／重置。 |

- 沒有實作的硬體電量／驅動資訊，使用 Link 工具查看並記錄；不回傳假數字。
- 原始收音、逐幀頭手資料留在 Unity；Gateway 不重算捕捉、SAN 或到站資格。
- 本機保存成功、雲端發布與交票是三個不同狀態；票務依 [I2](I2.md)。
