## 電腦測試／Quest 測試怎麼切換

每次切換前先停止 **Play**。

- **電腦測試**：開啟 `CaptureLab`，啟用整個 **XR Interaction Simulator**。到 **Edit → Project Settings → XR Plug-in Management → Windows／Standalone**，取消 **Initialize XR on Startup**，再按 **Play**。
- **Quest 測試**：開啟 `QuestLab`，停用整個 **XR Interaction Simulator**，在同一個設定頁勾回 **Initialize XR on Startup**，確認 **OpenXR** 啟用。連上 Quest Link 後再按 **Play**。

**Initialize XR on Startup 是專案設定，換場景後也要依測試方式確認一次。** Simulator 的啟用狀態則存於各自的場景，調整後按 **Ctrl+S**。

## 1. 第一次測頭戴與手把，從這裡開始


1. 停止 **Play**，在 **Project → Assets → _Project → Scenes** 開啟 `QuestLab`。若沒有這個場景，開啟 `CaptureLab` → **File → Save As…** → 存成同資料夾的 `QuestLab.unity`。
2. 在 **Hierarchy** 選 **XR Interaction Simulator**，取消 **Inspector 最上方物件名稱左邊**的勾選，讓整個物件變灰。**XR Origin (XR Rig)** 保持啟用。
3. Windows 開啟 **Meta Horizon Link → Devices → 頭戴 → USB Test → Test Connection**，確認線材連線。
4. 在電腦的 **Meta Horizon Link → Settings → General → OpenXR Runtime** 按 **Set Meta Horizon Link as active**，若有變更就重新開啟 Unity。在頭戴內啟動 **Quest Link**。
5. Unity 開 **Edit → Project Settings → XR Plug-in Management**，在 Windows／Standalone 分頁勾 **OpenXR**、**Initialize XR on Startup**。在 **OpenXR → Interaction Profiles** 確認已有 **Oculus Touch Controller Profile**。
6. 在 **Project Validation** 處理紅色錯誤。2026/11/24 截圖中的兩項 `optional` 黃色警告可先保留。
7. 按 **Play**。頭戴中應直接進入灰牆遊戲場景，轉頭時視角跟著動。電腦切到 **Game** 觀察，再測左右手把和捕捉器。新版 QuestLab 已接追蹤保護；要開始搖桿探索，先依第 2 節在實體中心 **Calibrate**，再按 **Resume／P**。若仍看到網格空間中的浮動電腦視窗，先回第 4～5 步確認 Runtime 和 XR 啟動設定。

完成標準：頭戴直接看見遊戲世界，轉頭時遊戲視角跟著動，左右手把與捕捉器可追蹤。通過後接第 2 節；右手搖桿是新增功能，依下表另外測試，不沿用舊版的已通過紀錄。

### 右手視角與停止轉向測試

先完成第 2 節校正，進入 **Active**。尚未有正式影片時，用 Enter 跳過開場／教學。

| 操作 | 預期／記錄 |
| --- | --- |
| 左搖桿前後左右，右搖桿左右 | 左手平移；右手連續轉身，不同時平移。原型左右轉速 45°／秒。 |
| 右搖桿向上／向下 | 額外抬頭／低頭，原型 25°／秒、限制 ±30°；身高、地面碰撞、雙手瞄準仍一致。 |
| 按下右搖桿 | 額外俯仰歸零，SAN、收藏及頭部追蹤不重置。 |
| 保持搖桿撥動，按 P 暫停 | 當幀停用人工移動／轉向，角度保留；實際轉頭仍跟著動。 |
| 暫停後仍握著搖桿，再 Resume | 不立刻轉動；放回中心，再撥動才恢復右手視角控制。 |
| 操作 UI；再恢復探索 | `Ui Busy` 時不人工轉向、不累積捕捉；結束後先放開右搖桿回中。 |
| 遮住任一控制器、摘頭戴、開系統選單、拔 Link | 追蹤保護暫停遊戲；人工轉向停止，不清 SAN／收藏。恢復後人工 Resume，再回中。 |
| 重啟 Link／OpenXR，或停用再啟用 Guard | 重新取得目前的 XR 焦點；追蹤子系統替換時清除校正及到站資格，先重新 Calibrate，不沿用舊實體中心。 |
| 搖桿移動／轉向／俯仰，仍站同一實體位置 | Guard 的實體半徑不因此增加；實際接近邊界才提示／暫停。 |
| 按 Calibrate、完成下一場重置 | 額外俯仰歸零，到站資格清除；下一場重新校正。 |
| 實際跑一場 | 記錄俯仰舒適度、轉速、線材、左右眼及捕捉器瞄準；不適時先用右搖桿回正，或在 Right Stick Look 取消 Enable Pitch 後重測。 |

人工視角由 [U3 的 RightStickLook](U3.md#右搖桿視角接線新版-u3) 負責；本頁只接 Quest 的有效追蹤、校正與實機驗收，不再新增第二套 Turn Provider。

設定依據：[Meta Link 開發與 OpenXR Runtime](https://developers.meta.com/vr/documentation/unity/unity-link/)、[Unity Quest Link 與控制器設定](https://docs.unity.cn/Packages/com.unity.xr.meta-openxr@2.1/manual/get-started/link.html)。

## 2. 追蹤保護、校正及活動圈

先確認 QuestLab 的頭、AimOrigin、Tip 沿用 U3 欄位；不掛第二套 Rig。

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 取得新版 `Scripts/Tutorial/ExhibitGuard.cs`（[相同範例](../範例程式/X1/ExhibitGuard.cs)） | QuestLab 的 DesktopLab 只掛一份；桌面 CaptureLab 不掛。 |
| 2 | Guard 的 **Lab** 拖 DesktopLab；**Origin** 拖 XR Origin 根物件；**Tracking Space** 拖 Camera Offset；**Look** 拖 Right Stick Look | Origin 負責校正，Tracking Space 負責原始實體座標；兩個欄位不可混用。XR Origin Scale 保持 1。 |
| 3 | 實際地面標中心與起始朝向；直徑 3 m，外圍至少 0.5 m 淨空 | 線材走圈外；真實可用位置先確認。 |
| 4 | 進 Play，觀眾站中心、面向起始方向，工作人員按 Calibrate at physical centre | 先把額外俯仰歸零；Ready 時把頭部水平位置對齊 Exit Anchor 或預設原點，朝向 +Z。用 Camera Offset 原始追蹤座標保存實體中心，保留實際身高。 |
| 5 | 檢查起點兼結尾區在長街左端、回收站在右端。搖桿平移、左右轉身及上下俯仰後測量真實活動區 | 同一實體位置的半徑不變；只有真實走動計入邊界。 |
| 6 | Guard 顯示 Ready，按 Resume，再開始 | 校正／有效頭手／配戴／焦點都符合才繼續。 |
| 7 | 測摘頭戴、開系統選單、遮住控制器、拔掉 Link | 暫停；Mask 收起，不計時、不新增群落；影片／演出保留。 |
| 8 | 恢復追蹤後由工作人員核對，再按 Resume，右搖桿先回中 | 不自動跳過教學或清掉捕捉進度，也不沿用暫停前持續撥動的人工轉向。 |
| 9 | 按 Quest 重新置中 | 清到站資格並要求重新校正；回收資格不能沿用舊座標。 |
| 10 | 模擬接近 1.2 m 半徑及超出 1.5 m | 先提示邊界；超出暫停，回圈內後人工恢復。 |

- Guard 查頭／雙手的有效追蹤、配戴資訊、XR 顯示與頭戴焦點；Runtime 缺少必要資訊時維持未就緒，記錄後修支援。
- 焦點以 OpenXR 1.16.1 的 `OpenXRUtility.IsSessionFocused` 取得目前狀態，不以工作人員桌面視窗焦點代替。XR 顯示／輸入子系統更換時重新校正。
- 開啟 Run In Background 後，工作人員切換管理頁不以桌面視窗失焦暫停；頭戴 XR 焦點遺失仍暫停。這項差異須實機驗證。
- 首次開場前仍需工作人員確認 Quest 系統安全邊界；此圓圈保護不取代系統邊界。
- 校正保留遊戲資料，只清瞄準／到站資格；換頭戴或重設 Runtime 後重新校正。

### 效能測試操作

| 步驟 | 做法 | 觀察／記錄 |
| --- | --- | --- |
| 1 | QuestLink Build 勾 Development Build／Autoconnect Profiler，關 Deep Profiling | 避免額外量測負擔。 |
| 2 | Window → Analysis → Profiler，Target 選該 Player | 看 CPU、GPU（可用時）、Audio、Memory。 |
| 3 | 在 Link 固定一組刷新率／解析度，例如先測 72 Hz | 72 Hz 每幀預算約 13.9 ms；記錄真正設定，不只看桌面 FPS。 |
| 4 | 分別測晴天 3 群、雨天 4 群、透明特效、UI 及修復最重組合。另測左右眼黑幕，以及左手是否能點開信封 | 記雙眼體驗、CPU／GPU／音訊耗時及記憶體趨勢。 |
| 5 | 超預算先用 Profiler 找瓶頸 | 分別調粒子／透明重疊、陰影／光源、模型與音訊負擔，再以相同條件重測。 |

### 發聲顯現驗收（後續規劃，本階段先不做）

1. 依 [U2 第 8 節](U2.md#8-windows-aecvad-導入x1-協助)建置並在測試用 QuestLab 接外掛。確認 Windows 音訊選 Quest Link 的輸出與麥克風，喇叭保持正常展出音量。
2. 每項至少試 10 次。依序測只播放遊戲音訊、只發聲、邊播邊發聲、持續說話後停聲再說。記誤觸發、漏判和觸發時間。
3. 暫停、摘頭戴、切換裝置再恢復。確認無新音訊時停止發聲顯現，取得有效收音並停聲後才重新就緒，捕捉進度仍接續。
4. 在同一條街比較屋外、門口與室內的發聲回應。核對前方角度、距離與遮擋，再把實測結果與未定參數填到[驗證清單](../../待確認與驗證清單.md)。

## 3. Quest 借到後先做的測試

| 順序 | 小測試 | 記錄 |
| --- | --- | --- |
| 1 | 借用線材／Link USB Test，最小場景及頭手輸入 | 接口、傳輸結果、Link／頭戴／驅動版本。 |
| 2 | 先用單聲源轉頭，再用 3／4 群循聲；分別測屋外、門口與室內 | 記錄左右／前後／高度辨認、多群混音、屋內外音量差與疲勞。 |

| 4 | 左搖桿移動、右搖桿左右轉身／上下俯仰／按下回正、右手捕捉、UI 選取與震動 | 對準穩定、介面可讀，暫停／失效停止人工轉向，恢復先回中。 |

### 修復後返回起點

| 操作 | 預期 |
| --- | --- |
| 完成修復，轉頭並離開回收站 | 返回起點語音清楚、只播放一次，不受距離影響。 |
| 90 秒內回起點、留在街尾等 90 秒各測一次 | 兩者都只進結尾一次；超時原地淡黑，不瞬移或重新結算。 |

| Ready／Active 時經過起點 | 不觸發結尾；Exit Anchor 與起點校正位置相同。 |

## 4. CaptureLab 有新內容時，更新 QuestLab

**自動接線工具：** 停止 Play、保存自己的修改，再選 **Tools → AudioBugs → Refresh QuestLab From CaptureLab**。確認覆寫後，工具會用已保存的 CaptureLab 重建 QuestLab、保留 QuestLab 的 GUID、停用 Simulator，並重接 Right Stick Look／Exhibit Guard。Console 應出現 `QUEST_LOOK_VALIDATED`；這是編譯／接線／座標驗證，不是 Quest 實測通過。

已有只存在 QuestLab 的自訂內容時，先另存備份並核對，再執行覆寫。工具不修改 CaptureLab 或專案的 XR 啟動設定。

- **CaptureLab** 是 U2／U3 持續開發、整合美術與遊戲功能的主場景。目前仍在建置，後續完成的內容也放在這裡。
- **QuestLab** 是從某次 CaptureLab 複製出的頭戴測試版本。複製後，CaptureLab 新增的場景物件、位置與欄位接線需要同步過來；兩個場景共用的腳本與 Prefab 資產修改則會一起生效。
- **現在**先用已建立的 QuestLab 確認頭戴和手把。**之後 CaptureLab 有新的整合成果，或準備正式驗收／打包時**，依本節步驟更新 QuestLab。

### CaptureLab 更新後，同步 QuestLab

**用途：把最新版 CaptureLab 另存成 QuestLab。這會覆蓋舊 QuestLab 的場景內容，Quest 專用設定要重新套用。**

1. **先保存目前的 QuestLab**：停止 **Play**，開啟 `QuestLab`，按 **Ctrl+S**。在 VS Code 的 **Source Control** 提交這次的場景修改，之後需要時可找回舊版。
2. **只有做過本頁第 2 節的人才要做**：在 **Hierarchy** 點 `DesktopLab`，找到 **Inspector** 的 `Exhibit Guard` 元件，把其中已填好的欄位截圖。後面覆寫 QuestLab 後，要依這張圖重新填回。還沒做第 2 節就直接跳過。
3. **取得最新內容**：依[一般開發](../環境與Git.md#一般開發)把最新 `main` 合併進自己的功能分支。
4. **開啟來源場景**：在 **Project → Assets → _Project → Scenes** 雙擊 `CaptureLab`，確認 Unity 上方場景名稱是 **CaptureLab**。
5. **另存並覆寫**：按 **File → Save As…**，選 `Assets/_Project/Scenes/QuestLab.unity`，按 **Save**，出現覆寫詢問時確認。完成後，上方場景名稱應變成 **QuestLab**。
6. **套用頭戴設定**：在 **Hierarchy** 選 `XR Interaction Simulator`，取消 **Inspector 最上方物件名稱左側**的勾選。確認 **XR Origin (XR Rig)**、Right Stick Look 仍啟用；DesktopLab 的 **Tracked Head／Tracked Aim／Tracked Tip／XR Move Provider／Xr Look Provider** 都有引用。
7. **補回專用元件**：依本頁第 2 節重新掛上 ExhibitGuard，接 **Lab／Origin／Tracking Space／Look**。其他只存在舊 QuestLab 的設定也依截圖補回，再按 **Ctrl+S**；不要以缺少 Guard 的版本驗收暫停／追蹤失效行為。
8. **重測**：保持 Quest Link 連線，在 **QuestLab** 按 **Play → Calibrate → Resume／P → 開始**，確認頭手與本頁的右手視角測試表，記下測試版本與結果。

## 5. 需要獨立執行時才打包

### Windows 桌面版

由 Windows 電腦操作；Mac 成員可先在 Editor 跑相同場景，Windows 打包由該包主責一起整合。

| 步驟 | 在哪裡 | 操作／預期 |
| --- | --- | --- |
| 1 | Project 雙擊 CaptureLab | 確認是 U3 跑通的場景。打包前依 [I1 第 3～4 節](I1.md#3-unity-掛上傳送元件)接好 Probe 並儲存 Scene。 |
| 2 | File → Build Profiles | Add Build Profile → Windows → Add／Switch，命名 DesktopSimulation。 |
| 3 | Scene List | Add Open Scenes，保留 CaptureLab 勾選；移除未使用的預設 SampleScene。不需要找尚未建立的 Bootstrap。 |
| 4 | Player Settings → Other Settings | 第一版 Scripting Backend 用 Mono、Architecture x86_64；Run In Background 開。 |
| 5 | Project Settings → XR Plug-in Management | 桌面模擬先關 Initialize XR on Startup；模擬輸入由場景內 Simulator 提供。 |
| 6 | CaptureLab Hierarchy | 保留一份啟用的 XR Interaction Simulator，不能只依賴 Editor 自動建立。 |
| 7 | Build Profiles | 勾 Development Build → Build，選 `unity-vr/Builds/DesktopSimulation/`。 |
| 8 | 檔案總管 | 關閉 Editor Play，再開輸出的 `.exe`；相鄰 `_Data` 等檔案不要拆開。 |
| 9 | 執行檔 | 啟動 Gateway、開執行檔，跑到 Ending，按 Send result，確認 `RESULT_SAVED` 並核對成果數量與本場實收一致。 |
| 10 | 記錄 | 版本、啟動方式、Player.log 位置、Gateway 啟動方式與未通過項目。 |

### 之後輸出 Quest Link 執行檔

1. 先依第 4 節同步最新 CaptureLab 到 QuestLab，並完成 Editor 測試。在 **File → Build Profiles → Windows → Scene List** 使用這份 `QuestLab`，確認整個 Simulator 物件已停用。
2. 確認 Windows OpenXR 和 **Initialize XR on Startup** 已啟用，輸出到 `unity-vr/Builds/QuestLink/`。
3. 保持 Quest Link 連線，關閉 Editor 的 Play，開啟輸出的 `.exe`，重測頭手、操作與單場流程。
