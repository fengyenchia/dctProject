## 1. 先做 Windows 桌面執行檔

由 Windows 電腦操作；Mac 成員可先在 Editor 跑相同場景，Windows 打包由該包主責一起整合。

| 步驟 | 在哪裡 | 操作／預期 |
| --- | --- | --- |
| 1 | Project 雙擊 XrLab | 確認就是U3跑通的場景。 |
| 2 | File → Build Profiles | Add Build Profile → Windows → Add／Switch，命名 DesktopSimulation。 |
| 3 | Scene List | Add Open Scenes，保留 XrLab 勾選；移除未使用的預設 SampleScene。不需要找尚未建立的 Bootstrap。 |
| 4 | Player Settings → Other Settings | 第一版 Scripting Backend 用 Mono、Architecture x86_64；Run In Background 開。 |
| 5 | Project Settings → XR Plug-in Management | 桌面模擬先關 Initialize XR on Startup；模擬輸入由場景內 Simulator 提供。 |
| 6 | XrLab Hierarchy | 保留一份啟用的 XR Interaction Simulator，不能只依賴 Editor 自動建立。 |
| 7 | Build Profiles | 勾 Development Build → Build，選 `unity-vr/Builds/DesktopSimulation/`。 |
| 8 | 檔案總管 | 關閉 Editor Play，再開輸出的 `.exe`；相鄰 `_Data` 等檔案不要拆開。 |
| 9 | 執行檔 | 從開場跑到回收／成果保存；不能只測視窗有出現。 |
| 10 | 記錄 | 版本、啟動方式、Player.log 位置、Gateway 啟動方式與未通過項目。 |

### 切到 Quest Link 時再做

1. 將 XrLab 複製為 QuestLab，**停用其中的 Simulator**，保留同一套規則與頭手參照。
2. Windows 裝好 Meta Horizon Link，用現有 USB 線連 Quest；Devices → 選頭戴 → USB Test → Test Connection，記錄結果。
3. Link → Settings → General → OpenXR Runtime，選 **Set Meta Horizon Link as active**；在頭戴啟動 Quest Link。更改後重新開啟 Unity。
4. Project Settings → XR Plug-in Management：Windows 啟用 OpenXR、Initialize XR on Startup；OpenXR → Interaction Profiles 加入 **Oculus Touch Controller Profile**，再修正 Project Validation 的必要項目；不新增第二個 Rig。
5. Build Profile 改用 QuestLab，輸出到另一個 QuestLink 資料夾；確認包內沒有啟用 Simulator。
6. Link、追蹤／XR 焦點、麥克風及效能按下一節實機驗收。

XR 啟動設定不會只因 Profile 名稱而自動切換；每次打包前依本表核對。沒借到頭戴不把 QuestLab 標為已通過。

設定依據：[Meta Link 開發與 OpenXR Runtime](https://developers.meta.com/vr/documentation/unity/unity-link/)、[Unity Quest Link 與控制器設定](https://docs.unity.cn/Packages/com.unity.xr.meta-openxr@2.1/manual/get-started/link.html)。

## 2. 追蹤保護、校正及活動圈

先確認 QuestLab 的頭、AimOrigin、Tip 沿用 U3 欄位；不掛第二套 Rig。

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 複製 [ExhibitGuard.cs](../範例程式/X1/ExhibitGuard.cs) 到 Scripts/Tutorial | 只掛 QuestLab 的 DesktopLab 物件；桌面 XrLab 不掛。 |
| 2 | Guard 的 Lab 拖 DesktopLab，Origin 拖 XR Origin 根物件 | 不拖 Camera Offset；XR Origin Scale 保持 1。 |
| 3 | 實際地面標中心與起始朝向；直徑 3 m，外圍至少 0.5 m 淨空 | 線材走圈外；真實可用位置先確認。 |
| 4 | 進 Play，觀眾站中心、面向起始方向，工作人員按 Calibrate at physical centre | 把頭部水平位置對齊世界原點，朝向 +Z；保留實際身高。 |
| 5 | 檢查後方站體在世界 (0,0.9,-0.65)，雙手與虛擬模型方向一致 | 不每幀將回收站移到觀眾背後。 |
| 6 | Guard 顯示 Ready，按 Resume，再開始 | 校正／有效頭手／配戴／焦點都符合才繼續。 |
| 7 | 測摘頭戴、開系統選單、遮住控制器、拔掉 Link | 暫停；Mask 收起，不計時、不新增群落；影片／演出保留。 |
| 8 | 恢復追蹤後由工作人員核對，再按 Resume | 不自動跳過教學或清掉捕捉進度。 |
| 9 | 按 Quest 重新置中 | 清到站資格並要求重新校正；回收資格不能沿用舊座標。 |
| 10 | 模擬接近 1.2 m 半徑及超出 1.5 m | 先提示邊界；超出暫停，回圈內後人工恢復。 |

- Guard 查頭／雙手的有效追蹤、配戴資訊、XR 顯示與頭戴焦點；Runtime 缺少必要資訊時維持未就緒，記錄後修支援。
- 開啟 Run In Background 後，工作人員切換管理頁不以桌面視窗失焦暫停；頭戴 XR 焦點遺失仍暫停。這項差異須實機驗證。
- 首次開場前仍需工作人員確認 Quest 系統安全邊界；此圓圈保護不取代系統邊界。
- 校正保留遊戲資料，只清瞄準／到站資格；換頭戴或重設 Runtime 後重新校正。

### 效能測試操作

| 步驟 | 做法 | 觀察／記錄 |
| --- | --- | --- |
| 1 | QuestLink Build 勾 Development Build／Autoconnect Profiler，關 Deep Profiling | 避免額外量測負擔。 |
| 2 | Windows→Analysis→Profiler，Target 選該 Player | 看 CPU、GPU（可用時）、Audio、Memory。 |
| 3 | 在 Link 固定一組刷新率／解析度，例如先測 72 Hz | 72 Hz 每幀預算約 13.9 ms；記錄真正設定，不只看桌面 FPS。 |
| 4 | 測 3 群、透明特效、UI、發聲及修復最重組合，連跑多場 | 記雙眼體驗、CPU／GPU／音訊耗時及記憶體趨勢。 |
| 5 | 超預算先用 Profiler 找瓶頸 | 分別調粒子／透明重疊、陰影／光源、模型與音訊負擔，再以相同條件重測。 |

## 3. Quest 借到後先做的測試

| 順序 | 小測試 | 記錄 |
| --- | --- | --- |
| 1 | 現有 USB 線／Link USB Test，最小場景及頭手輸入 | 接口、傳輸結果、Link／頭戴／驅動版本。 |
| 2 | 單聲源轉頭，再 3 聲源循聲 | 左右／前後／高度辨認、混音與疲勞。 |
| 3 | 只播遊戲聲、只說話、播放中說話 | AEC／VAD 誤觸發率、延遲及持續聲音只觸發一次。 |
| 4 | 左右手、UI 選取、捕捉與震動 | 對準穩定、介面可讀、操作不中斷。 |
| 5 | 活動區、轉身回收、線材、暫停／恢復 | 圈內可及、失效不跳進度、重校正清到站資格。 |
| 6 | 最重場景連續跑多場 | CPU／GPU 時間、雙眼幀率、顯存、錯誤與電量趨勢。 |

實測結果填回[待確認與驗證清單](../../待確認與驗證清單.md)所對應測試；未通過先修，不用增加新的遊戲規則繞開問題。
