# W1｜成果總覽與個人成果網頁

[分段排程與整合期限](../02_里程碑與美術期限.md)

| 開始日期 | 初版完成日期 |
| --- | --- |
| **2026/12/29** | **2027/1/7** |

初版驗收：home／results／about 三個入口、卡片總覽、個人成果頁與樣本聲部播放可用；成果 QR／旋律回放於 2027/1/26 前整合；正式網站依 3/15～4/15 排程。頁面展示內容另由團隊定稿，先用佔位元件。

分支：`web/souvenir`；`web/admin` 留作後續選配。開工前依[網頁／Gateway 環境](../共用/網頁開發慣例.md)準備 Node.js 24 LTS、pnpm 11.9.0。

第 1～3 節先用樣本，不必等待 Quest 或 I1。第 4 節接雲端，第 5 節的管理頁先不做、保留來源；票面與列印由 [I2](I2.md)接續。

## 網站入口

| 路徑 | 功能 |
| --- | --- |
| `/`（home） | 首頁，呈現主視覺與作品入口。 |
| `/results` | 所有已上傳成果的卡片總覽；點卡片進入該份成果，每頁 12 張。 |
| `/results/<token>` | 紙票 QR 直接開啟該份個人成果；可前往總覽，再看其他人的成果。 |
| `/about` | 團隊介紹；收到正式資料後替換佔位內容。 |
| `/display` | 前導影片播放頁；導覽先保留 Display 入口，影片後續交付。 |
| `/api/results?page=1` | 唯讀卡片清單，不提供遊戲操作。 |
| `/api/results/<token>` | 讀取同一份固定成果，重新整理不換配方。 |

- 觀眾不需登入；個人成果也會出現在公開總覽，token 是唯讀網址識別，不是私密保護。
- 正式卡片與個人頁要顯示哪些內容，見[討論清單](../../待確認與驗證清單.md)。範例收藏圖、文字與播放器可替換，不作定稿。
- 總覽卡片只顯示一張封面與成果編號（result_id），不列音虫名稱或文字按鈕；整張卡片仍可點入個人頁。封面先用該份成果第一個變體的圖片，缺圖只顯示圖示。
- 兩套設備輪替、一次一套／一位觀眾；網站彙整各場成果，不建立雙人或雙場同步系統。

## 完成條件

- [ ] 導覽可切換首頁主視覺、成果總覽、團隊介紹；每張卡片開對應個人成果。
- [ ] 紙票 QR 直接進自己的 `/results/<token>`；個人頁可到總覽並開其他人的成果。
- [ ] 範例先顯示收藏、暫用文字及播放器；正式展示項目與版面由團隊定稿後替換。
- [ ] 重開連結仍是相同配方／素材。
- [ ] 總覽只列已上傳成果；空清單、載入失敗、分頁與無效個人連結有對應畫面。
- [ ] 將固定成果 API 與網址交 I2 串接。

範例有 1／3／5 群三筆獨立成果，供卡片與個人頁測試。若保留感謝信，正式稿需與 U3 共用同一版文字。

## 1. 建立一次網頁專案

repo 已有 `web/package.json` 時，先在 web 執行 `pnpm install --frozen-lockfile`，沿用既有 UI 元件與設定；不重建專案。

套件管理使用 **pnpm 11.9.0**。僅第一次建置者在 **repo 根目錄**執行：

```text
pnpm create next-app@16 web --use-pnpm --disable-git
```

| 選項 | 選擇 |
| --- | --- |
| 自訂設定 | TypeScript、ESLint、Tailwind、App Router：Yes。 |
| `src/` 目錄 | No，沿用組內目錄慣例。 |
| React Compiler／Cache Components | 原型先不加，降低入門設定量。 |
| alias | `@/*`。 |

建立後開啟 `web/next.config.ts`，確認以下設定；已有欄位就改原值，其餘設定保留。範例使用 `force-dynamic`，不搭配 Cache Components。

```ts
cacheComponents: false,
partialPrefetching: false,
```

建立後，進入 **repo/web** 再執行：

```text
cd web
pnpm add server-only @neondatabase/serverless
pnpm add @radix-ui/react-slot @radix-ui/react-avatar @radix-ui/react-dialog class-variance-authority clsx tailwind-merge @tabler/icons-react axios motion
pnpm add -D typescript@5.9.3 @tailwindcss/postcss@4.3.3
pnpm dev
```

- 開 `http://localhost:3000`；完成下一節後顯示首頁主視覺佔位與三頁導覽。
- 在 `web/package.json` 設定 `"packageManager": "pnpm@11.9.0"`；已有此欄位就修改原值，只保留一個。
- Tailwind 沿用 repo 的 `web/postcss.config.mjs`（`@tailwindcss/postcss`）；不用 `@tailwindcss/turbopack` 自訂 loader，避免樣式更新仍顯示舊版。
- 提交 `web/package.json`、`web/pnpm-lock.yaml`；同一 web 只保留 pnpm 的 lockfile。
- 目錄及後續 UI／API 套件依[網頁開發慣例](../共用/網頁開發慣例.md)取用；本章先用 Tailwind 與附帶元件完成串接。

其他組員拉取後，從 repo 根目錄執行：

```text
cd web
pnpm install --frozen-lockfile
pnpm dev
```

日常啟動同樣先確認終端機在 web；若留在 repo 根目錄，可直接用 `pnpm --dir web dev`。Unity／Gateway 各用自己的入口。

## 3. 音樂及真實 Unity 結果

### 3.1 先用測試聲部

1. 複製 [make-test-stems.mjs](../範例程式/W1/make-test-stems.mjs) 到 `web/tools/`。
2. 在 **web 終端機**執行：

```text
node tools/make-test-stems.mjs
```

3. 應產生 `public/assets/prototype-2/stems/` 的八個 WAV；這是合成佔位音色。
4. 回成果頁按播放，再暫停／續播；所有本場聲部使用同一起點，不個別播放。

此工具不覆蓋已存在素材；已有正式檔案時不需執行。正式配樂另以新素材版本交付，避免改掉舊成果。

### 3.2 接I1的成果

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 保持 Gateway 啟動 | `127.0.0.1:8788/health` 正常。 |
| 2 | 在 web 建 `.env.local` | 加入 `GATEWAY_HTTP_BASE=http://127.0.0.1:8788`。 |
| 3 | 重開 Next dev server | 環境變數生效；此值只供伺服器讀取。 |
| 4 | Unity 完整回收後 Send result，等待 RESULT_SAVED | 複製 Probe 的 token。 |
| 5 | 開 `http://localhost:3000/results/本場token` | 顯示實際抓到的變體及對應聲部。 |
| 6 | 重新整理、重啟 Gateway 再讀 | 同一份 SQLite 成果，組合不變。 |

這時只有個人頁由 Next 伺服器向 Gateway 讀取；本機 Gateway 未提供總覽清單。未接 Neon 的開發總覽仍標為樣本；接好下一節後，總覽才列出已上傳的真實成果。公開交付需完成雲端部署。

### 3.3 播放器已處理什麼

| 功能 | 做法 |
| --- | --- |
| 啟動 | 觀眾按播放，先啟用 AudioContext，再載入本場對應聲部。 |
| 同步 | 全部 decode 完成、核對長度後，以共同 `currentTime + 0.1` 起播。 |
| 暫停／續播 | suspend／resume 同一 AudioContext，維持共同時間軸。 |
| 離頁 | 取消載入、關閉音訊，避免重複播放。 |
| 缺音檔 | 顯示重試訊息，收集摘要仍可看。 |

| 錯誤 | 檢查 |
| --- | --- |
| Module not found | 檔案是否依表改名？路徑 alias 是否為 `@/*`？ |
| 找不到 `result-ready.example.json` | 將 I1 的 sample-result.json 複製到 `web/lib/fixtures/result-ready.example.json`；檔名也要改，見第 2 節。 |
| `Response.json` 型別不存在 | 在 web 執行 `pnpm add -D typescript@5.9.3`；提交更新後的 package.json 與 lockfile。 |
| `dynamic` 與 `cacheComponents` 不相容 | 將 next.config.ts 的 cacheComponents、partialPrefetching 設為 false，重啟 pnpm dev；保留範例的 force-dynamic。 |
| 缺少聲部素材 | WAV 路徑及 asset_version 是否一致？先跑測試聲部工具。 |
| 聲部長度不一致 | 正式聲部需共用 BPM、小節數、循環起點；不要用個別長度修補同步。 |
| 真實 token 查不到 | Gateway 是否仍啟動？Unity 是否收到 RESULT_SAVED？Next 是否重開載入 `.env.local`？ |

### 3.4 換上正式網頁素材

1. 在 `web/public/assets/<asset_version>/` 建新版本。把彩色收藏圖放 `images/<variant_id>.png`，把八個正式聲部放 `stems/stem-<variant_id>.wav`。檔名對應成果的 image_id 與 stem_id。
2. 用 [I1 成果格式](I1.md) 核對素材版本和聲部參數。W1、I2 都已備妥該版本後，Unity 再調整 VariantCatalog 的 Asset Version，讓新場次產出該版本。舊版資源保留給已發出的成果。
3. 首頁主視覺放 `web/public/images/`，在 `app/page.tsx` 換成圖片；`app/about/page.tsx` 接正式團隊資料。依團隊定稿調整 `ResultCard.tsx`、總覽及個人頁。若採感謝信，替換三段正文，同步對照 U3 的 Letter One／Two／Three。
4. 開一筆新成果，確認彩色圖與捕獲代號相符。播放、暫停及續播一次，確認聲部同步，再開一筆舊成果核對原素材。

## 4. 雲端 API：先本機接資料庫，再部署

| 教學來源 | 放到 web |


### 4.2 用真實結果測上傳

先完成 I1／I2。Gateway 的 .env 改以下值，再開 pnpm dev:delivery：

| Gateway 設定 | 本機測試值 |
| --- | --- |
| INGEST_URL | http://127.0.0.1:3000/api/ingest |
| INGEST_SECRET | 與 web 相同 |
| ALLOW_LOCAL_INGEST | 1；只用於回環測試。 |
| RESULTS_BASE_URL | http://localhost:3000/results；不要當正式票務網址。 |

| 測試 | 預期 |
| --- | --- |
| Unity 收集／回收→RESULT_SAVED | Gateway upload_status 由 pending 轉 uploaded；Neon 多一列。 |
| GET http://localhost:3000/api/results/本場token | 200，只有固定成果，不含密鑰或原始收音。 |
| 再送同 result／相同內容 | 列數不增加，回相同成功。 |
| 同 result 改內容後測上傳 | 409；不可覆蓋原成果。不要修改保留中的正式待交付檔。 |
| 停 Next，產生另一份結果，再重開 | I2 自動補傳；token 不變。 |
| 隨機錯 token | 404；頁面顯示尚未就緒或無效。 |
| 開 `/results` 與 `/api/results?page=1` | 顯示已上傳成果，最新在前；每張連結開同一筆個人成果。 |
| 建立超過 12 筆不同測試結果 | 可翻到下一頁；只回傳卡片資料，不帶 session、SAN、裝置狀態或管理密鑰。 |
| 雲端零筆／暫時無法查詢 | 分別顯示空清單／重試提示；API 失敗回 503，不顯示假成果。 |

### 4.3 部署 Vercel

| 步驟 | 操作 | 驗收 |
| --- | --- | --- |
| 1 | web 執行 pnpm exec tsc --noEmit、pnpm exec eslint .、pnpm build | 錯誤先修；不是只有 dev 能開。 |
| 2 | 提交 web 程式及 lockfile，Vercel Add New Project→選 repo | Root Directory 設 web；Framework 為 Next.js。 |
| 3 | Production 環境設 DATABASE_URL／INGEST_SECRET | ENABLE_LOCAL_ADMIN=0；不設定 Gateway key／工作人員密碼。 |
| 4 | Deploy，取得穩定 Production 網址 | /admin 與 /api/local 為 404。 |
| 5 | Gateway 改 RESULTS_BASE_URL=https://正式站/results、INGEST_URL=https://正式站/api/ingest、ALLOW_LOCAL_INGEST=0 | 不使用 Preview 網址印正式票。 |
| 6 | 產生新的測試結果與票，手機用行動網路掃票 | 直接進自己的成果頁；可回總覽開其他卡片，實收聲部同步播放。 |
| 7 | 停展場 Gateway，再重開手機成果 | 已發布資料仍由雲端提供。 |

- 舊票保留原網址；改設定不重製既有票。正式印票前先確認穩定網址。
- 同一 asset_version 的素材不可原地覆寫；舊圖與音檔保留。
- 圖放 public/assets/版本/images/<variant_id>.png，八個聲部沿用 stems/。
