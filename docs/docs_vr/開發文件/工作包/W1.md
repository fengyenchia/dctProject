## 1. 建立一次網頁專案

套件管理使用 **pnpm 11.8.0**。僅第一次建置者在 **repo 根目錄**執行：

```text
pnpm create next-app@16 web --use-pnpm --disable-git
```

| 選項 | 選擇 |
| --- | --- |
| 自訂設定 | TypeScript、ESLint、Tailwind、App Router：Yes。 |
| `src/` 目錄 | No，沿用組內目錄慣例。 |
| React Compiler／Cache Components | 原型先不加，降低入門設定量。 |
| alias | `@/*`。 |

建立後，進入 **repo/web** 再執行：

```text
cd web
pnpm add server-only @neondatabase/serverless
pnpm dev
```

- 開 `http://localhost:3000`；先完成一張成果頁，不先做完整網站導覽。
- 在 `web/package.json` 新增 `"packageManager": "pnpm@11.8.0"`，保留原有欄位。
- 提交 `web/package.json`、`web/pnpm-lock.yaml`；同一 web 不產生 npm／Yarn 的 lockfile。
- 目錄及後續 UI／API 套件依[網頁開發慣例](../共用/網頁開發慣例.md)取用；本章先用 Tailwind 與附帶元件完成串接。

其他組員拉取後，從 repo 根目錄執行：

```text
cd web
pnpm install --frozen-lockfile
pnpm dev
```

日常啟動同樣先確認終端機在 web；若留在 repo 根目錄，可直接用 `pnpm --dir web dev`。Unity／Gateway 各用自己的入口。

## 3. 音樂及真實 Unity 結果

### 3.1 先用測試聲部

1. 複製 [make-test-stems.mjs](../範例程式/W1/make-test-stems.mjs) 到 `web/tools/`。
2. 在 **web 終端機**執行：

```text
node tools/make-test-stems.mjs
```

3. 應產生 `public/assets/prototype-1/stems/` 的九個 WAV；這是合成佔位音色。
4. 回成果頁按播放，再暫停／續播；五個聲部使用同一起點，不個別播放。

此工具不覆蓋已存在素材；已有正式檔案時不需執行。正式配樂另以新素材版本交付，避免改掉舊成果。

### 3.2 接I1的成果

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 保持 Gateway 啟動 | `127.0.0.1:8788/health` 正常。 |
| 2 | 在 web 建 `.env.local` | 加入 `GATEWAY_HTTP_BASE=http://127.0.0.1:8788`。 |
| 3 | 重開 Next dev server | 環境變數生效；此值只供伺服器讀取。 |
| 4 | Unity 完整回收後 Send result，等待 RESULT_SAVED | 複製 Probe 的 token。 |
| 5 | 開 `http://localhost:3000/results/本場token` | 顯示真實抓到的五個變體及聲部。 |
| 6 | 重新整理、重啟 Gateway 再讀 | 同一份 SQLite 成果，組合不變。 |

這時成果由 Next 伺服器向本機 Gateway 讀取；還不是離場後可用的公開網址。公開交付需完成下一節的雲端部署。

### 3.3 播放器已處理什麼

| 功能 | 做法 |
| --- | --- |
| 啟動 | 觀眾按播放，先啟用 AudioContext，再載入五個聲部。 |
| 同步 | 全部 decode 完成、核對長度後，以共同 `currentTime + 0.1` 起播。 |
| 暫停／續播 | suspend／resume 同一 AudioContext，維持共同時間軸。 |
| 離頁 | 取消載入、關閉音訊，避免重複播放。 |
| 缺音檔 | 顯示重試訊息，收集摘要仍可看。 |

| 錯誤 | 檢查 |
| --- | --- |
| Module not found | 檔案是否依表改名？路徑 alias 是否為 `@/*`？ |
| 缺少聲部素材 | WAV 路徑及 asset_version 是否一致？先跑測試聲部工具。 |
| 聲部長度不一致 | 正式聲部需共用 BPM、小節數、循環起點；不要用個別長度修補同步。 |
| 真實 token 查不到 | Gateway 是否仍啟動？Unity 是否收到 RESULT_SAVED？Next 是否重開載入 `.env.local`？ |

## 4. 雲端 API：先本機接資料庫，再部署

### 4.1 建表與複製程式

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | Neon 建立原型專案；開 SQL Editor | 選原型資料庫，不使用正式資料測刪除。 |
| 2 | 貼 [cloud-schema.sql](../範例程式/W1/cloud-schema.sql) 全文→Run | 建立 results 表；result_id／session_id／token 唯一。 |
| 3 | Neon Connect 複製連線字串 | 填 web/.env.local 的 DATABASE_URL；保留 sslmode 等連線參數。 |
| 4 | 在 web 終端機產生密鑰：`node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` | 填 INGEST_SECRET；之後同值給 Gateway，不放 NEXT_PUBLIC_。 |
| 5 | 依下表放檔，重開 pnpm dev | Server 端查 Neon；不再優先讀本機 Gateway。 |

| 教學來源 | 放到 web |
| --- | --- |
| [cloud-results.ts](../範例程式/W1/cloud-results.ts) | lib/api/results/cloud.ts；第 2 節已放則更新。 |
| [ingest-route.ts](../範例程式/W1/ingest-route.ts) | app/api/ingest/route.ts |
| [results-route.ts](../範例程式/W1/results-route.ts) | app/api/results/[token]/route.ts |

.env.local：

```dotenv
DATABASE_URL=貼上Neon連線字串
INGEST_SECRET=貼上剛產生的密鑰
ENABLE_LOCAL_ADMIN=0
```

### 4.2 用真實結果測上傳

先完成 I1／I2。Gateway 的 .env 改以下值，再開 pnpm dev:delivery：

| Gateway 設定 | 本機測試值 |
| --- | --- |
| INGEST_URL | http://127.0.0.1:3000/api/ingest |
| INGEST_SECRET | 與 web 相同 |
| ALLOW_LOCAL_INGEST | 1；只用於回環測試。 |
| RESULTS_BASE_URL | http://localhost:3000/results；不要當正式票務網址。 |

| 測試 | 預期 |
| --- | --- |
| Unity 收集／回收→RESULT_SAVED | Gateway upload_status 由 pending 轉 uploaded；Neon 多一列。 |
| GET http://localhost:3000/api/results/本場token | 200，只有固定成果，不含密鑰或原始收音。 |
| 再送同 result／相同內容 | 列數不增加，回相同成功。 |
| 同 result 改內容後測上傳 | 409；不可覆蓋原成果。不要修改保留中的正式待交付檔。 |
| 停 Next，產生另一份結果，再重開 | I2 自動補傳；token 不變。 |
| 隨機錯 token | 404；頁面顯示尚未就緒或無效。 |

### 4.3 部署 Vercel

| 步驟 | 操作 | 驗收 |
| --- | --- | --- |
| 1 | web 執行 pnpm exec tsc --noEmit、pnpm exec eslint .、pnpm build | 錯誤先修；不是只有 dev 能開。 |
| 2 | 提交 web 程式及 lockfile，Vercel Add New Project→選 repo | Root Directory 設 web；Framework 為 Next.js。 |
| 3 | Production 環境設 DATABASE_URL／INGEST_SECRET | ENABLE_LOCAL_ADMIN=0；不設定 Gateway key／工作人員密碼。 |
| 4 | Deploy，取得穩定 Production 網址 | /admin 與 /api/local 為 404。 |
| 5 | Gateway 改 RESULTS_BASE_URL=https://正式站/results、INGEST_URL=https://正式站/api/ingest、ALLOW_LOCAL_INGEST=0 | 不使用 Preview 網址印正式票。 |
| 6 | 產生新的測試結果與票，手機用行動網路掃票 | 可重開同成果，五聲部同步播放。 |
| 7 | 停展場 Gateway，再重開手機成果 | 已發布資料仍由雲端提供。 |

### 5.1 放檔及設定

| 教學來源 | 放到 web |

| [local-admin-route.ts](../範例程式/W1/local-admin-route.ts) | app/api/local/route.ts |

本機 web/.env.local 增加；雲端部署維持 ENABLE_LOCAL_ADMIN=0：

```dotenv
ENABLE_LOCAL_ADMIN=1
LOCAL_ADMIN_PASSWORD=使用前述指令另產生一組至少24字元的密碼
GATEWAY_KEY_FILE=C:/dctProject/gateway/data/gateway-key.txt
```

Mac 改成自己 clone 位置的**絕對路徑**。管理頁不讀取瀏覽器檔案，也不把 Gateway key 傳到手機。

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 先依 I1 啟動 Gateway、Unity；本機 Next 改 `pnpm dev --hostname 127.0.0.1` | 網址統一 http://127.0.0.1:3000。 |
| 2 | 開 /admin，輸入 LOCAL_ADMIN_PASSWORD，按連線 | 顯示目前場次及 Unity 回傳快照。 |
| 3 | 按 PAUSE／RESUME | 先 pending，再核對 acknowledged 的 accepted 及最新 paused；不自行假定成功。 |
| 4 | Ready 按 SESSION_START | Unity 核對階段與追蹤後進 Intro。 |
| 5 | Quest 版按 CALIBRATE | 依 X1 校正；桌面不用校正按鈕。 |
| 6 | 未交票按 RESET | Unity 拒絕；I2 確認交票後才接受。 |
| 7 | 活動中按 ABORT，確認 | 存故障紀錄、回 Ready，不產成功成果；Ending 不接受中止代替交票。 |
| 8 | PRINT_MODE=windows 且 I2 啟用時，核對出紙後按補印／已交票 | 只處理對應 result_id；不是重新捕捉或重新結算。 |
| 9 | 將前導 mp4 放 public/videos/prelude.mp4，開 /display | 工作人員先按播放，可全螢幕循環；不顯示成果 QR。 |

管理路徑：**瀏覽器→本機 Next HTTP→Gateway→既有 WebSocket→Unity**；狀態每 1.5 秒更新。只有 Unity 能變更遊戲規則。
