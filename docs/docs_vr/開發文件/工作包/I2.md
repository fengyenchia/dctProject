# I2｜紀念品交付與重置

**初版交付日：2026/12/20**｜[排程與整合期限](../02_里程碑與美術期限.md)

初版驗收：票面／QR、背景補傳、模擬交票與下一場重置跑通；實體出紙另驗證。

分支：`gateway/upload`、`gateway/print`、`unity/session-reset`。

前置：[I1](I1.md)能收到 RESULT_SAVED。先完成本機測試，再接 W1 正式網址及借用印表機。

| 順序 | 本頁完成什麼 |
| --- | --- |
| 1 | 產生本場 5 變體組合圖、清單、真正 QR 的 PNG／SVG。 |
| 2 | 測背景上傳、斷線重試與固定成果重送。 |
| 3 | 確認交票後，才讓 Unity 開下一場。 |
| 4 | 借到印表機後接 Windows 驅動送印與人工出紙確認。 |

## 2. 本機測試設定

範例 .env 已填好：

| 設定 | 用途 |
| --- | --- |
| DELIVERY_ENABLED=1 | 在原 Gateway 啟用 I2。 |
| RESULTS_BASE_URL=http://localhost:3000/results | QR 的成果網址前綴，後面自動接本場 token。 |
| INGEST_URL=http://127.0.0.1:9190/ingest | 本機測試接收器，不是已部署的雲端。 |
| INGEST_SECRET | 兩端共用驗證值，先沿用範例測試值。 |
| ALLOW_LOCAL_INGEST=1 | 允許回環 HTTP 測試；正式服務使用 HTTPS。 |
| PRINT_MODE=file | 只產生檔案，不送印。 |
| REQUIRE_TICKET_ART=0 | 缺圖時用標有 PROTOTYPE 的幾何測試圖。 |

localhost 只供這台電腦測試；手機離場成果須用 W1 正式 HTTPS 網址。網址設定好再產票；改設定不會重製既有票面。

## 3. 啟動

兩個終端機都先 `cd gateway`：

| 終端機 | 指令 | 預期 |
| --- | --- | --- |
| A | `pnpm mock-cloud` | Prototype upload receiver，連接埠 9190。 |
| B | `pnpm dev:delivery` | 8787／8788 啟動，加上 I2 delivery enabled。 |

原本 I1 的 pnpm dev 若還在跑，先 Ctrl+C；同時只開一份 Gateway。CLI 查詢另開第三個終端機。

## 4. 完成一場，查看票面

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | Unity 完成收集、回收、修復 | 進 Ending。 |
| 2 | Probe 按 Connect Gateway、Send same result / retry | 收到 RESULT_SAVED。 |
| 3 | 第三個 gateway 終端機執行 `pnpm delivery list` | 找到本場 result_id；票面完成後 ticket_ready=true。 |
| 4 | 複製 png_file 路徑，在檔案總管／Finder 開啟 | 5 個變體、聲音清單、QR。 |
| 5 | 再送相同成果、再開同一 PNG | 沿用原圖，不新增第二份自動列印工作。 |

檔案保存於 `gateway/data/tickets/<本場資料夾>/ticket.png`、ticket.svg；資料夾名稱是結果雜湊，不是控制器編號。

正式黑白圖放 `gateway/assets/<asset_version>/ticket/A1.png`～`C3.png`。正式交付設 REQUIRE_TICKET_ART=1，缺圖就停止產票。

## 5. 沒印表機時：模擬交票

將下方 RESULT_ID 換成本場值，由 Probe 的 Copy result id 或 pnpm delivery list 取得：

```text
pnpm delivery status RESULT_ID
pnpm delivery handoff RESULT_ID --simulate
```

- 票面已產生、PRINT_MODE=file 才能模擬。
- 回傳 delivered=true、delivery_mode=simulated；不算實體出紙通過。
- 重複確認不新增第二筆交票紀錄。

## 7. 斷網重試與正式上傳

| 操作 | 預期 |
| --- | --- |
| 停 mock-cloud，再完成一場 | 仍可產票及確認交付；upload_status=pending。 |
| 重開 mock-cloud | 到重試時間後 uploaded，不重製結果或票面。 |
| 刻意填錯驗證值後重開 Gateway | 401 會 blocked，不持續自動重送。 |
| 修正設定、重開 Gateway，再執行下方命令 | 同一結果重新嘗試，不換 token。 |

```text
pnpm delivery retry-upload RESULT_ID
```

接 [W1 第 4 節正式 API](W1.md)時，RESULTS_BASE_URL 換 Production 成果前綴；INGEST_URL 換 HTTPS 網址；兩端設定相同 INGEST_SECRET；ALLOW_LOCAL_INGEST 改 0。

| 上傳契約 | 內容 |
| --- | --- |
| 請求 | POST、Authorization Bearer；JSON 為 `{schema_version:1, session_id, payload}`，payload 是固定成果。 |
| 成功 | 回 `{result_id, status:"saved"}`；重送相同內容也回同一份成功。 |
| 暫時失敗 | 網路、5xx、408／429：保存次數及下次時間，退避重試。 |
| 固定錯誤 | 其餘 4xx 或回執不符：blocked，修正後人工重試。 |

## 8. 借到印表機後再做

Windows 送印範例使用驅動；紙長、可印寬與自動裁刀須用借用機實測。

| 步驟 | 操作 |
| --- | --- |
| 1 | 安裝借用機 Windows 驅動、USB 連接，先印 Windows 測試頁。 |
| 2 | PowerShell 執行 Get-Printer，複製正確 Name。 |
| 3 | .env 設 PRINT_MODE=windows、PRINTER_NAME=完整名稱；核對 pnpm delivery list 的待印工作。 |
| 4 | 重開 pnpm dev:delivery；待印工作會自動送到 Windows 列印系統。 |
| 5 | 檢查完整出紙與裁切；sent_to_spool 不代表觀眾已取票。 |
| 6 | 確實交票後執行 --printed 確認；Unity 取消 Allow Simulated Delivery。 |

```text
pnpm delivery handoff RESULT_ID --printed
```

缺紙／卡紙／USB 中斷或狀態不明時，先核對實際出紙；修復後才人工補印：

```text
pnpm delivery reprint RESULT_ID
```

自動送印每份結果一次；不明狀態記 unknown，不自動多印。補印另記 print_attempts，沿用原圖與 QR。

## 9. 本包驗收

| 測試 | 通過條件 |
| --- | --- |
| 票面／QR | 5 變體與清單對上，QR 解碼為本場固定網址。 |
| 重送／重啟 | 原票面與 token 保留，不新增第二份自動工作；交票紀錄保留。 |
| 上傳失敗 | pending／blocked 可辨認；修正後同結果補傳。 |
| 重置 | 保存、Ending、交票缺一項就不能按；上傳未完成仍可正常重置。 |
| 下一場 | SAN 100、收藏 0、新識別；開場／修復可再播，舊成果保留。 |
| 實體列印 | 另用借用機驗證；模擬交票不算出紙通過。 |
