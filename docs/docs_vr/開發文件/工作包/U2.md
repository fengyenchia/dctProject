# U2｜場景、Mask、顯現與聲音

**初版交付日：2026/11/29**｜[排程與整合期限](../02_里程碑與美術期限.md)

初版驗收：桌面場景／Prefab、Mask、顯現、捕捉音量與麥克風預覽可測；AEC 效果另驗證。

分支：`unity/mask-audio`。前置：[U0](U0.md)完成，先依 [U1](U1.md)跑過起步操作。停止 Play 後再修改。

本包處理 Prefab、Shader、來源聲音與桌面收音範例；第 8 節提供 Windows AEC／VAD 導入範例，仍需編譯與實機驗證，規格見[聲音處理](../../開發規格.md#6-聲音到站授權與回收確認)。

## 1. 把球體換成可重用 Prefab

| 步驟 | 操作 | 填值／結果 |
| --- | --- | --- |
| 1 | 複製 CaptureLab 場景，改名 `PresentationLab`，雙擊開啟 | 不直接改原練習場景。 |
| 2 | Hierarchy 建空物件 `BugGroup`，Transform Reset | 根物件 Scale 1。 |
| 3 | BugGroup 下建 Sphere，命名 `Visual` | Local Position 0、Rotation 0、Scale 0.7。 |
| 4 | 選 Visual → Sphere Collider 右上選單 → Remove Component | 碰撞改由群落根物件負責。 |
| 5 | 選 BugGroup → Add Component → BugView | 自動出現 Box Collider、AudioSource。 |
| 6 | BugView 的 Visual 欄位拖入 Visual 子物件 | Base Volume 0.12；Use Prototype Material 勾選。 |
| 7 | 根物件 Box Collider 勾 Is Trigger | Center 0；Size X 1.2、Y 0.8、Z 1.2。 |
| 8 | 將 BugGroup 從 Hierarchy 拖到 `Prefabs/Bugs/` | 產生藍色圖示的 BugGroup.prefab。 |
| 9 | 刪除 Hierarchy 裡這個樣本 BugGroup | 避免多出一隻未受規則管理的模型。 |
| 10 | 選 DesktopLab → Group Prefab 拖入 Project 的 BugGroup | Play 後由系統建立最多 3 群。 |

**檢查：**抓到一群後新群仍使用此 Prefab；更改 Prefab 的 Visual 模型，不需重寫捕捉規則。

Visual 保持啟用，由材質透明度隱藏；不要取消物件勾選。

## 2. 自己擺六個候選位置

1. Hierarchy 建空物件 `SpawnPoints`，Transform Reset。
2. 在其下建立 P0～P5 六個空物件，依下表填 **Local Position**。
3. 選 DesktopLab → Spawn Points 展開，Size 改 6。
4. 依序把 Hierarchy 的 P0～P5 拖入 Element 0～5。
5. Create Lab Geometry 先維持勾選；此時仍使用原本地面與牆。

| 物件 | X | Y | Z |
| --- | --- | --- | --- |
| P0 | 2 | 1.3 | 3.46 |
| P1 | 4 | 1.3 | 0 |
| P2 | 2 | 1.3 | -3.46 |
| P3 | -2 | 1.3 | -3.46 |
| P4 | -4 | 1.3 | 0 |
| P5 | -2 | 1.3 | 3.46 |

六個是候選區，**不是六群同時存在**；遊戲仍同時最多 3 群。欄位未填滿會報錯，先補齊再 Play。

## 3. 換成九個來源聲音

1. 將音檔放 `Assets/_Project/Audio/Sources/`。
2. 選每個音檔 → Inspector：定位用音檔勾 Force To Mono → Apply。
3. 選 DesktopLab → Source Clips，Size 9，依下表拖入。
4. Play 後點一個執行中的 Bug 物件，查看 AudioSource：Loop 開、Spatial Blend 1。
5. 對準一部分後移開，查看 AudioSource Volume 是否保留；再對準繼續降低。

| 陣列位置 | 變體 | 陣列位置 | 變體 | 陣列位置 | 變體 |
| --- | --- | --- | --- | --- | --- |
| 0 | A1 | 3 | B1 | 6 | C1 |
| 1 | A2 | 4 | B2 | 7 | C2 |
| 2 | A3 | 5 | B3 | 8 | C3 |

缺少音檔的欄位暫用測試音色。來源聲音與紀念旋律聲部是不同素材，不能把同一個音檔誤當兩者已交付。

## 4. 檢查 Mask 與遮擋

| 操作 | 預期 |
| --- | --- |
| 看向沒有音虫的牆面 | 圓形 Mask 仍沿牆面移動；不增加捕捉進度。 |
| 看向沒有命中的方向 | Mask 收起。 |
| 勾 DesktopLab 的 UI Busy | Mask 收起、停止累積；取消後重新查詢，不清舊進度。 |
| 勾 Pause lab | 進度、顯現及音量保留。 |

遮擋測試：

1. 停止 Play，建 Cube `Occluder`。
2. 世界 Position 設 `(1, 1.3, 2)`、Rotation Y `30`、Scale `(1.5, 2, 0.2)`。
3. 保留 Cube 的 Box Collider。
4. Play：對準擋板後方的目標，不得穿牆捕捉；拿開擋板再測。

這版 Mask 由腳本＋Shader 產生，不需手動建第二個光罩。之後換凹凸城市時，再依美術需求改為 URP 投射效果。

## 5. 發聲練習：先接電腦麥克風

此段是**桌面音量偵測範例，不含 AEC**；正式頭戴收音仍按驗證清單處理。

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 複製 [MicRevealPreview.cs](../範例程式/U2/MicRevealPreview.cs) 到 Scripts/Tutorial | 編譯無紅字。 |
| 2 | 在 DesktopLab 物件 Add Component → MicRevealPreview | Inspector 出現 Lab／Threshold。 |
| 3 | Lab 拖入同一個 DesktopLab 物件 | Device Index 0，先使用預設麥克風。 |
| 4 | Play，依系統提示允許 Unity 使用麥克風 | Console 顯示使用的麥克風名稱。 |
| 5 | 進 Active 後說話，觀察 RMS／Audio Ready | 音量足夠時，前方多群 3 秒淡入、1 秒淡出。 |
| 6 | 持續說話，再停一下、重新說 | 同段只觸發一次，停聲且冷卻後才再次觸發。 |

| 問題 | 修正 |
| --- | --- |
| 找不到麥克風 | Windows 設定→隱私權與安全性→麥克風；Mac 系統設定→隱私權與安全性→麥克風。 |
| RMS 說話時也很低 | 確認選對輸入裝置；依觀察結果調 Threshold，不用猜固定值適合所有機器。 |
| 遊戲聲音自己觸發 | 這個範例沒有 AEC；先暫停此元件並用 V 測規則，不能當成正式發聲完成。 |
| 沒有新音訊資料 | 不觸發，也不把缺資料當停聲；先修輸入。 |

## 6. 三個呈現值的接法

| 值 | 已由哪個檔案處理 | 核對方式 |
| --- | --- | --- |
| 有效秒數／3 | GameRules → Progress | 捕捉 1.5 秒約 50%。 |
| max(Progress, VoiceVisibility) | BugView → 材質 `_Visibility` | 移開後仍保留進度對應外觀。 |
| Base Volume × (1-Progress) | BugView → AudioSource.volume | 進度 50%，該群音量約為原始的一半。 |

不要在第二個腳本再加另一套計時或扣 SAN。成功後新群從 0 開始，不能繼承舊透明度／音量。

## 7. 替換 Prefab 的模型

1. 將 FBX／貼圖放 `Art/Bugs/<名稱>/`，等待 Unity 匯入。
2. Project 雙擊 `BugGroup.prefab`，進 Prefab Mode。
3. 刪除範例的 Visual 球體，將 FBX 拖入，命名 `Visual`。
4. 根物件 BugView 的 Visual 重新拖入新模型；根物件的 BoxCollider／AudioSource 留著。
5. 先保持 Use Prototype Material 勾選，確認模型可以透明顯現與捕捉。
6. 要保留貼圖：在 Materials/ 建 Material，Shader 選 AudioBugs/PrototypeReveal；Color 設白色，Color Texture 拖入 PNG。把材質拖到模型 Renderer 的 Materials 欄位，再取消 Use Prototype Material。
7. 多個材質槽各自設定；PrototypeReveal 已提供 `_Visibility` 與貼圖入口。正式自訂材質同樣需有 `_Visibility` 參數。
8. Prefab Mode 按 Save，左上返回場景，再 Play 測試。

| 問題 | 修正 |
| --- | --- |
| 比例怪 | 比對 1 m Cube；只調模型子物件或匯入比例，不縮放 XR Origin。 |
| 模型粉紅 | 材質 shader 不適用 URP；先用提供的 PrototypeReveal 測管線。 |
| 模型消失後也聽不見 | 不要停用整個 BugGroup；只控制 Visual 顯現。 |
| 新模型顯現失效 | 材質是否有 `_Visibility`？先勾回 Use Prototype Material 排除規則問題。 |
| 貼圖沒出現 | Renderer 是否使用新材質、Color Texture 是否已填、Use Prototype Material 是否已取消？ |

音檔匯入與陣列位置依[U2](#3-換成九個來源聲音)，此處不重複接線。

PrototypeReveal 已加入 XR 立體渲染巨集；仍需在 Quest 確認左右眼的貼圖、透明度及 Mask。

三種外形接法：

1. 在 Project 複製 BugGroup 為 BugA／BugB／BugC，分別換 Visual 模型。
2. DesktopLab 的 Variant Prefabs 改 Size 9。
3. 依U2變體表：0～2 拖 BugA、3～5 拖 BugB、6～8 拖 BugC。
4. 空白格使用 Group Prefab；要做獨立變體時，再替換該格。

## 8. Windows AEC／VAD 導入

**此節由 Windows 開發者執行。**Mac 先用第 5 節預覽；正式版不可用 RMS 預覽冒充回音消除。

### 8.1 編譯外掛（一次）

| 前置 | 做法 |
| --- | --- |
| C++ 工具 | Visual Studio Installer 安裝「使用 C++ 的桌面開發」，包含 MSVC、Windows SDK、CMake tools。不是只安裝 VS Code。 |
| 命令視窗 | 開始功能表開 Developer PowerShell for VS 2022，cd 到 repo。 |
| 工具位置 | vcpkg 放自行管理的工具資料夾，例如 C:/tools/vcpkg；不提交整套工具到專案。 |

第一次安裝 vcpkg：

```powershell
git clone https://github.com/microsoft/vcpkg C:/tools/vcpkg
& C:/tools/vcpkg/bootstrap-vcpkg.bat
& C:/tools/vcpkg/vcpkg.exe install speexdsp:x64-windows-static-md
```

| 教學來源 | 放到 repo |
| --- | --- |
| [exhibit_aec.cpp](../範例程式/U2/exhibit_aec.cpp) | native-aec/exhibit_aec.cpp |
| [aec-CMakeLists.txt](../範例程式/U2/aec-CMakeLists.txt) | native-aec/CMakeLists.txt；改檔名。 |

repo 根目錄執行；工具不在 C:/tools 時替換相同絕對路徑：

```powershell
cmake -S native-aec -B native-aec/build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/tools/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static-md
cmake --build native-aec/build --config Release
```

- 產物 native-aec/build/Release/exhibit_aec.dll；失敗先看第一個 CMake／C++ 錯誤。
- 原型採 SpeexDSP 1.2.1 AEC＋預處理 VAD；記錄 vcpkg 的 git rev-parse HEAD 與外掛版本。
- 提交 C++／CMake 原始碼及版本記錄；build/ 不提交。隨發布附 SpeexDSP 的 copyright。

### 8.2 接入 Unity

先在 Windows 專用 AecLab（複製 PresentationLab）測；借到頭戴後在 QuestLab 接同元件。Mac 的共用模擬場景不啟用此 Windows 收音元件。

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 建 Assets/Plugins/x86_64，放 exhibit_aec.dll | Inspector 只啟用 Windows／Editor，CPU x86_64；Mac 不載入。 |
| 2 | Project Settings→Audio | System Sample Rate 48000；Default Speaker Mode Stereo；套用後重開 Editor。 |
| 3 | Windows 系統音效選 Quest Link 的播放與麥克風輸入 | 列出裝置名稱；這裡不是瀏覽器相機權限。 |
| 4 | 停用 MicRevealPreview | 同時只能有一個收音入口。 |
| 5 | 複製 [AecVoiceInput.cs](../範例程式/U2/AecVoiceInput.cs) 到 Scripts/Tutorial | 掛在唯一含 AudioListener 的 Main Camera。 |
| 6 | Lab 拖 DesktopLab；Device Index 選正確輸入 | 先看 Microphone.devices 順序；需要單聲道 48000 Hz。 |
| 7 | Play，先保持安靜，再說話 | Audio Ready 有效；RMS 是 AEC 後音量；發聲觸發由 VAD＋門檻共同判定。 |
| 8 | 正式九個群落聲音、影片及音效都走 Unity AudioSource／混音 | AudioListener 的播放參考涵蓋實際遊戲聲；不要用外部程式播放干擾音。 |

外掛以每 10 ms 音訊處理；同段發聲只觸發一次，有效停聲 0.4 秒且冷卻 1 秒後重新就緒。缺少新鮮輸入／播放參考時停用發聲並重新等停聲。

### 8.3 用實際頭戴驗證

| 測試（每項至少 10 次） | 記錄／通過目標 |
| --- | --- |
| 只播群落及影片，不說話 | 誤觸發 0 次；否則尚未通過。 |
| 不播聲，觀眾說話 | 每次短呼喚有回應；記漏判及延遲。 |
| 邊播聲邊說話 | 不把整段音效當人聲；記重複觸發。 |
| 持續說話→停聲→再說 | 第一段一次，停聲後可再次觸發。 |
| 摘頭戴／切裝置／暫停再恢復 | 不把缺資料當停聲，不重設捕捉進度。 |

- Speex 的非同步參考內建延遲不能保證符合 Quest Link；此導入範例**尚未通過真實聲學驗收**。
- 若只播聲仍誤觸發，先核對正確輸入／輸出、取樣率、混音參考及實測延遲；不能只拉高門檻就宣布完成。
- Unity Profiler 檢查音訊執行緒耗時；DLL 建置與量測結果記入驗證清單。
