### 試聽方向與音量

1. 進 Play Mode，留一群作測試。在 Hierarchy 選另一個 Bug_…，勾 **Audio Source → Mute**。不改群落狀態。
2. 原地轉向及走近聲源，先測單群的左右與近遠，再取消 Mute 測兩群能否分辨。針對室內音虫，分別從門外、門口及進屋後試聽。
3. 預設採 Unity 內建 3D 音訊，尚未選空間音效插件。距離使用 1～12 m 線性衰減。正式音檔接好後再調音量，並由 X1 用頭戴確認前後／高度辨位。

### 雨景與雨聲

**開始前**：停止 **Play**，在 **Project** 開啟 `Assets/_Project/Scenes/CaptureLab.unity`。以下是 CaptureLab 灰盒的起始值。

- **素材交付（1/17）**：美術交雨景參考圖，聲音負責人交可無縫循環的雨打鐵皮 WAV。見[美術與聲音交付規格](../共用/美術與聲音交付.md#5-音檔交付)。
- **U2 接入**：1/12 先用佔位粒子和替代雨聲跑過切換。正式素材到檔後替換材質與音檔，再複驗循聲。

#### A. 在 Hierarchy 建物件

1. 點 **GameObject → Create Empty**，命名 `RainEffects`。放在場景最外層、與 `DesktopLab` 同層。在 **Inspector → Transform** 右上選單選 **Reset**。
2. 點 **GameObject → Effects → Particle System**，命名 `RainParticles`，拖到 `RainEffects` 底下。選子物件，在 **Transform** 填 **Position** `(0, 5, 7)`、**Rotation** `(90, 0, 0)`、**Scale** `(1, 1, 1)`。這會讓發射器從長街上方朝下。
3. 再點 **GameObject → Create Empty**，命名 `RoofRainAudio`，拖到 `RainEffects` 底下，對它的 **Transform** 選 **Reset**。在 **Inspector → Add Component** 搜尋並新增 **Audio Source**。

```text
CaptureLab
├─ DesktopLab
└─ RainEffects
   ├─ RainParticles   [Particle System]
   └─ RoofRainAudio   [Audio Source]
```

#### B. 設定雨滴

在 **Project** 的 `Assets/_Project` 新增資料夾 `Art/Weather`（已有資料夾可沿用）。在 `Weather` 內按右鍵 → **Create → Material**，命名 `MAT_RainPrototype`。選材質，在 **Inspector** 設 **Shader** 為 `Universal Render Pipeline/Particles/Unlit`，**Surface Type** 選 **Transparent**，**Blending Mode** 選 **Alpha**。先用白色底色即可。

選回 `RainParticles`，在 **Inspector → Particle System** 展開下列區塊。**Main** 是元件最上方的一組欄位。

| 區塊 | 欄位與起始值 |
| --- | --- |
| **Main** | 勾 **Looping**、**Play On Awake**。**Start Lifetime** `0.6`、**Start Speed** `8`、**Start Size** `0.06`、**Gravity Modifier** `0`、**Simulation Space** `World`、**Max Particles** `180`。**Start Color** 用淡藍色、約一半不透明度。 |
| **Emission** | 勾選區塊，**Rate over Time** `120`。 |
| **Shape** | 勾選區塊，**Shape** `Box`、**Emit from** `Volume`、**Scale** `(8, 14, 0.1)`、**Randomize Direction** `0`。這裡的 **Scale** 在 **Shape** 區塊內。 |
| **Renderer** | 勾選區塊，**Render Mode** 選 **Stretched Billboard**，**Camera Scale** `0`、**Velocity Scale** `0`、**Length Scale** `4`。從 **Project** 把 `MAT_RainPrototype` 拖到 **Material**。 |

選著 `RainParticles`，在 **Scene → Particle Effect** 面板播放，確認雨滴沿長街向下落。若雨太密，先降低 **Rate over Time**。換正式材質時，替換 **Renderer → Material**。換城市後再調 **Transform → Position** 和 **Shape → Scale**。

Unity 6.3：[粒子預覽](https://docs.unity.com/en-us/engine/6000.3/manual/visual-effects/particle-systems/part-sys-usage) · [Shape](https://docs.unity.com/en-us/engine/6000.3/manual/visual-effects/particle-systems/particle-system-modules/part-sys-shape-module) · [Renderer](https://docs.unity.com/en-us/engine/6000.3/manual/visual-effects/particle-systems/particle-system-modules/part-sys-renderer-module)

#### C. 設定雨聲

1. 在 **Project** 建立 `Assets/_Project/Audio/Environment`，把雨打鐵皮的 WAV 從檔案管理器拖進該資料夾。測試時可先放一段可循環的替代雨聲。
2. 選 **Hierarchy → RoofRainAudio**，把 **Project** 的 WAV 拖到 **Audio Source → Audio Resource**。勾 **Loop**、**Play On Awake**，**Mute** 保持未勾。
3. **Volume** 先設 `0.08`、**Spatial Blend** 設 `0`（2D）。先把雨聲當背景，聽得到下雨，也要能循聲找到魟魚。正式試聽時再調這一軌的音量。替換正式 WAV 時只需更新 **Audio Resource**。 [Unity 6.3 Audio Source](https://docs.unity.com/en-us/engine/6000.3/manual/audio/reference/class-audio-source)

#### D. 接進 CaptureLab 並測試

1. 在 **Hierarchy** 選 `DesktopLab`，找到 **Inspector → Desktop Lab (Script) → Rain Effects**。從 **Hierarchy** 把最外層的 `RainEffects` 拖進欄位。
2. 選 `RainEffects`，取消 **Inspector** 頂端物件名稱旁的勾選，讓場景儲存時預設是晴天。兩個子物件維持啟用，遊戲開始下雨時會由程式啟用整組。用 **File → Save** 儲存場景。
3. 按上方 **Play**，點一下 **Game** 視窗取得焦點。若開場停在 `Ready`、`Intro` 或 `Tutorial`，看到左上提示時按 **Enter** 推進到 `Phase: Active`。先留在探索階段，等左上計時到 60 秒。

| 測試 | 通過條件 |
| --- | --- |
| 開場到探索滿 60 秒前 | 左上顯示 `Weather: dry`，沒有雨滴、沒有雨聲。 |
| 探索滿 60 秒 | 左上切到 `Weather: rain`，`RainEffects` 啟用，看到雨滴、聽到循環雨聲。未捕捉的海天使／海兔和其聲源退場，仍可循聲找到並捕捉魟魚。 |
| 停止 **Play** 再開始 | 開場恢復晴天，雨景與雨聲等到本場探索滿 60 秒才啟用。 |

**卡住時**

- 顯示 `rain` 但雨景和雨聲都沒有：停止 **Play**，核對 **Rain Effects** 指向場景裡的 `RainEffects` 父物件，兩個子物件各自都已啟用。
- 有聲音但看不到雨：檢查粒子 **Emission**、**Renderer → Material**、發射器 Position／Rotation，以及 **Game** 視窗是否看向長街。
- 有雨但沒聲音：檢查 **Audio Resource** 是否有音檔、**Play On Awake** 是否勾選、**Game** 視窗是否靜音。雨聲蓋住音虫時，先降 `RoofRainAudio` 的 **Volume**。

## 4. 檢查 Mask 與遮擋

| 操作 | 預期 |
| --- | --- |
| 看向沒有音虫的牆面 | 圓形 Mask 仍沿牆面移動；不增加捕捉進度。 |
| 對準身後沒有牆面的有效群落 | 光罩移到群落前方並維持顯示；有遮擋時只能照到前方牆面。 |
| 看向沒有命中的方向 | Mask 收起。 |
| 勾 DesktopLab 的 UI Busy | Mask 收起、停止累積；取消後重新查詢，不清舊進度。 |
| 桌面測試按 P 暫停，再按一次 P 繼續 | 游標自動鎖回，可直接用滑鼠轉頭。進度、顯現及音量保留。 |

遮擋測試：

1. 停止 Play，建 Cube `Occluder`。
2. 世界 Position 設 `(1, 1.3, 2)`、Rotation Y `30`、Scale `(1.5, 2, 0.2)`。
3. 保留 Cube 的 Box Collider。
4. Play：對準擋板後方的目標，不得穿牆捕捉；拿開擋板再測。

這版 Mask 由腳本＋Shader 產生。預設直徑 0.25 m，在 DesktopLab 的 Mask Diameter 可調。換成凹凸城市後，再依美術需求評估 URP 投射效果。

### 用灰盒測室內音虫

**直接試玩：**預設 CaptureLab 保持 Create Lab Geometry 開啟、Spawn Points 與 Spawn Rooms 都為 Size 0。進 Active 後，左側 LabHouse 內固定有 1 群，室外另有 1 群。從街上循聲找到左側門洞，在屋外照射確認無進度，再走進屋內捕捉。

**需要自行配置室內點位時**，使用最新的 [DesktopLab.cs](../範例程式/U0/DesktopLab.cs) 和 [BugView.cs](../範例程式/U0/BugView.cs)。專案已有這兩個檔案，更新原檔即可。

1. 停止 Play。先完成第 2 節的 P0～P7，保留 Create Lab Geometry。以下測試房指定 P2（-3.2, 1.3, 5.9）。
2. Hierarchy 建空物件 HouseLab，Transform Reset。各牆用 **GameObject → 3D Object → Cube**，拖為 HouseLab 子物件，保留 Box Collider、取消 Is Trigger。

| Cube | Local Position | Local Scale |
| --- | --- | --- |
| Back | (-4.1, 1.5, 5.9) | (0.2, 3, 2.4) |
| SideA | (-2.9, 1.5, 4.7) | (2.4, 3, 0.2) |
| SideB | (-2.9, 1.5, 7.1) | (2.4, 3, 0.2) |
| DoorSideA | (-1.7, 1.5, 5.0) | (0.2, 3, 0.6) |
| DoorSideB | (-1.7, 1.5, 6.8) | (0.2, 3, 0.6) |

3. HouseLab 下建空物件 RoomZone，Local Position 設 (-2.95, 1.5, 5.9)，Scale 維持 (1, 1, 1)。**Add Component → Box Collider**，Center = (0, 0, 0)，Size = (2.5, 3, 2.4)，勾 **Is Trigger**。
4. 選 DesktopLab。**Spawn Rooms → Size 8 → Element 2** 拖入 RoomZone，其餘留空代表室外。若房間有多個候選點，各對應欄位拖同一個 RoomZone。新位置若沒有室內需求，Spawn Rooms 可整組留空。
5. Play 進 Active。觀察 Hierarchy 的 Bug 物件是否有一筆位在 P2；若自訂場景首批沒抽到，重新試跑。屋外應聽得到聲源，從牆後聽更悶。站在空門洞外直瞄，捕捉進度仍為 0。
6. 走進 RoomZone，再直接瞄準音虫。測進度約 50% 後退出，再進屋對準，應接回原進度與音量。若隔牆測試不夠明顯，先用有較多高頻的測試音。

BugView 的 **Outside Room Gain** 預設 0.45，**Behind Wall Cutoff** 預設 1200 Hz。先核對屋外仍可循聲，再按頭戴試聽調整。

### 接入正式城市模型

1. 停止 **Play**。把 FBX、貼圖放到 `Assets/_Project/Art/City/<模組名>/`。從 **Project** 把 FBX 拖進 **Hierarchy** 的 `CityRoot` 空物件。用 1 m Cube 比對大小及朝向，確認 **Renderer → Materials** 使用對應的 URP 材質。
2. 重複使用的建築或街景模組，加好材質與碰撞後，從 **Hierarchy** 拖到 **Project** 的 `Assets/_Project/Prefabs/City/` 做成 Prefab。一套只在本場使用的固定街景，可以直接放在 Scene。
3. 在需要擋住捕捉射線或顯示 Mask 的地面、牆面加 **Box Collider**。複雜的固定表面可用貼合形狀的 **Mesh Collider**。取消 **Is Trigger**，保留 **Default** Layer；裝飾物依需求加碰撞。
4. 確認正式地面與牆的 Collider 都到位，再在 **DesktopLab → Inspector** 取消 **Create Lab Geometry**。下次 Play 不再生成 LabFloor、LabWall、LabHouse 與內建入口標記。移除自己手動搭的佔位模型。把正式室內點位的 RoomZone 接回 **Spawn Rooms** 同索引，另按 [U3 入口定點](U3.md#83-入口定點淡黑與感謝信)接回 Exit Anchor 和地標。
5. 儲存 Scene、按 **Play**。看不到舊牆，地面與牆面能顯示 Mask，瞄向空處 Mask 收起。對準同一隻音虫，隔牆時進度不動，換到無遮擋位置可累積。捕捉一隻後確認補群也沒有埋進模型。室內點依上節把正式建物的 RoomZone 接到同索引的 Spawn Rooms。

## 5. 發聲顯現（後續規劃，本階段先不做）

**本階段先不做。** 共用場景保持 Enable Voice Reveal Preview 關閉。之後以獨立測試場景依序做下列步驟。

| 順序 | 開工後要做 | 通過條件 |
| --- | --- | --- |
| 1｜U2 顯現 | 在測試場景勾 DesktopLab → Enable Voice Reveal Preview。進 Active 後面向音虫，按 V 驗證事件。 | 前方範圍最多兩個既有群落回應。3 秒淡入＋1 秒淡出，回到原捕捉進度對應外觀。SAN、捕捉進度及群落數維持原值。 |
| 2｜U2 桌面收音 | 依下方步驟接 MicRevealPreview，先看音量與單次觸發。 | 短呼喚可觸發一次，持續說話不刷新，停聲與冷卻後才能再觸發。 |
| 3｜U2＋X1 頭戴收音 | 按第 8 節匯入 AEC／VAD 外掛，接 Quest 麥克風及實際播放參考。 | 只播放不誤觸發，說話有效，音訊失效時暫停發聲顯現。 |
| 4｜U3 教學 | 按 [U3 發聲教學](U3.md#發聲教學後續規劃本階段先不做)接字幕與提示。 | 教學只示範，Active 才接受正式發聲。 |
| 5｜X1 實機驗收 | 跑 [X1 發聲驗收](X1.md#發聲顯現驗收後續規劃本階段先不做)，記錄收音、延遲與誤觸發。 | 通過後才接進展出場景。 |

V 預覽目前用前方夾角 60°、距離 8 m 選目標。開工後把角度、距離及遮擋測試記入[待確認與驗證清單](../../待確認與驗證清單.md)，再定正式參數。展出場景只由有效收音觸發，接入前須把 V 限制在開發測試。

| 4 | Play，依系統提示允許 Unity 使用麥克風 | Console 顯示使用的麥克風名稱。 |
| 5 | 進 Active 後說話，觀察 RMS／Audio Ready | 音量足夠時，前方多群 3 秒淡入、1 秒淡出。 |
| 6 | 持續說話，再停一下、重新說 | 同段只觸發一次，停聲且冷卻後才再次觸發。 |

| 問題 | 修正 |
| --- | --- |
| 找不到麥克風 | Windows 設定→隱私權與安全性→麥克風；Mac 系統設定→隱私權與安全性→麥克風。 |
| RMS 說話時也很低 | 確認選對輸入裝置；依觀察結果調 Threshold，不用猜固定值適合所有機器。 |
| 遊戲聲音自己觸發 | 這個範例沒有 AEC；先暫停此元件並用 V 測規則，不能當成正式發聲完成。 |
| 沒有新音訊資料 | 不觸發，也不把缺資料當停聲；先修輸入。 |

## 6. 三個呈現值的接法

| 值 | 已由哪個檔案處理 | 核對方式 |
| --- | --- | --- |
| 有效秒數／3 | GameRules → Progress | 捕捉 1.5 秒約 50%。 |
| max(Progress, VoiceVisibility) | BugView → 材質 `_Visibility` | 移開後仍保留進度對應外觀。 |
| Base Volume × (1-Progress) | BugView → AudioSource.volume | 進度 50%，該群音量約為原始的一半。 |

不要在第二個腳本再加另一套計時或扣 SAN。成功後新群從 0 開始，不能繼承舊透明度／音量。

## 7. 替換 Prefab 的模型

1. 將 FBX／貼圖放 `Art/Bugs/<名稱>/`，等待 Unity 匯入。
2. Project 雙擊 `BugGroup.prefab`，進 Prefab Mode。
3. 保留 Visual 空物件，移除它下面的佔位球體。把單隻灰模 FBX 拖到 Visual 下，按群落構圖複製並調整子物件位置。照射顯現以整個 Visual 為一組。
4. 根物件 BugView 的 Visual 指向該空物件。保留根物件的 Box Collider／Audio Source，讓整群共用一個捕捉範圍與一個聲源。比對所有灰模範圍，必要時在 Box Collider → Edit Collider 調整。
5. 先保持 Use Prototype Material 勾選，確認模型可以透明顯現與捕捉。
6. 要保留貼圖：在 Materials/ 建 Material，Shader 選 AudioBugs/PrototypeReveal；Color 設白色，Color Texture 拖入 PNG。把材質拖到模型 Renderer 的 Materials 欄位，再取消 Use Prototype Material。
7. 多個材質槽各自設定；PrototypeReveal 已提供 `_Visibility` 與貼圖入口。正式自訂材質同樣需有 `_Visibility` 參數。
8. Prefab Mode 按 Save，左上返回場景，再 Play 測試。

| 問題 | 修正 |
| --- | --- |
| 比例怪 | 比對 1 m Cube；只調模型子物件或匯入比例，不縮放 XR Origin。 |
| 模型粉紅 | 材質 shader 不適用 URP；先用提供的 PrototypeReveal 測管線。 |
| 模型消失後也聽不見 | 不要停用整個 BugGroup；只控制 Visual 顯現。 |
| 新模型顯現失效 | 材質是否有 `_Visibility`？先勾回 Use Prototype Material 排除規則問題。 |
| 貼圖沒出現 | Renderer 是否使用新材質、Color Texture 是否已填、Use Prototype Material 是否已取消？ |

音檔匯入與陣列位置依[U2](#3-換成九個來源聲音)，此處不重複接線。

PrototypeReveal 已加入 XR 立體渲染巨集；仍需在 Quest 確認左右眼的貼圖、透明度及 Mask（X1 協助實測）。

三種外形接法：

1. 在 Project 複製 BugGroup 為 BugA／BugB／BugC，分別換 Visual 模型。
2. DesktopLab 的 Variant Prefabs 改 Size 9。
3. 依U2變體表：0～2 拖 BugA、3～5 拖 BugB、6～8 拖 BugC。
4. 空白格使用 Group Prefab；要做獨立變體時，再替換該格。三類各三款的正式造型由美術組決定。
5. 在 Prefab 根物件下另放正式外觀物件，與 Visual 並列。只放模型／材質，拖到 BugView 的 Capture Visual 欄位。
6. Play 並捕捉一次。成功時停聲、扣 SAN，彩色預覽後整群退場。DesktopLab 的 Capture Preview Seconds 原型預設 0.35 秒；正式時長由吸收動畫決定。
7. 無正式素材時，預設球體會短暫切換測試色。實機把雨天、兩群及成功顯形一起跑，記錄最重幀時間。

## 8. Windows AEC／VAD 導入（X1 協助）

**後續規劃，本階段跳過本節。** 啟用時才由 U2 與 X1 接入收音。 Mac 先用第 5 節預覽；正式版不可用 RMS 預覽冒充回音消除。

### 8.1 編譯外掛（一次，由 X1 協助）

| 前置 | 做法 |
| --- | --- |
| C++ 工具 | Visual Studio Installer 安裝「使用 C++ 的桌面開發」，包含 MSVC、Windows SDK、CMake tools。不是只安裝 VS Code。 |
| 命令視窗 | 開始功能表開 Developer PowerShell for VS 2022，cd 到 repo。 |
| 工具位置 | vcpkg 放自行管理的工具資料夾，例如 C:/tools/vcpkg；不提交整套工具到專案。 |

第一次安裝 vcpkg：

```powershell
git clone https://github.com/microsoft/vcpkg C:/tools/vcpkg
& C:/tools/vcpkg/bootstrap-vcpkg.bat
& C:/tools/vcpkg/vcpkg.exe install speexdsp:x64-windows-static-md
```

| 教學來源 | 放到 repo |
| --- | --- |
| [exhibit_aec.cpp](../範例程式/U2/exhibit_aec.cpp) | native-aec/exhibit_aec.cpp |
| [aec-CMakeLists.txt](../範例程式/U2/aec-CMakeLists.txt) | native-aec/CMakeLists.txt；改檔名。 |

repo 根目錄執行；工具不在 C:/tools 時替換相同絕對路徑：

```powershell
cmake -S native-aec -B native-aec/build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/tools/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static-md
cmake --build native-aec/build --config Release
```

- 產物 native-aec/build/Release/exhibit_aec.dll；失敗先看第一個 CMake／C++ 錯誤。
- 原型採 SpeexDSP 1.2.1 AEC＋預處理 VAD；記錄 vcpkg 的 git rev-parse HEAD 與外掛版本。
- 提交 C++／CMake 原始碼及版本記錄；build/ 不提交。隨發布附 SpeexDSP 的 copyright。

### 8.2 接入 Unity（X1 協助）

先在 Windows 開啟 `CaptureLab`，進入 **Play** 後暫時依下表切換收音元件。測完停止 **Play**，共用場景保留桌面收音設定。借到頭戴後，在 X1 的 `QuestLab` 保存正式接線。DLL 匯入、Audio 設定和腳本複製先在 **Play** 前完成。

| 步驟 | 操作 | 預期 |
| --- | --- | --- |
| 1 | 建 Assets/Plugins/x86_64，放 exhibit_aec.dll | Inspector 只啟用 Windows／Editor，CPU x86_64；Mac 不載入。 |
| 2 | Project Settings→Audio | System Sample Rate 48000；Default Speaker Mode Stereo；套用後重開 Editor。 |
| 3 | Windows 系統音效選 Quest Link 的播放與麥克風輸入 | 列出裝置名稱；這裡不是瀏覽器相機權限。 |
| 4 | 停用 MicRevealPreview。在這個測試場景勾 DesktopLab → Enable Voice Reveal Preview | 此勾選讓 AEC 範例可呼叫顯現原型。同時只留一個收音入口。 |
| 5 | 複製 [AecVoiceInput.cs](../範例程式/U2/AecVoiceInput.cs) 到 Scripts/Tutorial | 掛在唯一含 AudioListener 的 Main Camera。 |
| 6 | Lab 拖 DesktopLab；Device Index 選正確輸入 | 先看 Microphone.devices 順序；需要單聲道 48000 Hz。 |
| 7 | Play，先保持安靜，再說話 | Audio Ready 有效；RMS 是 AEC 後音量；發聲觸發由 VAD＋門檻共同判定。 |
| 8 | 正式九個群落聲音、影片及音效都走 Unity AudioSource／混音 | AudioListener 的播放參考涵蓋實際遊戲聲；不要用外部程式播放干擾音。 |

外掛以每 10 ms 音訊處理；同段發聲只觸發一次，有效停聲 0.4 秒且冷卻 1 秒後重新就緒。缺少新鮮輸入／播放參考時停用發聲並重新等停聲。

範例有效發聲從 0.35 秒起測。若已顯示 Audio Ready 但音虫毫無反應，先核對預覽勾選、是否在 Active、是否先有效停聲，以及頭部前方有沒有音虫。

### 8.3 用實際頭戴驗證（X1 協助）

| 測試（每項至少 10 次） | 記錄／通過目標 |
| --- | --- |
| 只播群落及影片，不說話 | 誤觸發 0 次；否則尚未通過。 |
| 不播聲，觀眾說話 | 每次短呼喚有回應；記漏判及延遲。 |
| 邊播聲邊說話 | 不把整段音效當人聲；記重複觸發。 |
| 持續說話→停聲→再說 | 第一段一次，停聲後可再次觸發。 |
| 摘頭戴／切裝置／暫停再恢復 | 不把缺資料當停聲，不重設捕捉進度。 |

- Speex 的非同步參考內建延遲不能保證符合 Quest Link；此導入範例**尚未通過真實聲學驗收**。
- 若只播聲仍誤觸發，先核對正確輸入／輸出、取樣率、混音參考及實測延遲；不能只拉高門檻就宣布完成。
- Unity Profiler 檢查音訊執行緒耗時；DLL 建置與量測結果記入驗證清單。

來源：[Speex AEC／VAD](https://www.speex.org/docs/manual/speex-manual/node7.html)、[SpeexDSP 原始碼](https://github.com/xiph/speexdsp)、[vcpkg port](https://github.com/microsoft/vcpkg/tree/master/ports/speexdsp)。
