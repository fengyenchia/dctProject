# 音虫 VR｜開發規格

日期：2026-11-03｜版本：VR v0.1

適用：單人 PCVR，VR 控制器操作虛擬捕捉器與回收站。這是開發規劃；所有未定參數、設備選型與驗證項目集中於[待確認與驗證清單](待確認與驗證清單.md)。先讀[技術架構](技術架構.md)，資料路徑對照[五張技術流程圖](技術流程圖.md)。

## 1. 功能與遊戲狀態

觀眾在 3D 城市循聲尋找音虫，持續瞄準一個群落完成自動捕捉。群落可以是一隻或一群，整群收走算一次捕捉、扣一次 SAN。SAN 為遊戲內精神值，不代表觀眾實際心理狀態。Unity 統一管理遊戲狀態。

```text
待機 → 工作人員協助配戴／建立場次 → 定位與操作教學 → 探索／捕捉
  ├─ 未達任務且 SAN 允許 → 繼續探索
  └─ 任務達成或 SAN 達限制 → 停止捕捉／前往虛擬回收站
回收站有效感應 → 記錄本場已到站 → 控制器按確認
→ 固定清單／登錄種類與群落數量 → 能量轉化為物品 → 城市修復
→ 本機保存成果 → 結尾／取下頭戴／交付成果 QR → 清場重置 → 待機
```

SAN 計算為 `max(0, 初始值 - 成功捕捉次數 × 每次扣值)`，參數與任務條件存於設定檔。精神啃食即扣 SAN，器具受損以震動呈現，不另計耐久或改變控制能力。回收後進入結尾。

## 2. 部署、開發軟體與設備

| 模組 | 規格與責任 |
| --- | --- |
| Unity、C#、URP | Windows PCVR 程式；城市、群落、捕捉、SAN、回收、音訊與修復 |
| XR Plug-in Management／OpenXR | 接入選定頭戴裝置的執行環境及輸入配置 |
| XR Interaction Toolkit／Input System | XR Origin、手部姿態、射線、移動、UI 與震動 |
| Unity Audio／Microphone | 城市空間聲源、觀眾音量分析與捕捉噪音 |
| Node.js、TypeScript | 本機串接服務 Gateway；管理、SQLite、成果同步與選配列印 |
| Next.js App Router、React、TypeScript | 必做的雲端成果頁／API，另部署本機工作人員管理頁 |
| SQLite／PostgreSQL | 本機成果及 outbox／雲端成果資料 |
| WebSocket／HTTPS | 本機 Unity 與 Gateway 雙向事件／認證上傳及唯讀成果 |
| Web Audio API、Blender、Git／Git LFS | 網頁聲部播放、3D 素材及版本管理 |

Unity 與 Gateway 同機執行。本機事件使用回環介面，不將 VR 頭手姿態逐幀傳往雲端。頭戴影像連線及追蹤由選定設備的 PCVR 執行環境處理，不能以 Gateway 的 WebSocket 代替。原型將 Unity 編輯器、套件、設備韌體及輸入配置版本記入交付文件。

## 3. 場次建立與 XR 輸入

1. 啟動頭戴設備的 PCVR 執行環境、Gateway、Unity 與管理頁，檢查頭戴畫面、頭手追蹤、音訊及本機保存服務。
2. 工作人員建立唯一 `session_id`，Unity 初始化 SAN、收集清單與群落。一次只允許一個進行中場次。
3. 以 XR Origin 管理虛擬原點；頭戴與控制器姿態轉為同一 Unity 世界座標。控制器模型綁定虛擬捕捉器，另設固定瞄準起點及前向。
4. 操作以 Input Actions 定義 Move、Turn、UI Select、Recycle Confirm；教學依實際控制器顯示操作提示。捕捉無需按鍵。
5. 取下頭戴、失焦或必要控制器失去追蹤時，取消未完成捕捉並暫停遊戲計時、擾動及生成事件；恢復後同步提示，重新瞄準。
6. 重設定位或更換設備後清除捕捉進度與到站資格，檢查 XR 原點及回收站互動；已確認收集紀錄保留於本場。

## 4. 群落、瞄準與自動捕捉

每個出現區有 `spawn_point_id`，只表示虛擬城市中的生成位置；每次生成建立新的 `group_id`、種類及狀態，不沿用上一群的捕捉進度。小個體在群落範圍內不規則運動。

1. 從捕捉器前端發出射線，取得最近有效碰撞；環境遮擋物必須參與判定，不能穿牆命中音虫。
2. 群落設一個捕捉範圍 Collider，與可見小個體分開。多個候選重疊時取最近有效命中，不同時累積多群。
3. 檢查場次、探索階段、追蹤、SAN、距離及群落可捕捉狀態。有效瞄準同一 `group_id` 才累積有效遊戲時間。
4. 確認移開、換目標、遮擋、群落消失或失去追蹤後進度歸零；手部容許值以設定管理，不把渲染幀數當作持續時間。
5. 達捕捉時間再檢查群落狀態，先標記為已捕捉並關閉判定，才整群移除、寫入一筆收集、扣一次 SAN、更新虛擬 LCD 與控制器震動。
6. 每次結算發出唯一捕捉紀錄對應的 `CAPTURE_NOISE`。同一出現區可生成新的不同種類群落，使用新 `group_id`；舊事件不能再次捕捉新群落。

虛擬 LCD 顯示 SAN、捕捉進度、結果與回收提示，保留像素風。介面是 Unity 畫面，不需要實體 LCD 板或讀取紅外線閃爍編碼。

## 5. 本機服務與資料分工

```text
OpenXR 輸入 → Unity 捕捉判定 → 畫面／聲音／控制器震動
Unity ↔ 本機 WebSocket ↔ Gateway ↔ SQLite／上傳佇列
本機管理頁 ↔ Gateway ↔ Unity 場次控制
Gateway → HTTPS → Next.js API → 雲端資料庫／版本化音軌
觀眾手機 → Next.js 唯讀成果頁
```

Unity 保存本場即時狀態；Gateway 保存成果與同步工作。Gateway 不判斷射線、不增加 SAN 或收集數。服務中斷時 Unity 保留場次，成果取得持久化確認前不得正常重置；後續重送使用同一結果識別。

事件進入 Unity 時由主執行緒套用。一般遊戲事件留在 Unity 程式內部；只有管理、保存及同步需要跨程式通訊，避免將本機捕捉拆成多段網路請求。

## 6. 聲音互動與虛擬回收站

### 兩條聲音路徑

| 來源 | 處理 | 影響 |
| --- | --- | --- |
| 觀眾聲音 | 頭戴麥克風在 PC 顯示的輸入裝置 → Unity 取樣 → 音量／持續時間、平滑及門檻 | 既有群落局部快速亂動，不生成音虫 |
| 成功捕捉 | 唯一 `CAPTURE_NOISE` → 噪音播放＋生成控制 | 捕捉器製造噪音，促成新群落誕生 |

頭戴麥克風的 PC 音訊路由須與實際 PCVR 連線一致。城市線索使用具位置的 AudioSource，頭部轉向改變聆聽方向；捕捉噪音在虛擬捕捉器附近播放。生成由程式事件直接驅動，不等音效被麥克風重新收到。

收音以門檻、持續時間及冷卻抑制誤觸，並對系統播放設輸入抑制／去回授處理。播放抑制期間不把系統聲音算成觀眾聲音，也不刪除合法的捕捉生成事件。第一版只分析音量，不需語意辨識、人聲雲端處理或保存原始錄音。

### 到站與確認分兩步

1. 任務達成或 SAN 達限制後切入 Return 階段，關閉捕捉並引導前往虛擬回收站。
2. 檢查玩家 XR Origin 位於站點互動距離內，且虛擬捕捉器進入回收站感應 Collider；只用延伸射線遠指不能授權。
3. 通過後設定本場 `station_visited = true`，提示按控制器確認鍵。捕捉器可移開，資格保留到回收或本場結束。
4. 確認鍵送出 `RECYCLE_REQUEST`，Unity 檢查場次、Return 階段、已到站、尚未結算及追蹤有效。
5. 先標記已回收、關閉重複結算，再固定收集清單，登錄種類與群落數量。噪音能量轉為物品並修復城市，演出呈現在 VR 世界內。
6. 新場次、中止、重置或重新定位時清除到站資格。重複進出感應區不自動回收，重複確認不重播演出或新增成果。

群落數量代表整群成功捕捉次數，不推算群內個體數。轉入 Return 後停止接受新捕捉，已成功捕捉引發的噪音與誕生回饋仍可完成，新群落不可捕捉；回收結算後進入結尾並清除尚未執行的生成事件。

## 7. VR 場景、移動與美術整合

原型使用傳送與分段轉向：傳送僅落在可行走地面，避開障礙、未開放區與不可達空間；傳送、切場或重新定位時取消捕捉進度。實際小幅移動與控制器虛擬移動共用 XR Origin，不能直接移動頭戴 Camera 抵消頭部追蹤。

| 交付 | 規格 |
| --- | --- |
| 城市 | 合理世界尺度、可探索路徑、地面／阻擋碰撞、聲源、生成區與回收站 |
| 群落 | 外觀小個體、活動範圍、獨立捕捉 Collider、擾動及捕捉／誕生動畫 |
| 捕捉器 | 控制器握持對位、射線起點、前向、像素 UI 與回收提示 |
| UI | World Space 或合適的跟隨介面；真機檢視字級、距離、遮擋及雙眼閱讀 |
| 回收／修復 | 物品生成、城市前後狀態、音效與注意力引導；不強制拖動頭部視角 |
| 效能 | 限制大量透明粒子及高成本光效，配置 LOD、物件池與烘焙光照，使用實機 Profiler 檢查 |

畫面品質以頭戴內穩定雙眼渲染為準，不能只依電腦鏡像判斷。工作人員螢幕顯示監看視角，不作第二套獨立遊戲。

## 8. 線上紀念品與實體列印

每場成果包括收集種類、各種類群落次數、修復結果與旋律配方。不同種類對應預製聲部，統一 BPM、拍號、循環長度與起點；保存配方、編排及素材版本，離場重開保持同一旋律。

1. Unity 完成結算後以 `RESULT_READY` 交付固定成果快照。
2. Gateway 在同一 SQLite 交易保存 `result_id`、不可猜測唯讀 token、配方及 outbox，成功後回覆 `RESULT_SAVED`。
3. Gateway 認證上傳至 Next.js API，依同一 `result_id` 去重，雲端資料庫與版本化音檔供離場觀看。
4. 觀眾取下頭戴後取得可用手機掃描的成果 QR；不能只把 QR 放在頭戴內作為唯一交付。
5. 斷網時照常保存與交付連結，復線補傳。尚未發布的連結提示「成果尚未就緒或連結無效，請稍後重試」。
6. 感謝信、摘要、點擊播放旋律為必要內容；列印為選配，紙本使用同一成果連結。列印故障不重新結算、不阻塞線上成果。

遊戲重置不刪除成果與 outbox。雲端服務獨立於展場主機；長期維護安排見討論清單。

## 9. 事件與資料模型

| 資料 | 用途 |
| --- | --- |
| session_id | 區分場次，拒絕上一場延遲指令 |
| spawn_point_id／group_id | 虛擬生成區／當次群落；不是實體牆面或燈通道編號 |
| capture_id | 一次成功捕捉；扣 SAN、噪音與生成控制都對應這筆紀錄 |
| result_id／token | 同一成果去重上傳及離場重開 |

| 範圍 | 事件 | 作用 |
| --- | --- | --- |
| 管理端 ↔ Unity，經 Gateway | SESSION_START／PAUSE／RESUME／RESET | 本場控制與狀態回覆 |
| Unity 內部 | AIM_CHANGED／CAPTURE_PROGRESS | 目標改變、捕捉進度與 UI |
| Unity 內部 | CAPTURE_COMMITTED／CAPTURE_NOISE | 一次成功扣值與回饋／噪音播放及生成 |
| Unity 內部 | STATION_VISITED／RECYCLE_REQUEST／RECYCLE_COMMITTED | 到站授權、按鍵要求與一次回收 |
| Unity → Gateway | RESULT_READY | 固定成果快照 |
| Gateway → Unity | RESULT_SAVED | 本機持久保存確認 |
| Gateway → 雲端 | RESULT_UPLOAD／ACK | 同一成果重試與上傳確認 |

狀態含 phase、SAN、收集清單、目前群落、捕捉進度、station_visited、recycled；事件綁定本場。同一 capture_id 只執行一次噪音與生成規則，不是限制每次只能生成一群。頭手姿態只在即時輸入使用，成果不需要保存完整移動軌跡。

## 10. 異常與備援

| 情況 | 處理 |
| --- | --- |
| 頭戴取下、應用失焦或控制器失去追蹤 | 取消捕捉進度，暫停計時與生成；恢復後重新瞄準 |
| 重新定位／更換設備 | 暫停，清進度及到站資格，檢查虛擬原點後恢復 |
| 目標遮擋、移開、消失或更換群落 | 進度歸零，拒絕對已捕捉群落重複結算 |
| SAN 達限制 | 正常進入 Return，不再接受捕捉 |
| 遊戲進入回收／暫停 | 不繼續累積捕捉；暫停時凍結生成計時，回收結算後取消尚未執行生成事件 |
| 麥克風不可用 | 顯示管理告警並修復收音；不偽造觀眾發聲事件 |
| 低電、連線中斷或活動邊界告警 | 工作人員暫停體驗、處理設備；不要求觀眾盲走找實體回收座 |
| Gateway／本機保存失敗 | 保留結果並重試，不正常重置開新場 |
| 外網斷線 | 本機持續遊戲，outbox 復線補傳 |
| Unity 當機 | 僅由已持久化且驗證有效的資料恢復，否則標記中止；不得宣稱已還原所有即時進度 |
| 重複回收／上傳 | 同一場只結算一次，同一成果只保存發布一份 |
| 網頁播放或列印故障 | 摘要可查看，播放提示重試，列印可補印 |

頭戴使用感應與追蹤有效性由所選執行環境提供；有不可靠訊號時由管理端暫停處理，不假設所有設備暴露相同功能。

## 11. 管理、成果交付與重置

管理頁顯示場次、XR 連線／追蹤、麥克風、SAN、捕捉／回收階段、成果保存、同步及設備可取得的電量資料。提供開始、暫停、恢復、中止、重置、成果重開與選配補印；管理操作限定工作人員。

結尾、成果 QR 交付及本機持久保存都完成後才重置。重置取消生成事件、移除群落、清空 SAN／收集／進度／到站／回收狀態，回到待機教學起點；保留已存成果與同步佇列。檢查設備及活動區後再開下一場。

## 12. 開發順序與交付

1. **VR 操作原型：**建立 XR Origin、移動／轉向、一個群落與捕捉器 UI，完成對準、移開歸零、SAN 及震動。
2. **聲音因果：**接入頭戴收音，分別完成既有音虫擾動與捕捉噪音促成誕生，確認不重複觸發。
3. **完整結尾：**虛擬到站、按鍵確認、一次回收、轉化與城市修復。
4. **成果串接：**本機保存、Next.js 頁面、旋律、離場 QR 與斷網補傳。
5. **正式內容與展場：**擴充城市／種類，檢查實機效能、追蹤、暫停恢復及完整接待重置。

建議程式目錄為 `unity-vr/`、`gateway/`、`web/`、`shared/`；本資料夾僅交付文件，不表示已建立或實作程式。共用成果模型可沿用投影版設計，但另建 VR 場景及輸入模組，保留原投影版。

交付包含 Unity 專案與套件鎖定檔、輸入映射／生成設定、事件 schema、本機服務／網頁、素材清單、場次操作手冊及實機驗證紀錄。
