# 音虫互動投影技術架構

日期：2026-10-28  
版本：v0.8  
用途：供組員了解作品運作方式、軟硬體需求與跨組配合事項。

程式介面、資料格式、連線控制及詳細驗收請見[開發規格](../開發規格.md)。本文件說明目前採用的方案；手機辨識、到站判定與連線效能仍待原型驗證，設備配置待場勘確認。

## 1. 專案概述與功能範圍

本作品為單人進場的城市互動投影。觀眾以自己的手機掃描固定入口 QR Code，開啟網頁並按下「開始」。觀眾聆聽城市聲音、發聲吸引音虫，再用手機相機對準投影中的音虫進行捕捉。

手機顯示捕捉框、收集清單與 SAN；SAN 是依捕捉數量扣減的遊戲數值。任務尚未完成時繼續捕捉，完成或達到捕捉限制後前往回收站，以手機按鈕觸發轉化與城市修復，進入結尾。

回收成果依收集的音虫種類組合預製音軌，產生個人旋律與感謝信。觀眾離場後可再次開啟成果頁，並可選配實體列印紀念品。

## 2. 系統連接架構

```text
觀眾手機：Next.js 網頁
  ├─ 相機 → 手機端背景辨識 → 對準座標
  └─ 捕捉／回收操作
            ↕ HTTPS／WSS
雲端：Next.js 網站與 API ＋ Node.js 即時通訊服務
  ├─ 入口狀態、單人連線與操作驗證
  └─ 成果資料庫與音樂素材
            ↕ WSS
展場主機：本機串接服務（Gateway） ↔ Unity
  ├─ Unity：音虫、判斷是否捕捉成功、SAN、回收、投影與聲音
  └─ 本機串接服務（Gateway）：事件紀錄、成果同步與列印

現場麥克風 → 音訊介面 → Unity 聲音分析
Unity → 兩面主投影／回收站投影／喇叭
本機串接服務（Gateway） → 印表機（選配）
```

**Unity 統一決定遊戲結果。**手機送出對準座標與操作要求，Unity 判定後同步更新投影與手機。相機影像在手機端分析，通訊只傳座標、操作與狀態。

例如：手機對準音虫並按下捕捉 → 傳送對準位置 → Unity 判斷捕捉成功 → 投影音虫消失，手機更新收集清單。

HTTPS 提供網站與相機存取所需的安全環境；WSS 是加密的即時雙向連線，用來同步手機與投影。現行配置需要對外網路，主機建議使用有線連線。

每次只開放一個場次。其他手機開啟入口時顯示體驗中；暫時斷線可恢復原場次，逾時由系統中止並重置。結尾先保存成果，待 Unity 重置完成後才開放下一位。

本機串接服務（Gateway）是執行於展場電腦的程式，負責在雲端與 Unity 之間轉送操作及結果，並處理成果同步與列印。

## 3. 主要開發軟體

| PostgreSQL／SQLite | 分別保存雲端成果、本機紀錄與待同步工作 |
| Web Audio API | 成果頁依同一時間軸播放預製音軌 |
| Blender、音訊剪輯／混音軟體 | 製作模型、動畫、城市聲音與旋律音軌 |

## 5. 手機辨識與捕捉流程

**觀眾看到的是連續的城市畫面。**技術組從背景挑選商店、站牌、窗框等具有獨特細節的範圍，建立「牆面參考區塊」。區塊邊界只存在於辨識資料中，可大小不同、局部重疊；音虫可跨越區塊移動。

1. **載入參考資料：**手機開始體驗後取得各牆背景的參考圖與位置資料。
2. **開啟相機：**觀眾授權後鏡頭，手機顯示相機預覽與中央捕捉框。
3. **辨識背景：**追蹤模組比對招牌、窗框等細節，確認目前拍到哪面牆、哪個參考區塊。
4. **換算對準位置：**依拍攝角度，估算捕捉框對準整面牆的哪個位置，供 Unity 判斷是否對準音虫。
5. **送出捕捉：**觀眾按下按鈕，手機傳送有效座標與捕捉要求。
6. **判定與回饋：**Unity 檢查該處是否有可捕捉音虫，成功後更新音虫、收集數量與 SAN，再同步投影與手機。
7. **走動與換牆：**手機自動重新比對背景。快速轉身、遮擋或特徵不足時暫停捕捉，辨識恢復後繼續；兩牆歸屬不明時提示對準單一牆面。

音虫微動、生成或消失由 Unity 管理，手機持續依背景辨識位置。手機顯示搜尋中、已辨識背景、處理中、成功或暫時無法辨識背景等狀態；收到 Unity 確認後才顯示捕捉成功。

布展時須完成背景與投影座標對位。更換背景、移動投影機或調整輸出比例後，須重新驗證座標。

## 6. 聲音、回收與紀念品

| 環節 | 實際運作 |
| --- | --- |
| 聆聽與發聲 | 城市播放預製聲音引導探索；現場麥克風取得觀眾聲音，Unity 分析音量、持續時間等特徵，驅動音虫吸引與視覺反應 |
| 收音控制 | 麥克風避開喇叭直射，設定背景門檻與反應上限，實測排除作品播放聲反覆觸發的情況 |
| 回收與修復 | 回收站投影在實體物件上；觀眾以手機虛擬按鈕送出回收要求，Unity 結算並播放轉化與城市修復 |
| 個人旋律 | 依收集種類組合預先製作、節拍一致的音軌，保存配方供成果頁再次播放 |
| 數位成果 | 結尾提供感謝信與旋律連結，離場後仍可開啟；成果頁僅供查看與播放 |
| 實體紀念品 | 選配列印感謝卡、音虫圖案與個人成果 QR Code，由本機串接服務依序送印 |

SAN 達限制時停止捕捉，前往回收站；系統確認觀眾到站後，才開放手機回收按鈕。完成回收後進入結尾。

到站採手機相機辨識回收站的固定圖樣；圖樣在畫面中夠大並穩定約 1 秒後，開放回收按鈕。按下時再次確認，無法辨識或圖樣太小時鎖定。判定門檻與穩定度待不同手機實測，感測器作為備案。

## 7. 美術配合與交付需求

背景採**穩定辨識層與動態演出層分開製作**。穩定層提供定位；音虫、粒子、環境動態與修復動畫在其他圖層或物件中演出。

| 項目 | 配合重點 |
| --- | --- |
| 背景辨識細節 | 招牌、海報、管線等須有清楚輪廓、明暗對比與非重複圖樣；各捕捉點附近都應有可見特徵 |
| 兩牆差異 | 使用可區分的背景，減少大面積重複窗戶、對稱或相似紋理造成的誤認 |
| 動畫與遮擋 | 互動期間保留參考區塊的位置、比例與足夠細節；大範圍霧、閃光或遮蔽時暫停捕捉 |
| 場景變動 | 整體平移、縮放或換視角時，同步調整參考資料與座標映射 |
| 投影對位 | 素材比例對應正式輸出；裁切、拼接及物件投影校正後，驗證手機對準位置 |
| 音虫與回饋 | 定義各種類的活動、出現／消失、可捕捉範圍、捕捉與回收演出 |
| 聲音素材 | 城市聲源、音虫音色、操作音效及相同速度與節拍的旋律音軌，各音軌分開交付 |

交付需包含：各牆穩定背景圖與版本、參考區塊的位置及範圍、分層場景、音虫互動定義、正式投影對位資料，以及手機各狀態介面。

美術與技術須共同用真實投影測試：觀眾對準音虫時，鏡頭內就應有足夠背景細節可定位。參考區塊的尺寸、分布與局部辨識能力以實測調整。

| 類別 | 優先確認內容 |

| 手機辨識與相容性 | iOS／Android 真機的相機權限、後鏡頭、局部入鏡、走動與換牆、發熱及背景恢復；候選追蹤套件能否達到捕捉需求 |

# 音虫互動投影開發規格

日期：2026-10-28  
版本：v0.8  
用途：供開發與整合使用，定義部署、辨識、通訊、資料、異常處理與驗收規格。

專案概覽、設備摘要與跨組配合請見[技術架構](../技術架構.md)。本文件為規劃規格，候選套件、設備型號與效能參數須經原型及場勘確認。

## 1. 功能與遊戲狀態

### 架構範圍

本作品是單人進場的城市互動投影。觀眾以自己的手機掃描固定入口 QR Code，開啟網頁，按下「開始」建立單人場次。完成相機授權後，對準投影中的音虫並按下捕捉。手機辨識城市背景、取得對準座標，Unity 負責命中判定、音虫活動與 SAN 更新。

完成任務或達到捕捉限制後，觀眾前往回收站，以手機虛擬按鈕觸發轉化與城市修復。結尾取得感謝信、個人旋律及選配列印紀念品；數位成果可於離場後再次開啟。

**系統組成：Unity Windows 應用程式＋Next.js 手機網頁＋Node.js 通訊服務＋現場收音與播放設備＋兩面主投影。**

背景保留可辨識的穩定特徵，音虫可微動、生成或消失。觀眾走動與換牆時，手機自動重新辨識；特徵不足時暫停捕捉，恢復追蹤後繼續。

本文件為架構設計；套件版本、設備型號與效能參數於原型及場勘後確認。

### 功能需求

| 項目 | 內容 |
| --- | --- |
| 體驗人數 | 第一版單人，一場只允許一個有效操作身分 |
| 主要介面 | 觀眾自備手機，掃固定入口 QR Code 開啟 Web App，按「開始」建立場次 |
| 場次管理 | 一次一個場次、一個有效操作連線；結束後保留成果並重置展場 |
| 互動方式 | 手機相機辨識投影背景，鏡頭中央捕捉框對準音虫 |
| 場景聲音 | 預先製作的城市與音虫聲源，供觀眾聆聽、尋找 |
| 人聲輸入 | 現場設置數支麥克風收取觀眾聲音，影響音虫活動 |
| SAN | 遊戲內虛擬數值，依捕捉數量降低 |
| 捕捉循環 | 任務未完成且 SAN 尚可捕捉時，繼續尋找與捕捉 |
| 回收後 | 直接進入轉化與結尾 |
| 轉化規則 | 依互動流程圖：回收資源轉化為回饋物品，呈現城市修復 |
| 紀念旋律 | 依收集種類，組合預先製作的音軌 |
| 影像輸出 | 暫定兩面主投影；小互動區數量待定 |
| 個人成果 | 感謝信與旋律離場後仍可開啟；實體列印可做 |

### 遊戲狀態與任務判定

### 狀態流程

```text
待機開放 → 掃固定入口 QR → 按開始／建立場次 → 前導與教學 → 探索／捕捉
                                ├─ 未完成且可捕捉 → 繼續探索／捕捉
                                ├─ 達成任務 → 前往回收站
                                └─ SAN 達限制 → 停止捕捉，前往回收站
前往回收站 → 回收登錄 → 轉化／城市修復 → 保存成果 → 結束 → 重置完成 → 待機開放
```

回收後直接結尾，不回到探索。現場管理介面另提供暫停、取消與強制結束，處理離場或設備故障。

### 結束與重置

1. 完成回收與結尾後，將收集結果、感謝信與旋律配方保存為獨立成果，手機取得唯讀連結；雲端暫時離線時保存本機待同步工作。
2. 將場次標記完成，撤銷遊戲操作憑證與有效控制連線，手機切換成果頁並停止相機及追蹤。
3. Unity 進入重置：清空當場音虫與生成計時、SAN、收集清單、捕捉冷卻、對準狀態、回收狀態及暫存提示，恢復待機畫面與聲音。
4. Unity 回報 `EXHIBIT_READY` 後，服務端釋放單人名額並依入場開放設定接受下一場。重置完成前，入口顯示「準備中」。
5. 中途離場或管理端中止時，將原場次標記中止、撤銷控制權，再執行同一重置流程。未完成場次不標為成功成果。

已保存成果、待同步工作與列印佇列依場次分開保存，重置遊戲不刪除這些資料。雲端同步或列印可於背景續作；本機保存或重置失敗時保持暫停入場，由管理端處理。

### SAN 與完成條件

SAN 作為捕捉負荷的主要指標；是否另設容量顯示由企劃確認。

SAN 可採 `max(0, 初始值 - 已成功捕捉數量 × 每隻扣除值)`。數值均由設定檔控制；畫面上的「捕捉要求」不算成功，只有 Unity 確認後才扣值。

任務目標以設定檔管理，保留數量、種類與區域條件。SAN 達限制即停止捕捉並進入「前往回收站」，作為正常回收流程。

Unity 是當場遊戲狀態的唯一權威。手機、回收站與 本機串接服務（Gateway） 只提出要求，不自行增加捕捉數、恢復 SAN 或完成任務。

## 3. 場次建立與控制權

### 固定入口與場次建立

入口 QR Code 固定連到捕捉器 HTTPS 網址，可印在入口告示。每次掃碼只開啟網頁與查詢展場狀態；遊戲場次在按下「開始」後建立。

1. 展場主機啟動並完成初始化，管理端開放入場。
2. 觀眾掃固定 QR 開啟網頁。展場可用時顯示「開始」；體驗中顯示「目前體驗中」；重置或設備未就緒時顯示對應狀態。
3. 觀眾按「開始」，服務端以排他操作保留唯一名額並建立待啟動場次，Unity 初始化場景、SAN、音虫與收集紀錄。重複點擊沿用同一啟動要求。
4. Unity 確認初始化完成後，場次進入有效狀態，手機取得綁定該場次的操作憑證並建立有效 WSS 連線。初始化失敗或啟動逾時時，取消待啟動場次並清理保留名額。
5. 手機載入內容版本與參考圖，觀眾點擊啟用音效、確認音量，並授權後鏡頭。[T1]
6. 顯示相機預覽、中央捕捉框、SAN 與追蹤狀態，進入前導與教學。相機畫面在手機處理，背景辨識成功後開放捕捉。授權或裝置問題可重試、使用備用手機，或由管理端取消場次。

iOS 與 Android 均以瀏覽器執行，但相機權限、後鏡頭選擇、效能與背景恢復需真機測試。退出捕捉頁或離場後停止相機串流，釋放追蹤模組與 WebSocket；恢復頁面時重新辨識，不沿用舊映射。

### 單人操作鎖定與恢復

- 服務端集中管理展場的單人名額，同時收到多個開始要求時，只接受一個；其餘回覆 `SESSION_BUSY`。一般開啟網頁或掃 QR 不會佔用名額。
- 同一場次只有一個有效遊戲控制連線。手機重整或重連時，以原場次恢復憑證取回狀態；新控制連線成立後，撤銷舊連線的操作權。多分頁沿用此規則。
- 每次控制連線帶有遞增連線世代，Unity 驗證場次與控制世代；舊連線、舊場次及重置前滯留的命令均拒絕。
- 其他手機只可查看入口可用狀態；已有的成果頁保持唯讀，不取得遊戲控制權。備用手機接手需由管理端明確轉移操作權。
- 暫時斷線保留原場次與名額，取消未完成捕捉，等待原觀眾恢復；逾時依管理設定中止並進入重置。停止相機或關閉頁面本身不立即釋放名額。
- 固定入口網址為公開入口；工作人員以管理端開放／關閉入場。服務端在主機未就緒、場次啟動中、遊戲中及重置中拒絕新場次。

## 4. 圖像追蹤與捕捉

### 背景辨識與對準座標

手機辨識背景並建立牆面的平面對應關係，將相機中央捕捉框映射到牆面標準座標，再由 Unity 與音虫範圍比對。

#### 牆面參考區塊

觀眾看到的是連續的城市畫面。技術組從背景挑選數個具有辨識度的美術範圍，保存為「參考區塊」，作為手機定位依據；區塊邊界只記錄在資料中，不顯示於投影。

例如，同一面牆可使用以下參考區塊，實際內容由美術設計決定：

| 城市背景 | 參考區塊 | 供手機比對的細節 |
| --- | --- | --- |
| 左側商店 | 商店 A | 招牌輪廓、窗框轉角與海報圖樣 |
| 中間公車站 | 公車站 B | 站牌外形、路線圖與候車亭結構 |
| 右側建築 | 建築 C | 管線轉折、裝飾與獨特窗框 |

參考區塊可大小不同、局部重疊，依鏡頭預期拍攝範圍配置。它與「遊戲互動區」是不同資料：前者協助定位，後者決定音虫生成與捕捉規則。兩者不必一對一，音虫也可跨越參考區塊邊界。

每個參考區塊具有 `anchor_id`，並記錄所屬 `wall_id`、背景版本、參考圖及其在整面牆的位置與大小。辨識成功後，即可從局部圖像換算到整牆座標。圖像追蹤套件須驗證局部入鏡能力；實際可辨識範圍依特徵分布、拍攝距離與角度測試決定。

#### 從相機畫面到捕捉結果

1. **準備參考資料：**美術交付穩定背景圖層，技術組選取參考區塊、產生圖像特徵資料，並建立區塊與牆面的座標對應。手機開始體驗時載入相同內容版本。
2. **取得相機影像：**Next.js 瀏覽器端取得後鏡頭畫面。中央捕捉框的位置依影片原始尺寸、CSS 裁切／縮放、直橫向與鏡像設定，換算成影像中的位置。
3. **比對圖像特徵：**追蹤模組比對窗框、招牌及海報等已知細節，取得參考區塊 ID 與有效追蹤結果。例如辨識出「第一面牆的商店 A」；這是與指定參考圖比對，而非僅判斷畫面中有商店。[T15]
4. **計算畫面對應：**利用可靠的特徵對應，計算相機斜拍畫面與參考圖的透視關係，處理觀眾站位造成的縮放與傾斜。追蹤結果經座標轉接層，取得捕捉框落在參考圖中的位置。[T16]
5. **換算整牆座標：**依區塊在整面牆的位置與大小，將捕捉框轉為 `wall_id` 與標準化 `u/v`。牆面左上為 `(0,0)`、右下為 `(1,1)`；手機同時保留參考區塊、內容版本、樣本時間與追蹤品質。
6. **提交捕捉：**觀眾按下捕捉後，手機透過 WSS 傳送當次有效座標與操作要求。相機影像留在手機分析。
7. **Unity 命中與回饋：**Unity 將音虫當下位置換算到相同牆面座標，驗證目標存在、可捕捉範圍、SAN 等條件，結算後更新投影並將結果回傳手機。

座標換算示例：某參考區塊佔牆面橫向 20%～50%、縱向 30%～60%。若捕捉框對準該區塊中心，換算後就是整面牆的 `(u=0.35, v=0.45)`。Unity 使用這個整牆位置檢查音虫，而不是把整個參考區塊視為一次命中。

音虫微動時更新命中範圍；暫時消失或已被捕捉時，該位置沒有有效目標。只要背景仍可辨識，音虫的狀態變化不影響背景定位。

#### 換牆與重新辨識

兩面牆分別建立參考資料與平面映射。觀眾轉向另一面牆時，手機自動比對另一組背景特徵，依品質與穩定性切換當前牆面。兩牆同時入鏡且歸屬不明時，顯示「請對準單一牆面」並暫停捕捉。

布展時完成參考圖與投影座標對位；移動投影機、更換背景或顯示比例後，重新驗證。快速轉身、遮擋或特徵不足時暫停捕捉，待自動重新辨識後恢復。曲面與立體物件需另外建立映射方式。

### 捕捉與延遲處理

手機顯示「搜尋中／辨識成功／追蹤失效」。捕捉要求帶入當次有效影像樣本的座標、內容版本與追蹤資訊。

Unity 驗證場次、有效控制連線世代、牆面／區塊、內容版本、座標、樣本新鮮度、目標、冷卻及 SAN，再統一結算結果。

捕捉時間窗與命中容許範圍，需涵蓋相機曝光、辨識及網路延遲。Unity 以當前狀態判定；目標已消失、已被捕捉或樣本過舊時，提示重新瞄準。

成功後 Unity 更新音虫、計數與 SAN，經原路徑回傳 `CAPTURE_RESULT` 與狀態快照。手機播放捕獲音色、更新清單，投影呈現音虫減少與吸取效果。手機先顯示「處理中」，只有收到成功結果才播放成功動畫。

影像在手機端辨識，WSS 傳送座標與事件。高頻瞄準資料採限流及最新樣本優先，辨識解析度與更新頻率依真機測試設定。

手機聲音仍需使用者點擊啟用；播放失敗時有提示及投影側替代音效，不阻塞捕捉。[T9]

## 5. Next.js 與 Unity 串接

### Next.js、通訊服務與 Unity 的責任

| 模組 | 負責內容 |
| --- | --- |
| Next.js Client Component | 相機預覽、圖像追蹤、背景座標換算、捕捉框、按鈕、音效及 WebSocket 客戶端 |
| Next.js Route Handlers／伺服器端 | 入口狀態查詢、場次建立／恢復、驗證、參考圖 manifest 與成果查詢等 HTTPS API |
| 常駐 Node.js WSS 服務 | 單人名額協調、控制連線驗證、轉送命令與結果、限流及斷線處理 |
| 本機串接服務（Gateway） | 維持雲端連線、轉送 Unity、記錄已確認事件、同步成果與列印 |
| Unity | 遊戲狀態、物件座標、命中、SAN、回收、投影與聲音 |

相機與追蹤套件在瀏覽器端載入。追蹤運算與 React 介面更新分離，依套件能力評估 Worker／WASM，降低主執行緒負擔。[T18]

HTTPS API 規劃為：`GET /api/exhibit/status` 查詢可用狀態、`POST /api/sessions/start` 按開始後建立場次、`POST /api/sessions/resume` 恢復既有場次、`GET /api/tracking/manifest?contentVersion=...` 讀取參考資料、`GET /api/results/:token` 讀取成果。場次 API 與 WSS 共用同一名額及控制權管理；即時捕捉與回收使用 WSS，路徑及 schema 於協定文件定版。

完整事件路徑為：`手機 Client → 雲端 WSS → 本機串接服務（Gateway） → Unity → 本機串接服務（Gateway） → WSS → 手機`。Unity 收到網路事件後排入主執行緒處理，避免在網路 callback 任意操作場景。

捕捉訊息範例（協定草案）：

```json
{
  "protocol_version": 1,
  "type": "CAPTURE_START",
  "session_id": "session-example",
  "control_epoch": 1,
  "request_id": "capture-unique-id",
  "payload": {
    "wall_id": "wall-a",
    "anchor_id": "shop-front-a",
    "content_version": "city-v1",
    "tracking_seq": 42,
    "frame_age_ms": 80,
    "u": 0.42,
    "v": 0.61,
    "tracking_valid": true
  }
}
```

Unity 回覆同一 `request_id`、成功與否、原因、最新 revision、SAN 與收集狀態。樣本新鮮度依 `frame_age_ms` 與傳輸時間共同判定；協定文件需定義時間同步、容許誤差與逾時策略。

## 6. 聲音與回收站

### 現場聲音與音虫系統

### 聲音來源分工

| 來源 | 資料 | 對應功能 |
| --- | --- | --- |
| 預製城市與音虫聲音 | 音檔、聲源位置與種類 ID | 引導尋找、辨認區域、提供捕獲音色 |
| 現場麥克風 | 各通道音量、發聲持續時間、必要時頻段特徵 | 吸引／聚集音虫，超過持續門檻時增加活動或生成風險 |
| 手機捕捉操作 | 開始／取消／完成要求 | 模擬收錄指定音虫，依遊戲目標取得聲源 |
| 結尾旋律 | 預製音軌 ID、編排與音量 | 依收集種類組成個人化成果 |

麥克風由音訊介面輸入 Unity，分析音量與持續時間。多通道讀取及驅動相容性需實測，必要時透過本機音訊服務傳回分析值。[T4]

### 即時處理規則

- 遊戲開始前依各區背景音量校正收音門檻。
- 使用平滑、持續時間、觸發／解除不同門檻及冷卻，避免一聲噪音重複觸發。
- 每支麥克風對應固定區域權重。
- 「吸引既有音虫」與「新增音虫」是不同事件，分別設門檻、冷卻與生成上限。
- 依喇叭、手機音效與麥克風擺位測試回授，對系統提示音採輸入抑制，降低誤觸。
- 收音只在本機即時分析，第一版不保存人聲、不上傳人聲，也不做語意辨識。
- SAN 依捕捉數量降低；現場聲音影響音虫活動。
- 聲音處理不依賴雲端；手機連線暫停時，現場聲音與畫面仍由本機運作，但不得讓未確認的捕捉繼續結算。

### 投影回收站

### 物件投影與手機 Web App 虛擬按鈕

回收站採固定的箱體、立柱或城市設施造型，以消光表面承接能量聚集、抽取及物件生成投影。

手機在「前往回收站」階段顯示回收引導；系統確認觀眾到站後，才開放「交付／回收」按鈕。觀眾按下確認後，物件投影同步呈現能量流入與轉化。

1. 遊戲進入「前往回收站」，投影與手機顯示回收引導。
2. 觀眾走到回收物件，系統確認到站後開放手機 Web App 的「交付／回收」按鈕。
3. 手機經 WSS 傳送回收要求；Unity 驗證操作憑證、有效場次、可回收狀態及到站條件。
4. Unity 鎖定本次收集結果、產生唯一 `recycle_id`，播放集中處理與轉化。
5. 投影城市修復，發布手機成果與選配列印。

其他狀態按下按鈕不會消耗物品；按下後暫停重複提交，服務端及 Unity 仍須去重，只結算一次。斷線時顯示待連線並以相同要求 ID 重試，必要時由受保護的管理介面協助。

回收按鈕須同時滿足可回收階段與到站確認才啟用。到站判定流程如下：

1. 回收站保留固定、可辨識的平面圖樣，投影動畫避開其主要特徵。
2. 手機辨識圖樣，計算圖樣投影四邊形在相機原始影像中的面積占比，避免使用手機介面裁切後的顯示大小。
3. 辨識有效、占比達門檻並持續穩定約 1 秒後，Unity 確認到站並開放回收按鈕。手機透過既有 WSS 路徑傳送辨識狀態、占比與樣本時間。
4. 按下回收時再次檢查最新到站狀態；失去辨識、占比不足或資料過期時，鎖定按鈕並提示靠近、重新對準。

占比與穩定時間門檻由設定檔管理，依不同手機、角度及遠近實測；此為接近判定，非精準測距。感測器為備案：必要時增加短距離感測器與控制板，經本機串接服務（Gateway）傳入站前有人訊號，與相機辨識共同判定。

## 7. 投影與美術整合

Unity 以同一個世界狀態配置 Camera／Display，分別輸出到兩面主投影。各牆互動區、捕捉與回收事件由同一應用程式同步。[T3]

美術交付各牆比例、物件投影模型、互動區與接縫。技術組完成顯示輸出設定，以及實體投影的幾何校正、拼接與物件表面對位。

回收站若增設投影機，需增加影像輸出、解析度設定與校正；若共用主投影，則驗證光路、解析度與觀眾遮擋。

人聲音量對應蟲群動態、局部材質或粒子，視覺回饋須與音虫吸引及生成狀態一致。

### 美術背景與追蹤層的配合

以店面、招牌、窗框、海報、管線等美術元素作為圖像參考。辨識區塊須有足夠細節、明暗對比、非重複形狀與分散特徵。[T17]

背景分為穩定辨識層與動態演出層：前者提供定位，後者呈現音虫、人物、粒子與環境變化。參考區塊融入城市構圖，觀眾無須看見技術邊界或主動尋找辨識圖案。

| 美術項目 | 配合規則 |
| --- | --- |
| 穩定辨識層 | 互動期間維持選定區塊的位置、比例與主要圖樣，保留足夠可見特徵 |
| 動態音虫層 | 可微動、生成、消失，與追蹤參考圖分層管理 |
| 特徵分布 | 各捕捉區附近配置可見細節，讓觀眾對準音虫時也能拍到背景；參考區塊可重疊，測試局部入鏡時的辨識能力 |
| 牆面區別 | A、B 牆使用可區分的圖樣；不同地方避免大面積相同窗戶、對稱構圖或重複磚塊，降低誤認 |
| 對比與亮度 | 使用清楚的輪廓與明暗細節，確保手機曝光後仍可辨識，並以真投影驗證 |
| 霧、粒子與閃光 | 保留背景特徵；全畫面遮蔽期間暫停捕捉 |
| 虛擬攝影機／場景移動 | 維持追蹤區塊的空間配置；整體平移、縮放或換視角時，同步切換參考版本與座標映射 |
| 畫面裁切與校正 | 交付圖對應正式輸出比例；調整投影映射、畸變、裁切或拼接後，重新驗證手機座標 |
| 修復與結尾動畫 | 修復可改變場景；若該階段仍需捕捉，保留追蹤區塊或切新版本；結尾已停止捕捉則可自由演出 |

定位期間須保留足夠的穩定參考資訊；背景整體變形或特徵被遮蔽時，暫停捕捉並重新辨識。

美術與技術共同以實際投影驗證：從預計站位、角度及手機畫面大小拍攝，確認捕捉音虫時背景特徵仍足夠。如果觀眾必須刻意轉向其他圖案才能定位，調整參考區塊的尺寸、分布或構圖。

### 美術與 Unity 交付清單

| 交付內容 | 需包含 |
| --- | --- |
| 每牆參考圖 | 無音虫、無臨時粒子遮擋的穩定圖層，牆面 ID、解析度與內容版本 |
| 局部辨識區塊 | 區塊名稱、`anchor_id`、所屬 `wall_id`、背景版本、參考圖／追蹤資料、整牆位置與大小／映射；數量及重疊範圍依測試決定 |
| 分層素材／場景 | 穩定辨識層、動態音虫、環境動態、互動特效、修復動畫分開管理 |
| 音虫互動定義 | 種類、出現／消失狀態、命中範圍、可捕捉條件及遮擋處理 |
| 正式輸出對位資料 | 各牆顯示輸出、投影校正與內容座標的對應；如有不規則 warp，需能把對準點與目標範圍換到同一座標系 |
| 手機 UI | 搜尋中、已定位、鎖定、處理中、成功、失追及重新對準狀態 |

Unity 透過 Camera／輸出映射，將物件世界座標轉成標準牆面座標，處理可見性與遮擋後，與手機 `u/v` 進行命中判定。

## 8. 成果保存與列印

### 音樂產生

音樂素材先統一 BPM、拍號、循環長度與起點，再依捕捉種類選取音軌、編排與混音。以種類控制聲部、數量控制有限的密度或段落，避免收得多就無限制疊音。

成果儲存 `recipe_version`、音軌版本、編排參數與固定 seed，確保每次開啟播放相同的預製音軌組合。

成果頁依共同時間軸播放音軌。單一音檔下載列為擴充功能，需增加伺服器混音及檔案儲存。

### 成果保存與連結

- Unity 完成回收後建立本機不可重複的成果記錄，本機串接服務（Gateway） 將成果送到雲端。
- 雲端資料庫保存收集清單、修復結果、感謝信模板與音樂配方；版本化音檔置於靜態資源／物件儲存。
- 手機取得獨立的成果網址，可加入書籤或分享。
- 成果連結使用不可猜測的唯讀 token，不使用可遞增流水號公開所有人的紀錄。
- 成果 token 與場次操作憑證分開；場次結束後撤銷操作權，唯讀成果連結仍有效。
- 頁面載明成果保存期間，服務費用與保存期限待團隊確認。
- 外網暫斷時本機保留待同步成果；可列印預先配置 token 的成果連結，同步完成前頁面顯示處理中。

### 實體列印

印表機連接展場主機，由本機服務透過 Windows 驅動與列印佇列輸出。若使用 ESC/POS，需驗證型號與指令相容性。

票面可包含音虫圖案、收集摘要、感謝文字與成果 QR。每份成果預設列印一次，補印由管理端明確操作。缺紙或卡紙只標記列印失敗，不重算成果、不重播整段遊戲。

## 9. 通訊介面與資料模型

### 事件設計

手機送的是「要求」，Unity 回傳的是「已確認結果」。每則遊戲操作帶 `protocol_version`、`session_id`、`control_epoch`、`request_id`、事件類型與 payload；憑證另在連線／驗證層處理，不寫進一般日誌。入口 QR 只包含固定網址，場次 ID 與操作憑證於開始後配置。

| 方向 | 事件 | 功能 |
| --- | --- | --- |
| 手機 → 場次服務（HTTPS） | `SESSION_START`、`SESSION_RESUME` | 開始時排他建立場次；恢復時驗證原憑證並保留遊戲進度 |
| 手機 → WSS 服務 → Unity | `CONTROL_BIND` | 將連線綁定有效場次及控制世代，撤銷同場次舊控制連線 |
| 手機 → Unity | `TRACKING_UPDATE`、`TRACKING_LOST` | 回報自動辨識的牆面、參考區塊、對準 u/v、內容版本、品質與時間 |
| 手機 → Unity | `CAPTURE_START`、`CAPTURE_CANCEL` | 要求開始或取消捕捉；長按可用心跳／租約，失聯即取消未完成動作 |
| Unity → 手機 | `AIM_FEEDBACK`、`CAPTURE_RESULT`、`STATE_SNAPSHOT` | 回傳對準提示、捕捉結果、SAN、收集清單與當前階段；攜帶對應 tracking_seq 以忽略舊提示 |
| 本機聲音分析 → Unity | `AUDIO_FEATURES` | 區域音量、持續時間等，不傳原始人聲到雲端 |
| 手機 → Unity | `RECYCLE_REQUEST` | 虛擬按鈕要求回收，由 Unity 驗證可回收階段及到站條件後執行 |
| Unity → 本機串接服務（Gateway）／雲端 | `RECYCLE_COMMITTED`、`RESULT_READY` | 鎖定回收結果、建立並發布個人成果 |
| Unity → 場次服務 | `SESSION_PREPARED`、`EXHIBIT_READY` | 確認新場次初始化或展場重置完成；場次服務據此開放操作及下一場 |
| 場次服務 ↔ Unity | `SESSION_END`、`SESSION_ABORT` | 結束／中止場次並撤銷控制權，銜接重置 |
| 管理端 → 本機服務 | `PAUSE`、`RESET`、`REPRINT` | 受保護的維運操作 |

以 `request_id` 去重，重送捕捉、回收與列印要求不會重複結算。每次狀態快照帶遞增 revision，手機忽略舊快照；重連取得完整狀態，不靠重播所有畫面動畫恢復。

本機與雲端都檢查授權、訊息大小、類型與頻率。前端不能用修改參數任意指定捕捉數量、SAN 或其他場次。

### 最小資料模型

| 資料 | 核心欄位 |
| --- | --- |
| Session | ID、啟動要求 ID、狀態、開始／結束時間、內容版本、最後 revision |
| ExhibitSlot | 展場 ID、入場開放狀態、主機就緒狀態、唯一場次 ID、保留逾時；以原子更新管理單人名額 |
| ControlBinding | 場次 ID、操作憑證驗證資料、有效連線 ID、控制世代、最後心跳與恢復期限 |
| ZoneDefinition | 區域 ID、牆面／投影對應、互動範圍、生成規則 |
| TrackingAnchor | 區塊名稱、anchor_id、wall_id、內容版本、參考圖／追蹤資料、整牆位置／大小及映射 |
| AimState | 牆面／區塊 ID、內容版本、最新影像序號、對準 u/v、品質與失效狀態；只供現場判定 |
| CreatureDefinition | 種類 ID、預製聲源、動畫／材質、旋律聲部 |
| CaptureRecord | 唯一捕捉 ID、session、zone、種類、成功時間、SAN 結果 |
| RecycleRecord | 唯一回收 ID、鎖定的捕捉清單、修復／轉化結果 |
| Result | 唯讀 token、感謝信、旋律配方、素材版本、發布狀態 |
| DeviceStatus／PrintJob | 連線狀態、裝置錯誤、列印工作狀態 |

不收姓名、電話與 GPS 地理位置；相機影像在手機分析，不預設保存、錄製或上傳影片，也不做人臉辨識。對準座標只作現場判定，不預設保存軌跡。固定入口開放狀態查詢；遊戲操作須驗證場次憑證、單人控制權與控制世代。若除錯需保留測試影像，只使用已同意的測試素材，不自動擷取一般觀眾畫面。

## 10. 跨平台、異常與備援

| 情況 | 系統處理 |

| iOS／Android 差異 | 外部 Safari／Chrome 實測相機授權、後鏡頭、影片尺寸、音效、辨識效能與背景恢復；不保證內嵌瀏覽器皆可用 [T1][T9] |

| 特徵不足／快速轉向／換牆失追 | 顯示搜尋中並暫停捕捉，自動重新辨識；提示放慢、退後或讓更多背景入鏡 |
| 投影條紋、反光、曝光或人影 | 以實際投影調整亮度、站位、素材與設備 |
| 追蹤過慢或手機發熱 | 降低辨識解析度／頻率、清理資源並記錄機型，必要時提供備用手機 |
| 目標暫時消失或移出範圍 | Unity 不接受捕捉，手機提示重新對準有效目標；恢復出現後再判定 |
| 手機斷線、鎖屏或重整 | 保留原場次與名額、取消未完成捕捉；恢復憑證驗證後綁定新控制連線並拉取快照，逾時中止後重置 |
| 其他手機掃入口／按開始 | 只開啟入口頁；已有場次時顯示「目前體驗中」，不建立第二場、不接管控制 |
| 同時按開始或重複點擊 | 排他保留名額，以啟動要求 ID 去重；只有一個要求成功 |
| 初始化失敗／啟動逾時 | 取消待啟動場次並回收保留名額；Unity 清理後回報就緒才開放開始 |
| 同場次多分頁／舊連線命令 | 僅最新有效控制連線可操作，舊世代命令拒絕 |
| 無外網 | 暫停雲端路徑、本機保留狀態；切換已驗證的連線備案，或暫停入場 |
| 手機沒有聲音 | 提示點擊播放與調音量，投影側提供替代聲音；不讓捕捉卡住 |
| 自己的喇叭誤觸收音 | 調整擺位、門檻與播放抑制，設定音虫生成上限 |
| SAN 達限制 | 停止捕捉並引導前往回收站，到站確認後開放回收按鈕 |
| 手機回收按鈕重複／斷線 | 去重、同 ID 重試，必要時管理端協助；不重複抽取或產生結果 |
| Unity 當機 | 讀取最後確認快照；若無法安全恢復，標記中止並重開，不憑手機畫面重建捕捉數 |
| 觀眾中途離場 | 逾時或管理端確認後中止，撤銷操作權並重置；Unity 回報就緒後再開放下一場 |
| 結束後仍收到原手機命令 | 依場次完成狀態與已撤銷控制權拒絕，保留原手機唯讀成果頁 |
| 重置失敗／主機未就緒 | 維持暫停入場，入口顯示「準備中」或設備狀態，由管理端排除 |
| 印表機缺紙／故障 | 保留數位成果與列印工作，可管理端補印，不阻塞下一場 |

### 備用設備

準備已通過測試的手機供相容性不佳的觀眾使用。背景辨識問題由美術、投影與追蹤模組共同調整。輸入介面統一提供牆面、對準座標及捕捉事件，方便維護與更換追蹤套件。

## 11. 管理、測試與驗收

### 管理介面

管理頁顯示入場開放狀態、單人名額、目前場次、有效控制連線、手機／Unity 狀態、當前辨識牆面／區塊、追蹤品質、對準座標、SAN、各區音虫、麥克風輸入、待同步成果與列印狀態。提供開放／關閉入場、暫停、中止、控制權轉移、重置、區域測試、音量校正、回收與補印；網頁管理端需認證，不能對觀眾公開。

部署提供固定開機腳本，按順序啟動 本機串接服務（Gateway）、音訊設備、Unity 與管理頁。日誌記錄事件、錯誤與內容版本，不記錄完整憑證或原始人聲。

### 分階段驗證

| 階段 | 範圍 | 通過條件 |
| --- | --- | --- |
| P0 相機與命中 | 一面真投影、穩定背景、微動／消失音虫、Next.js 相機頁、WSS 與 Unity | 在實際投影下，iOS Safari 與 Android Chrome 完成授權、辨識、座標對應、捕捉、音效與重連 |
| P1 完整閉環 | 固定入口、單人場次、一種音虫、SAN、手機回收、感謝信與兩軌旋律 | 未完成可繼續；達標／SAN 限制皆可到結尾；保存成果、撤銷控制權及重置後可建立下一場，原成果仍可重開 |
| P2 聲音與雙投影 | 至少兩個收音點、兩面主投影、正式場景樣本 | 自動區分雙牆、走動後重新辨識；觀眾聲音影響明確、生成量有上限；完成 GPU 與輸出測試 |
| P3 展出整合 | 回收物件映射、列印、斷線、現場管理 | 去重、同步恢復、重置及補印可靠；投影、網路與收音在近似展場條件測試 |

以下為開發驗收目標，實測紀錄另列：

- 手機本地按壓立即顯示操作中；從要求到投影確認回饋的第 95 百分位延遲，先以 300 ms 內為目標，若雲端路徑未達標則重新比較本機安全連線方案。
- 分別量測相機取幀、辨識、樣本年齡與網路傳輸。記錄不同距離、角度、局部入鏡、移動速度、影子與背景版本下的定位誤差、失追率及首次／換牆辨識時間；P0 後依音虫大小訂定驗收門檻。
- 人聲開始到本機音虫反應以 150 ms 內為初期目標，聲音裝置與緩衝需實測。
- 手機斷線再連不重複捕捉、扣 SAN 或回收；測試重送、重整、鎖屏與同時開兩個頁籤。
- 兩支手機同時按開始時只建立一個有效場次；掃固定入口不佔名額。重置中禁止開始，完成後同一入口可建立新場次。
- 重連沿用原場次、舊控制世代失效；結束／中止後原憑證無法操作下一場。連續完成兩場時，SAN、收集清單及回收狀態完全隔離，兩份成果與列印工作各自保留。
- SAN 達限制後停止捕捉並進入回收引導；未確認到站時按鈕不可用，確認到站後才可回收。
- 回收站測試遠處對準、靠近、斜拍、變焦及失去辨識；確認占比門檻、穩定時間與回收當下的到站檢查有效。
- 成果在另一台手機與展場關機後仍能開啟；音樂能在使用者點擊後播放。
- 先連續運作 4 小時，再以完整展出日長度進行壓力測試；記錄掉幀、記憶體、設備掉線與恢復時間。
- 以完整場景驗收效能，於 P2 後固定投影解析度、目標 FPS、場次上限與網路門檻。

### 待確認規格

1. 圖像追蹤套件、背景參考區塊、座標誤差、捕捉時間窗及雙牆切換門檻。
2. 回收站辨識圖樣、畫面占比與穩定時間門檻，以及回收投影能否共用主投影光路。
3. 任務完成條件、SAN 扣值、體驗時長與音虫種類。
4. 手機「錄音捕捉」的介面呈現與操作時間。
5. 雲端 HTTPS／WSS 連線的延遲與可用性是否通過，或需要本機安全部署。
6. 音樂只需重開播放，或還需混音檔下載；成果保存期限。
7. 印表機借用型號、耗材與是否納入第一版驗收。
